### 事故与修复（必记，代价=一次 force）

主库 `repos` gitlink bump 时，PowerShell 把 `origin/main^{tree}` 的 `{tree}` 解析成**脚本块**、把 `160000,sha,repos` 按逗号**拆成三参数** → `read-tree` 静默未执行、`cacheinfo` 被拒 → `write-tree` 写出**空树**并被推成 main 的 `30e26f5`（15 个文件被删：`AGENTS.md`／`ARCHITECTURE.md`／`CONTRIBUTING.md`／`llms.txt`／`.gitmodules`／`repos`＋`wiki` 指针等）。

处置：`ls-tree`＋`diff` 确诊 → **force 把 origin/main 回退到事故前的 `6ed12b8`**（回滚自己的错误提交，不涉及他人内容）→ `ls-tree` 复核根文档与两个子模块指针全在 → 改用精确字节 ASCII 文件（LF、无 BOM）＋`cmd /c` 重定向喂 `update-index --index-info` 重做（`0ea884d`，`diff` 实测仅 `repos` 一行）。

**教训**：git 管道一律用 Git for Windows 的 bash（`C:\Users\takomi\AppData\Local\Programs\Git\bin\bash.exe`，MSYS／bash 5.3）。本机本来就有 bash，之前用 PowerShell 是习惯而非必要；`^{tree}`、逗号参数、stdin 三处坑在 bash 里都不存在。同理：`update-index --cacheinfo` 需要**完整 40 位 SHA**。
