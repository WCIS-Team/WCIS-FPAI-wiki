# 通用模型量化实验与优化

最终原则： 精度掉了多少，为什么掉、如何恢复、速度是否真实提升、模型是否真的运行在目标硬件上

## 1. 实验目标与基本流程

阶段 0：固定基线

FP32 / FP16 / BF16，原始精度、性能、资源

阶段 1：普通 PTQ

INT8、代表性校准集、默认量化配置

阶段 2：低成本优化

校准数据、校准算法、量化粒度、激活范围

阶段 3：误差定位与精度恢复

逐层敏感性、混合精度、算子替换、量化约束

阶段 4：高级 PTQ

AdaRound、GPTQ、AWQ 等适用算法

阶段 5：QAT

模拟量化训练、微调、重新验证部署图

阶段 6：目标硬件验收

编译、端到端性能、精度回归、资源与稳定性

注意：这不是所有模型都必须逐项执行的算法清单。应先确认目标硬件、推理框架和算子支持情况；某些优化方法仅适用于特定模型结构或权重量化方案。

## 2. 阶段 0：建立 FP 基线

目的：确定量化前模型的真实表现，避免把原始模型问题误判为量化损失。

执行步骤：

1. 固定模型权重、代码版本、推理框架、输入尺寸和预处理流程。
    
2. 在固定测试集上运行原始模型，记录完整指标。
    
3. 分别测试目标硬件支持的 FP32、FP16 或 BF16 基线，不要默认它们的精度与速度相同。
    
4. 保存中间层输出、模型结构、权重文件及环境版本。
    
5. 确定竞赛验收门槛，例如精度下降不超过多少、延迟上限、内存上限。
    

记录以下指标：

|类别|必须记录的指标|
|---|---|
|精度|任务对应的主指标、辅助指标、失败案例|
|性能|单次延迟、吞吐量、预热时间|
|内存|峰值 RAM、峰值显存、模型文件大小|
|硬件|CPU/NPU/GPU 利用率、算子落点|
|部署|模型是否成功编译、是否存在回退算子|

语音、视频等流式模型还需要记录首包延迟、实时率、流式状态开销、丢帧率等适用指标。

阶段产物： `baseline.json`、FP 模型、测试数据清单、环境配置及原始评测日志。

## 3. 阶段 1：普通 PTQ

PTQ（Post-Training Quantization，训练后量化）是首选起点，因为通常不需要重新训练模型。

### 3.1 执行步骤

1. 选择目标量化格式，例如 INT8、INT4、FP8，或硬件支持的其他低精度格式。
    
2. 优先使用框架默认、成熟且硬件支持的量化方案。
    
3. 准备具有代表性的 calibration dataset。
    
4. 使用默认校准方法生成量化模型。
    
5. 导出、编译并运行量化模型。
    
6. 在与 FP 基线完全相同的测试集上评测。
    
7. 对比精度、延迟、模型大小、内存和硬件执行情况。
    

### 3.2 校准集怎么选

校准集应当代表模型的实际输入分布，而不是只挑选容易处理的样本。

- 视觉模型：不同光照、背景、目标大小、运动模糊、真实摄像头画面。
    
- ASR：不同说话人、语速、口音、噪声、采样率和远近场条件。
    
- NLP/LLM：不同输入长度、任务类型、常见词与长尾词、真实提示词。
    
- 语音合成：不同文本长度、语言、标点、数字和混合语言。
    
- 时序模型：不同运行阶段、信号幅值、突变和边界条件。
    

校准集与最终测试集应分开。测试集不能反复用来挑选校准配置，否则会产生评测泄漏。

### 3.3 首轮结果判定

- 精度满足要求、性能明显提升：进入部署验证。
    
- 精度略有下降：先检查校准数据与量化配置。
    
- 精度明显下降：检查逐层误差与敏感算子。
    
- 性能没有提升：检查算子是否真的在目标硬件上执行低精度计算，以及量化、反量化开销。
    

阶段产物： 默认 INT8 模型、校准配置、评测报告及与 FP 基线的差异报告。

## 4. 阶段 2：低成本 PTQ 优化

每次实验原则上只改变一个变量，方便确定改进来源。

|优化方向|可尝试方法|适用情况|
|---|---|---|
|校准数据|更换、扩充、重新采样校准集|真实输入与校准集分布不一致|
|校准算法|MinMax、Percentile、Entropy 等|极端值导致量化范围不合适|
|权重量化粒度|Per-tensor → Per-channel|不同通道的权重分布差异大|
|激活量化|调整激活范围、裁剪阈值|激活存在离群值或长尾分布|
|数值格式|对称/非对称量化、调整零点|数据分布或硬件约束适合其他方案|
|算子融合|检查 Conv-BN、MatMul 等融合|融合方式影响误差或执行效率|
|量化边界|调整残差、分支和拼接处的量化策略|多分支之间存在量化尺度不匹配|

注意：Per-channel 不一定对所有算子都有硬件支持；校准算法也不能不加区分地套用到所有模型。某些 NPU 只支持固定的对称 INT8 或固定激活量化方式，此时应以编译器实际支持的配置为准。

实验要求： 保存每个变体的配置与指标，不要将多种改动同时应用后只记录最终结果。

## 5. 阶段 3：敏感层分析与精度恢复

当普通 PTQ 和低成本优化仍无法达到精度门槛时，才进入这一阶段。

### 5.1 逐层敏感性分析

可以采用以下方法：

1. 比较 FP 与量化模型各层的输出误差。
    
2. 对关键层进行逐层量化、逐层恢复高精度的消融实验。
    
3. 对输入、输出、残差分支及关键中间张量进行误差分析。
    
4. 将局部误差与最终任务指标关联起来。
    
5. 识别对精度影响大、但对计算开销影响较小的层。
    

可记录的数值指标包括：

- MSE、MAE：量化前后张量差异。
    
- Cosine similarity：输出方向一致性。
    
- SQNR：信号与量化噪声的相对关系。
    
- 任务级指标差值：例如 mAP、WER、准确率或困惑度变化。
    

单层 MSE 最低不意味着任务精度一定最好，最终仍须以完整模型的任务指标判断。

### 5.2 混合精度

优先尝试：

- 敏感层使用 INT16、FP16 或其他受支持的高精度格式。
    
- 非敏感层继续使用 INT8。
    
- 只对少数关键算子或关键张量保留高精度。
    
- 在残差连接、归一化、Softmax 或输出头等位置评估精度保留的收益。
    

混合精度需要同时考虑算子支持、数据转换、内存带宽和调度开销。若高精度层导致跨设备传输或频繁量化转换，可能得不偿失。

阶段产物： 层级敏感性报告、混合精度配置、精度恢复与性能开销对照表。

## 6. 阶段 4：高级 PTQ 算法

不是所有算法都要执行。根据模型架构、误差来源和工具链支持情况选择。

|算法|主要作用|典型适用范围|
|---|---|---|
|AdaRound|优化权重舍入决策|CNN、常规神经网络权重量化|
|BRECQ|分块重构量化误差|CNN 等支持相应重构流程的网络|
|GPTQ|逐层近似优化权重量化误差|Transformer、LLM 权重量化|
|AWQ|利用激活信息保护重要权重|LLM 低比特权重量化|
|SmoothQuant|在激活与权重之间迁移量化难度|Transformer、LLM 的 W8A8 量化|
|OmniQuant|可学习量化参数及相关变换|支持相应优化流程的 LLM|
|PTQ4ViT 等专用方案|针对特定网络结构设计量化策略|视觉 Transformer 等特定模型|

选择原则：

- 卷积模型： 优先考虑校准、逐通道量化、敏感层分析和 AdaRound/BRECQ 等。
    
- Transformer/LLM： 根据权重、激活、KV Cache 的量化需求选择 GPTQ、AWQ、SmoothQuant 等。
    
- ASR/TTS： 先确认编码器、解码器、注意力、归一化和流式状态是否支持目标精度；不能直接假设 LLM 的量化方法适用于整套语音模型。
    
- NPU/FPGA： 先确认量化格式与算子支持。算法效果再好，如果不能导出、编译或在硬件上执行，就不构成有效的部署方案。
    

## 7. 阶段 5：QAT

QAT（Quantization-Aware Training，量化感知训练）应当在 PTQ 优化收益不足时再考虑。

执行流程：

1. 选定最优 PTQ 配置作为起点。
    
2. 使用框架提供的 QAT 或 Fake Quantization 流程。
    
3. 固定训练、验证、测试集的划分。
    
4. 使用较小学习率进行微调，避免破坏原模型能力。
    
5. 监控量化模拟训练过程中的精度、损失与稳定性。
    
6. 导出实际量化模型，并通过目标工具链编译。
    
7. 重新运行完整评测，确认部署结果与训练模拟结果之间的差异。
    

必须注意：QAT 训练时的 Fake Quantization 结果，不等于最终部署到 NPU/FPGA 的真实量化结果。 最终精度必须在实际导出与编译后的模型上重新测量。

如果模型没有可用的训练数据、训练代码或反向传播支持，应优先评估高级 PTQ，而不是强行进行 QAT。

## 8. 阶段 6：目标硬件验收

这是所有量化实验的最终验收阶段。

|验收项|检查内容|
|---|---|
|功能正确性|输入输出格式、动态形状、边界条件|
|精度|量化模型与 FP 基线的任务指标差异|
|延迟|预热后延迟分布、P50/P95、端到端延迟|
|吞吐量|固定批量、固定并发下的处理能力|
|内存|峰值 RAM、显存、外部 DDR 占用|
|硬件利用|目标算子是否在 NPU/FPGA/GPU 上执行|
|转换开销|量化/反量化、数据搬运、CPU 回退|
|稳定性|长时间运行、异常输入、内存增长|
|可复现性|固定权重、配置、工具链与测试集可重现结果|

在 FPGA 上还应记录 LUT、FF、BRAM、URAM、DSP、时序裕量等资源指标；在 NPU 上记录支持的算子、编译器版本、实际执行精度和回退情况。

## 10. 量化实验的停止条件

满足以下条件时，可以停止继续优化：

- 所有硬性精度指标达标。
    
- 延迟、内存与硬件资源满足要求。
    
- 最终模型确实在目标硬件上运行。
    
- 与当前最佳方案相比，后续优化的收益不足以抵消开发、训练和部署成本。
    
- 实验结果可复现，且关键配置和产物均已归档。
