## 一、准备工作

### 1.1 工具

板子只有 SSH（无本地 shell 直连），Windows 侧用 PuTTY 0.85：

- `plink.exe` 跑命令、`pscp.exe` 拉文件
- **必须显式加 `-ssh`**：PuTTY 0.85 的 `plink` 不加 `-ssh` 时会把 `-pw` 判成"只能配 SSH 协议"，每次都报 `plink: the -pw option can only be used with the SSH protocol`
- **必须显式给 `-hostkey`**：批量模式不接受首次连接的交互确认，固定值 `SHA256:IQGq+fgZLG+sC77GCs+cZuntFUYB1mcNM4POwA4ZzLc`
- `-accept-new-sshkeys` 在 0.85 上不支持，别用

调用模板：

```
plink.exe -ssh -batch -pw <口令> -hostkey "SHA256:..." root@192.168.1.113 "<命令>"
pscp.exe -batch -pw <口令> -hostkey "SHA256:..." "root@192.168.1.113:/tmp/<目录>/raw_logs/*" "<本地目录>/"
```

**`pscp` 拉目录不能用 `/.` 收尾**：传 `.../raw_logs/.` 会报 `security violation: remote host attempted to write to a '.' or '..' path!`。用 `*` 通配整个目录。

**口令只出现在命令行里**，不写进任何脚本、文件、日志或提交物。Windows 凭据管理器不存 plink 的口令，所以每条命令都带 `-pw`。

### 1.2 板子可达性

这台板子**可达性不稳定**，采集期间还被人反复重启（2026-10-20 早上 8 次，journal boots -7..0，06:17→13:12）。做法：

1. 每条命令带超时，失败就重试，别把"连不上"当成"字段不存在"
2. 每次采集前后各记一次 `uptime` 与 `cat /proc/uptime`，**用它判断是否中途重启过**
3. 采完核对 `journalctl --list-boots`——若采集窗口内有新 boot，本次数据属于"哪一次启动"必须写进档案

## 二、采集脚本

三份脚本都是 bash、**内容全英文**（AGENTS.md 要求脚本不写中文注释），存 `wiki/PS/` 下：

| 脚本 | 覆盖 | 份数 |
| --- | --- | --- |
| `collect.sh` | SOP 3.1–3.7 主项：身份、CPU、内存存储、加速器、OS、软件、限制 | 49 |
| `collect_followup.sh` | 补第一轮被截断或没采到的：全量 dmesg、缓存尺寸、网络、NPU/FPGA/Mali、cgroup v2、PCI、hugepages、平台设备、厂商包、ps 快照 | 27 |
| `collect_gap3.sh` | 补最后几个缺口：thermal zone、cpu capacity、DT clock-frequency/opp、fpga manager bitstream、dmesg 总行数、内核上限、存储细节、emmc 挂载、icraft 后端探测 | 9 |

脚本骨架（每条命令一段，带命令回显，出错不中断）：

```bash
#!/bin/bash
set +e
OUT=/tmp/sop_hw_$(date +%Y%m%d_%H%M%S)
mkdir -p "$OUT/raw_logs"
cd "$OUT"
TS=$(date -u +%Y-%m-%dT%H:%M:%SZ)
echo "$TS" > collect_time.txt
echo "$(date +%z)" > collect_tz.txt

run(){
  local name="$1"; shift
  { echo "### $name"; echo "cmd: $*"; echo "---"; } > "raw_logs/$name.txt"
  bash -c "$*" >> "raw_logs/$name.txt" 2>&1
}
```

### 2.1 第一轮踩到的坑：shell 通配不展开

`run cache_size "cat /sys/devices/system/cpu/cpu0/cache/index*/size"` 这类写法**在 `bash -c` 里不展开**（外层 shell 的引号把 `*` 原样传进去了），结果全部落成 `na`。改成显式枚举才拿到值：

```bash
for i in 0 1 2 3; do
  run "cache_index${i}_size" "cat /sys/devices/system/cpu/cpu0/cache/index${i}/size 2>/dev/null"
done
for z in $(ls -d /sys/class/thermal/thermal_zone* 2>/dev/null); do
  run "thermal_$(basename $z)" "cat $z/temp 2>/dev/null"
done
```

**规律：跨 `bash -c` 的路径一律写死，不靠通配。**

### 2.2 第二轮踩到的坑：dmesg 被截断

`dmesg | head -300` 会截断，而开机早期的设备探测行（mmc、sdhci、NPU、FPGA 绑定）恰恰在开头。补采要全量 `dmesg` 存文件，并记 `dmesg | wc -l` 对出行数。

### 2.3 `icraft device list` 不是合法子命令

`icraft` 的用法是 `icraft <command> [config.toml] [<--flag> [<args>]] [--dry_run]`。`icraft device list` 会以 "未找到指定的toml文件: list" 加一段 C++ 栈退出。

**这不是故障，是 CLI 语法如此**：它要的是一份 config.toml。SOP 2 只采状态不跑推理，所以**不要为了"验证后端"去造 config**——那既越界又会留下未验证的结论。脚本里这条命令留作探测，退出码与报错一并存档即可。

## 三、拉回本地

```bash
pscp.exe -batch -pw <口令> -hostkey "SHA256:..." \
  "root@192.168.1.113:/tmp/sop_hw_<时间戳>/raw_logs/*" \
  "S:\work\WCIS\wiki\PS\hardware\raw_logs/"
```

拉完做三件事：

1. **核对份数**：脚本里 `run` 调了几次就该有几个文件；缺就查板子上那一轮是不是中途断了
2. **时间戳文件也拉**：`collect_time.txt` / `collect_tz.txt` 是档案里的"采集时间"字段来源
3. **原始日志原地保留在 `raw_logs/`**，不要清洗、不要重命名——档案里每条数据的 `evidence` 字段都指回它

板端临时目录用完可删（`rm -rf /tmp/sop_hw_*`）；本地 `raw_logs/` 是交付物的一部分，**不能删**。

## 四、写档案

四份 JSON + 一份来源登记，字段口径见 [[硬件与基础运行环境档案]]：

| 文件 | 装什么 |
| --- | --- |
| `device.json` | 设备身份与硬件规格 |
| `system.json` | OS、内核、架构、容器判定、权限上下文、资源限制、网络 |
| `software.json` | 运行时、编译器、包管理器、厂商工具链、驱动、固件、环境变量 |
| `resources.json` | CPU/内存/存储/加速器实况、后台负载、采集限制清单 |
| `hardware来源登记.md` | 逐项来源登记、交叉验证结论表、待确认事项 |

四条硬规矩：

1. **每条数据带来源标签**：`official_spec` / `system_report` / `tool_report` / `measured` / `unverified` / `not_supported` / `not_accessible`
2. **算力、带宽、FPGA 占用只到"官方规格"或"未测量"**——不得由硬件信息推导性能结论
3. **不猜规格**：平台不暴露的字段标 `not_supported` 或 `unverified`，不写"约等于"
4. **人读报告另出一页**（wiki 页），把"官方规格 / 系统报告 / 实测"三栏分开写
