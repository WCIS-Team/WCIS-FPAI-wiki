# 交付件就绪状态盘点SOP

> **本页回答什么问题**：隔了一段时间回来，要在**不跑任何东西**的前提下判断"某个模型／某条交付线到底做到哪一步、还差什么"，并且把这个判断**写成能复查的页**——查哪几处、每处以什么为判据、怎么避免把过期结论写进去。
> **定稿 2026-10-30**（本轮实际做的事就是这套：Qwen3 交付件盘点 → 判定页 → 决策回写 → 归档）。
> 一句话：**先查台账和状态页的"最新一行"，再核盘上实物，最后才下结论——顺序反过来必写错。**

## 一、为什么需要这条 SOP

本轮踩到的真实代价：跨会话（9 天）后凭记忆复盘，给出"离上板还差四件事"，而台账 `#208`～`#213` 里明明白白记着**件早已拷上板、已过 `apply`**——那份复盘整个偏了一个阶段。**记忆会停在会话断开那一刻，盘上不会。** 所以流程必须是"先读现状，再谈差距"。

## 二、五步（照抄，按顺序）

### 第 1 步 · 查盘上实物（分钟级，全部只读）

```
# 交付目录本身
ls -la S:/work/WCIS/repos/<交付目录>/           # 顶层子目录齐不齐
find  S:/work/WCIS/repos/<交付目录>/ -type f | sort   # 逐件清点（体积件也在内）

# 中间件正本（编译树）
ls -la S:/apps/llm/agentwork/<项目>/compile/jr_path/<net>/

# git 侧：提交在不在、有没有漏推
git -C S:/work/WCIS/repos log --oneline -8
git -C S:/work/WCIS/repos status -sb --ignore-submodules=all
```

**判据**：文件存在只是必要条件，`git status` 里出现 `*.raw`／`*.onnx.data` 说明体积闸漏了；出现未跟踪的 `*.py`／`*.log` 说明临时件放错了地方（应进 `workenv/`）。

### 第 2 步 · 核完整性（唯一必算的 md5）

```
md5sum <交付目录>/board/<net>-decoder_ZG.raw
grep -o '"params_md5"[^,}]*' <交付目录>/board/<net>-decoder_ZG.json
```

**判据**：两侧**逐字相等**才算件完整（这是件自带的自校字段，比对外部基准更可靠）。1.6 GB 的件在 S 盘上算完约 3～5 分钟，**命令超时给足 420 s**，否则会被误判成失败。

### 第 3 步 · 核数值（能在本地对出来的，就别只信记录）

PC 侧验证产出的 `tokens.txt` 与校机 HF 基准 json **当场逐个对**：

```
cat <交付目录>/ref/tokens.txt          # 每行一个 id，prompt 段在前
cat <交付目录>/ref/padfix_*.json       # 校机基准，取 .gen_ids
```

**判据**：生成段与基准 `gen_ids` 逐个相等（本轮实测 26/26），且解码文本通顺。**这一步不需要跑任何东西**——两侧都是历史产物，比对是纯读。

### 第 4 步 · 读"最新一行"（这一步决定结论对不对）

按顺序查三处，**只看最新记录，不凭记忆**：

| 处 | 查什么 | 命令／判据 |
|---|---|---|
| 台账 | 该件／该驱动的**上板记录与取证行** | `grep -nE '#20[0-9]\|#21[0-9]' wiki/PS/板端我方代码与产物台账.md`，找 md5、`apply` 时长、心跳极值 |
| 模型状态页 | 状态表里**最后一次更正**（常见句式"**X 年 X 月更正本行**"） | `grep -nE '更正\|仍未\|已' wiki/PL/MOD/llm/<页>.md` |
| 决策记录 | 该线最近一条 `D-` | `grep -nE '^### D-' wiki/archive/开发管理/状态源与决策记录.md \| tail` |

**判据**：三处的"最新一句"必须互相自洽；**若台账比记忆新，以台账为准**。本轮正是靠这一步把"差四件事"修正成"只剩点火一件"。

### 第 5 步 · 写判定页 + 回写决策

1. 判定页落 `wiki/PL/MOD/`（模型线）或对应层级，页头必须写清**判据等级、盘点时刻、分工（正本在哪一页）**。
2. 每条结论挂证据级别与出处链接（A＝本轮实算／B＝既有 A 级转引／C＝外推），**过期结论要显式标"已作废"并说明为什么变**。
3. 若结论触及排期／架构／验证标准 ⇒ 回写 `状态源与决策记录.md` 新增一条 `D-<UTC 秒>`，写明原话、决定、影响、**回退条件**。
4. 新增页面在 `wiki/README.md`「目录」表补一行。
5. 跑校验：`python -X utf8 wiki/format/check-md.py wiki`，**记下当场的问题数**（与本轮改动前对比，增量应全部来自新页且可解释）。

## 三、判据速查

| 想判断 | 看哪 | 不算数的东西 |
|---|---|---|
| 件完整吗 | `_ZG.raw` md5 ＝ json 内 `params_md5` | 文件名、目录名、件大小 |
| 数值对吗 | PC 侧 tokens 与校机 HF 基准逐个对 | "以前验过"这句记忆 |
| 上板到哪步 | 台账的上板行＋取证行（md5／`apply`／心跳） | 会话里记得的操作 |
| 能不能跑 | 板侧门禁（位流 md5／`CmaFree`）＋驱动在不在板上 | 件已拷板＝能跑 |
| 结论过期没 | 状态页最后一次"更正"、决策记录最后一条 | 自己上一轮的复盘 |

## 四、三条坑（本轮真踩过）

1. **跨会话的记忆不可信**。9 天后回来，我拿"盘上有件、没上板"的印象去推断，而台账早记着已上板已 `apply`。⇒ **第 4 步不是可选步骤**。
2. **md5 命令会超时**。1.6 GB 在 S 盘上 120 s 算不完，默认超时会把成功读成失败。给 420 s。
3. **校机可能离线**。本轮 ssh 两条路由都超时，但跳板机应答正常（`"jump only, no shell"`）⇒ 能据此判断"是校机没开、不是网络全断"。查不到就**如实写"本轮没查到"**，别拿旧记录当现值。
