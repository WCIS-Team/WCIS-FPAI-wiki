# 交付物数字审计num-audit

交付物（方案文档、验收记录、报告）交出去**之前**跑一遍：把文里的数字逐条复算、
把"文件名:行号"这类引用逐条打开回查、把核心速率链对到外部锚点上。
目标是"证据先于结论"——**没跑过这条命令，就不许说这页数字是对的**。

脚本在 `repos/num-audit/`（2026-10-26 从 `workenv/` 移进代码库；AGENTS.md 硬规矩表现在
只登记了 `wiki/format/`、`wiki/site/`、`.github/workflows/` 三处入库脚本位置，
这一处**还没登记**，移动是照她的指令做的，登记与否待定）；
设计依据与"抓不住什么"见 `repos/num-audit/README.md`。

## 怎么跑

```bash
cd S:/work/WCIS

# 1) 先自证工具没坏：红测件必须 FAIL(exit 1)，绿测件必须 0 FAIL(exit 0)
python -X utf8 repos/num-audit/num-audit.py repos/num-audit/selftest-red.md   --root S:/work/WCIS; echo "RED=$?"
python -X utf8 repos/num-audit/num-audit.py repos/num-audit/selftest-green.md --root S:/work/WCIS; echo "GREEN=$?"

# 2) 跑交付物
python -X utf8 repos/num-audit/num-audit.py "<交付物.md>" --root S:/work/WCIS; echo "EXIT=$?"
```

`--root` 给仓库根（默认当前目录）；引用只写文件名时靠它全仓定位。
**默认只打 FAIL 全量＋每条 WARN 一行摘要**（省上下文）；`--verbose` 打全部含 PASS，
`--json` 另存 `<交付物>.audit.json` 全量报告。摘要只作用于 WARN，硬错不会被缩掉——
自证：红测件默认模式下 10 条 FAIL 逐条完整打印、退出码仍 1（2026-10-31 往红测件加了
一条空格文件名错例，从 9 条变 10 条；`--json` 那份报告里逐项数是 A1 2／A2 9／A3 1／B 2／C 3，
FAIL 10＝A1 1＋A2 4＋B 2＋C 3）。**注意 `--json` 会把报告写在交付物旁边**，交付物在 `wiki/` 里
就等于往入库路径丢了个临时件（本轮实踩一次）——跑完就地清掉，别让 `git status` 认出它。

坑（本轮实踩，清单以本节的枚举为准）：

1. **退出码要直接接命令**：写 `... | tail; echo EXIT=$?` 取到的是 `tail` 的码，
   会把"FAIL 1"读成"EXIT 0"。判据用 `${PIPESTATUS[0]}`，或先看 `总计` 行再看退出码。
2. **别把检查语法原样抄进文档**：本 SOP 与设计说明里若写带数字的引用例子，
   B 项会把它当真引用去全仓找，报出假 FAIL（本轮两份说明文各自被打过）。
   举例一律写成"文件名:行号"。
3. **`anchors.json` 的 `only_if` 是关键词触发，提一句就把锚点激活**：本轮写"坑"的时候
   举了两个触发词的名字，C 项立刻从 0 项涨到 2 项假 FAIL——因为说明文里没带那些锚点的
   断言值。规则：**要么把断言写全，要么在说明文里不要提触发词本身**（改说"见 `anchors.json`"）。
   这是本工具当前最小的一个缺口：`only_if` 不区分"这条链路的交付物"与"谈到这个词的说明文"。
4. **全量输出很贵**：方案文档一次全量 11 884 字节（估 ≈3 059 token），默认摘要 975 字节，
   省 1 − 975/11 884 ＝ 91.8%。只在需要逐条看 PASS 时才 `--verbose`。
5. **文件名带空格的引用必须整体放进一个反引号**（2026-10-30 实踩，2026-10-31 她裁定"要"已根治）：`REF` 原来的文件名字符类**不含空格**，厂商那几份带空格的教程正文与行号连写时，工具只把最后一个空格之后的片段当文件名 ⇒ 全仓找不到 ⇒ 一条真引用被记成"文件存在／全仓找不到同名文件"的假 FAIL（首发那轮一篇页面上 8 条 FAIL **全是**这一类，逐条打开原文件都对得上；同一类错还潜伏在全库 3 条裸名引用上，见坑 6）。现在 `REF` 的文件名拆成两支：**反引号内**允许空格（`[^` 与换行与竖线之外，最长 140 字符），**反引号外**仍不允许空格——所以散文里相邻两个词不会被吃成文件名。用法因此定死：
   - 引用带空格的文件名 ⇒ **整条放进一个反引号**，反引号内写 `路径/文件 名.md:行号`；拆开写、或把行号放到反引号外面，工具看不见。
   - 红测件 `repos/num-audit/selftest-red.md` 里"错误五"走的是"空格名但文件不存在必须照样 FAIL"这一支；绿测件 `repos/num-audit/selftest-green.md` 里"空格文件名（回归位）"那一节走的是"真文件必须打得开"这一支。两支都跑过才算这条改对了。
6. **同名双副本：裸文件名会静默换机器**（2026-10-31 实踩）：仓里有**两套同名不同 release 的厂商教程**——`wiki/PL/MOD/modrt/tutorial-runtime/docs/`＝**3.31**（带 `.git` 的 gitee 个人镜像 `mxh-spiger/tutorial-runtime`，分支 `tt3.31.0`，15 件全 `.md`，唯一含 `Part 1_5 ZG Usage.md`）与 `repos/official/tutorial/icraft_tutorial/WL/`＝**3.39、只面向 WL170(400TAI)**（ModelScope `AIBS/icraft_tutorial` v3.39.0 落库，12 件＝10 `.md`＋2 PDF），**6 件文件名相同、0 件内容相同**，行数差 ＋11／＋109／＋145／＋351 与 −64／−72。`resolve()` 的次序是"原样拼根 → 当绝对路径 → 全仓按文件名取 `hits[0]`"，而 `os.walk` 在本仓把 `repos/` 排在 `wiki/` 之前 ⇒ **裸文件名一律解析到 `repos/official/` 那一份**。后果两种，都不安全：那一份更短的章节会报**假 FAIL（行号越界）**，行号还在范围内的则**静默指到另一版**（同句"快照只支持 BY 阶段的网络"在两份里分别是 398 行与 462 行，行号在范围内时工具比不出指错了）。**规则：引这两套教程一律带全路径，并在句子里写明是哪一版。** 取证脚本 `python -X utf8 workenv/gate/dupcmp.py`（比两份的行数／md5／同句落点，并现场对比新旧 `REF` 的匹配结果）；名册与来源 `workenv/gate/twosets.py`，逐句字节比对 `workenv/gate/sentcmp.py`。本体记在 [[官方demo教程与skill审计]] 第二节与第十二节。
   - 曾经挂在这一条上的开口项**已结**：全库那 3 条裸名引 `Part 0 env_setup.md`（出厂口令行、百兆行）`git blame` 都在 **2026-10-18**，而两份副本的目录创建时间是 10-29 与 10-30（`workenv/gate/mtimes.txt`），当时盘上根本没有同名件；行号 52／116 精确对上 **3.39-WL** 那份（3.31 那份是 77／135，`workenv/gate/envsetup.txt`）⇒ 它们一直引的是**线上 3.39 版正文**，现在的"通过"落对了 release，只是没写明版本。等 [[官方demo教程与skill审计]] 第十节第 7 行裁完就一次改成带全路径＋标版本的形式。
7. **"本仓没有 X"这类负断言不在门禁覆盖面内**（2026-10-31 实踩，我自己写错的一句话）：`build_index()` 的 `os.walk` 排除名单里含 **`largefiles`**（源码那行 `d not in (".git", "__pycache__", "node_modules", ".venv", "largefiles")`），而 B 项只回查**写成 `文件:行号` 的引用**，不校验"我在哪些目录里搜过"。所以我上一版那句"本仓也没有 x86_64 Linux 版 iCraft CLI"（实情：`largefiles/04_ICraft/v3.39/icraft_v3.39.0/30TAI&100TAI.zip` 里就有 919.4 MB 的 `Icraft_3.39.0_amd64.deb`）**任何一项检查都不会报**——RED／GREEN／交付物三件全绿照样能把这句错话发出去。规则：**写"没有／只有／全仓都找不到"之前，把搜索面逐条列出来再下笔**（`repos/`／`wiki/`／`largefiles/`／`workenv/`／`source/` 五处互不覆盖，`largefiles` 与 `workenv` 还被 `.gitignore` 永久排除，git 历史里也查不到）；能写成引用句的就写成 `文件:行号`，让工具至少能回查存在性。**再补一条边界（同轮实测）**：`largefiles` 的排除只作用在"按文件名建索引"那一支——`resolve()` 的次序是"原样拼仓库根 → 当绝对路径 → 全仓按文件名取 `hits[0]`"，第一支不看索引，所以**带全路径的 `largefiles/…` 引用照样 PASS**（[[官方demo教程与skill审计]] 第十二节那 2 条 `largefiles/04_ICraft/v3.39/icraft_v3.39.0/readme.md` 就是现成证据），只有**裸文件名**引 `largefiles` 里的件才会被判"全仓找不到同名文件"。⇒ 这个缺口只在散文里的"没有／只有"，不在写法上；把负断言改成带全路径的引用句，就同时绕开了索引排除与 `hits[0]` 换机器两条坑。**同一天第二条（我犯了两次才立住）**：负断言的搜索面不只分目录，还分**盘**与**调用方式**——判"某台机上没有 X"要过三面：① 所有文件系统盘（`Get-PSDrive -PSProvider FileSystem`，别只看 `C:\`；我这轮就是漏了校机的 D 盘，那上面有 1.57 TB 可用的交叉编译树）；② PATH（`where` 找不到**只**证明"PATH 里没有"，绝对路径调用的工具链在 PATH 里永远是空的）；③ **本仓自己写给那台机的那页文档**（[[交叉编译主机路由SOP]] 第一节第 12 行与 [[校机交叉编译环境搭建SOP]] 第六节那七处写死的 `/d/yzd/WCIS/crosswin` 早就说明了工具链在哪——我上一版没读自己写的路由页就下结论）。这条与 [[官方demo教程与skill审计]] 第十二节最后两条同体。


## 判过了

**RED=1 且 GREEN=0 且交付物 FAIL=0**。三条缺一不成立。

- **FAIL 必须清零**：算式不成立／文件找不到／行号越界／核心速率链缺外部锚点。
- **WARN 逐条人眼确认后可留**，不许批量忽略。两类：
  - `A3:裸数字` ⇒ 补一行算式，或补"估／实测／待测"字样（A 级读数就补"实测＋行号"）。
  - `B:引用` ⇒ 中文句子常没有 ≥6 字符 ASCII 标识符可比，所以把被引区间打印出来看：

    ```bash
    python -X utf8 -c "L=open('被引文件路径',encoding='utf-8',errors='replace').read().split(chr(10));\
    print(chr(10).join('%d| %s'%(n,L[n-1][:120]) for n in range(起行,止行+1)))"
    ```

    区间内容对得上就留，对不上改行号（本轮就是这么抓到 P11 的 `:285-293` 应作 `:263-273`）。

## 写交付物时的纪律（工具管不到的部分）

1. **计数必须写成引用**。"队友试了 N 次""全仓 M 处"这类，要么落 `file.md:NNN` 让 B 抓，
   要么不写。写成散文的计数＝没验过的计数。
2. **派生数字要同段带算式**。只给结果不给式子，A2 就没法复算，错误只能在人眼盲区里存活。
3. **基数必须可追**。凡"速率／容量／带宽"类基数，要么来自盘上读数（给行号），
   要么来自外部常数并写出换算（`1 Gbit/s ÷ 8 = 125 MB/s`），二者皆无就是无出处。
4. **"我发现了一个错"这句话自己也要过算式才能落笔**。本轮真实教训：为了纠正
   117.5 MB/s 这个无出处基数，我把一直正确的 1474 B 判成"preamble+SFD 双重计数"
   并改成 1466 B——**纠错动作本身是新错的来源**，且新错比原错更隐蔽（它披着"已更正"的外衣）。
5. **说两个数的关系，必须同时写出各自的集合定义**。工具能复算式子，复算不了"这两个数是
   包含关系／换了口径所以变干净了"这类**解释句**。本轮真实教训：我把"整条记录含关键词"
   与"工具入参含关键词"两个口径跑成 64 与 62 条（只差 2 条），却在正文里把它写成
   "换口径所以数干净了"——真正变的是**问的问题**（62 条＝建＋跑＋读输出的全集，
   34 条＝其中写文件的子集）。落法：关系类断言一律做成带"定义"列的表，让人能逐行重跑。
6. **占比类数字要带读数时刻**。同一份 transcript 边聊边长（本轮实测两次读数
   86.83 → 89.36 credits，204 → 207 条请求；差额正是"做这次测量本身"产生的），
   所以任何"占百分之几"只对当刻成立。写法：`读于 N 条请求 / M credits 那份快照`，
   并优先给绝对值（条数、credits），把百分比放在后面。

## 加新检查的顺序

先往 `selftest-red.md` 加一条**该错的数字**，跑到它报 FAIL；再实现检查；然后确认
`selftest-green.md` 里同形口径报 PASS。顺序反了就是在写永远不会触发的代码。
外部常数进 `anchors.json`：`only_if` 决定何时生效，`assert` 用边界安全的正则
（`(?<![\d.])46 B` 而不是裸 `46`——裸 `46` 会命中 "4.46 MB"，这就是本轮实抓到过的假通过）。
