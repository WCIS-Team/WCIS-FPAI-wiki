# PS-PL_AXI_HP口与复位语义

> **本页回答什么问题**：PS-PL AXI HP 口的在途事务能不能读到；HP 口有 outstanding 事务时发生复位（PS 复位／HP 口复位／PL 复位／重配置）会怎样；这一块**本芯片到底保证什么、必须由 PL 自己做什么**。
> **页名里的下划线只是为了和文件名一致**（本库规矩：H1 必须等于文件名，见 [[注意事项]]）。正文一律写作 "PS-PL AXI HP 口"。
> **本页不回答**：HP 口在数据通路里承担哪一段流量（那属 [[接口契约与数据通路#4 PS↔PL 数据通路、DMA、DDR、时钟复位（全部待验证）|接口契约与数据通路——4]]）、自研模块的复位链设计（属 [[FPGA自研模块清单]]）。本页只登记**取证到的口径 + 未闭合的问题**。
> **口径提醒**：本芯片是复旦微 FMQL30TAI。**对 FMQL30TAI 的表述一律以厂商书面材料为准**，AMD 文档只能当等效参考；凡本条不满足的句子都标出来。

## 一、一句话口径

厂商答复的五条要点（原文整理）：

1. **计数**：PS 侧没有 `S_AXI_HP*_RCOUNT` / `RACOUNT`，AXI 协议也不定义这类信号 —— 要判在途，**只能在 PL 侧自行计数**。
2. **复位**：AXI 不要求"复位时把在途事务做完"。**任一侧在非空闲时被复位，另一侧会一直等下去（挂死）**。
3. **场景**：复位落在哪一层，结局完全不同（下表 L1–L5）。**只有"PS 与 PL 一起清"才没有残留**。
4. **处置**：凡是"只动 PL"的操作（PL 重配置、PL 逻辑复位），都必须**先排空**；而判空只能靠 PL 自己。
5. **判空**：厂商推荐给 PL master 加"**使能输入 + 忙/闲状态输出**"（下称判空握手），用它决定什么时候可以复位。

对本项目（SDI 采集，PL 是 HP 口上的**唯一 master**，只写不读）的落地见第六节。

## 三、计数：本芯片读不到，必须 PL 侧自己数

厂商答复（§1 结论，逐条）：

1. 该芯片的 PS 侧**没有 AFI 模块**，也不提供 `S_AXI_HP*_RCOUNT` / `RACOUNT`；AXI 协议同样不定义"在途事务计数"信号。
2. 所以"PS 侧还剩多少在途事务"**读不到**，只能在 PL 侧自行计数。
3. 自己写计数器可行；**更省事的做法是给 PL master 加忙/闲状态输出**（判空握手）。

### 3.1 自己数时的计数规格（厂商 §1.1.1，可直接照搬）

| 项目 | 定义 |
|---|---|
| 输出路数 | 对外 4 路：读 `arcnt`/`rcnt`，写 `awcnt`/`bcnt` |
| 计数类型 | **up-down 的"在途计数"**，不是累计计数；**接口空闲时必须为 0** |
| 计数粒度 | **事务级**（transaction），不是 beat 级 |
| 加 1 | 读 `ARVALID && ARREADY`；写 `AWVALID && AWREADY` |
| 减 1 | 读 `RVALID && RREADY && RLAST`；写 `BVALID && BREADY` |
| 溢出行为 | **回绕（wrap），且没有任何回绕/溢出标志位** |

- 精确公式：读在途 `= (ARVALID && ARREADY) - (RVALID && RREADY && RLAST)`；写在途 `= (AWVALID && AWREADY) - (BVALID && BREADY)`。
- 两个例外：只有 AXI4-Lite 槽位的读减计数**不看 RLAST**；`ID_WIDTH > 0` 时读减计数还要 `RID` 命中、写减计数还要 `BID` 命中。
- **`ID_WIDTH > 0` 时那 4 路都不等于总数**：它是按 ID 分线程实现的，每路只是"最后被碰到的那条线程"的读数。对策三条：① PL 侧按 ID 求和；② **自己写计数器时不按 ID 分线程（最直接）**；③ 改用判空握手。
- **计数器的复位源不要接到无关复位上** —— 否则"被清零"会伪装成"已排空"。

### 3.2 "计数归零"能不能当"PS 侧已排空"的判据？

厂商答复（问答 §1.2 第 (3) 问）：**可以，前提是计数逻辑正确** —— 加减条件与上表一致、复位源不接无关复位、`ID > 0` 时另行取总数。

依据是：检查期间**不再发起新事务**，计数只减不增，因此不会出现"因回绕而假归零"。剩下的风险只有两条：**计数语义写错**、或**复位源接错**。

### 3.3 推荐做法：判空握手（厂商 §1.2 末）

给 PL master 加"**使能输入**"和"**总线忙/闲状态输出**"：

1. 关闭 master：停止发起新传输，已发出的让它自然完成；
2. 读总线状态；
3. 等它变为 idle。

> 更正框（原二、四节的 AFI 水位内容）：UG1085 里 `*_RCOUNT[7:0]` / `*_RACOUNT[3:0]` 那一套是 **Zynq UltraScale+ 的 AFI 内部 FIFO 水位**，用途是 traffic shaping，原文自己就说跨时钟域时是"悲观值"。**本芯片没有 AFI，这套结论一条都不用**；原文留在这里只为解释为什么当初会往那个方向查。

## 四、复位语义：复位落在哪一层，结局完全不同

厂商答复的四条事实（§2.2）：

- **事实 2：HP 端口没有独立的复位引脚。** HP 端口的复位由 PS 侧寄存器 **`AXI_HP_RST_CTRL`** 控制，复位对象是 **HP 端口侧的 NIC 桥**（客户所称 "AFI"），时机由软件决定 —— 这就是 L2。
- **事实 3：PS 复位会把 `USER_LEVEL_SHIFT` 清零**，链路被切断，PS→PL 与 PL→PS 的信号都被**钳位**；要等 PS 内部配置完成、软件重新打开开关，链路才恢复。这个开关是**全局的**：4 位寄存器管住**全部** PS-PL 信号（GP、ACP、中断、DMA 一起断），不是每组 HP 端口一位。
  - 关键后果（PL 的时钟与复位都取自 PS 的设计）：**隔离期间 PL 既没有时钟、也没有复位，完全不工作**；`FCLK_RESETN` 进 PL 后还要过 `proc_sys_reset` 的 4 级滤波与同步（默认 4 拍），**复位生效本身也要靠 PL 有时钟**。
- **事实 4：`AXI_HP_RST_CTRL` 清不掉下游残留。** 它的复位对象只有 HP 端口侧的 NIC 桥：不复位 PS 其他部分、不复位 PL、不断链路、不涉及 DDR 控制器及其他 AXI 组件。**在途事务一旦越过 NIC 桥进入下游，写这个寄存器清不掉它** —— 该处会一直持有未完成传输，可能导致异常，甚至把系统总线挂死（波及 CPU 与其他主设备）。**所以寄存器复位不能替代排空，只能在排空之后使用。**

### 4.1 五种场景（厂商 §2.3 原表）

| 场景 | 复位 PS | 复位 PL | PS-PL 链路 | 会发生什么 / 怎么办 |
|---|---|---|---|---|
| **L1** PS 系统复位 | 是 | 与设计相关 | **被切断**，两向信号都被钳位 | 链路断 → PL 侧看到的 `ARREADY/AWREADY/RVALID/BVALID` 全低；PL 若不作处理就**挂死**（PL 挂死的直接原因是**链路被切断**，不是"PS 拒绝响应"）。按 5.1 的 8 步由软件复位 PL |
| **L2** 只写 `AXI_HP_RST_CTRL` | 否 | 否 | 不受影响 | 只清 HP 侧 NIC 桥；**桥内的被丢弃，已进下游的清不掉**。必须在排空之后使用（5.2） |
| **L3** PL 重配置（`PROGRAM_B`） | 否 | 是 | 保持连通 | PS 侧在途事务**无人消费** → 背压成为确定结果，并波及系统总线（现场"重配置后 PS 侧总线不动"就是这个原因）。**重配置前必须先排空 + 先关断链路**（5.3） |
| **L4** PL 逻辑复位 | 否 | 是 | 保持连通 | 同 L3，但配置保留、恢复快。范围就是该复位信号的扇出，**没接该网的模块（含其 FIFO、指针）不会被清**（5.4） |
| **L5** 整机上下电 / 成对复位 | 是 | 是 | 复位期间同样被切断 | **两侧全清，无残留，最安全**，也不需要"重配置前排空"（5.5） |

> 三条读表要点（原文）：L1 下 PL 挂死的直接原因是**链路被切断**；L3 与 L4 都会让 PS 侧在途事务无人消费、形成背压并波及系统总线；**只有 L5 没有残留**。

### 4.2 复位后会不会冒出"旧读响应"？

厂商答复（§2.5 问答 2）：

- **可能。**判据同样是"PS 侧有没有被清"：只复位 PL（L3/L4）时 PS 侧没清，**旧读响应可能在任意时刻返回**；此时 PL 已在发新请求，**新旧响应走同一条读数据通道，协议上无从区分**，旧数据可能被新的读逻辑**误收**。
- PS 系统复位（L1）、整板上下电（L5）：不会（NIC 桥与下游一起被清）。只写 `AXI_HP_RST_CTRL`（L2）：**不保证**。
- **芯片不提供"事务清空 / 响应隔离 / 复位后不保留旧响应"的保证**：计数侧没有回绕/溢出/清空/粘滞标志位；`AXI_HP_RST_CTRL` 只到 NIC 桥；**读通道没有错误响应，slave 被复位不会通知 master**；PS 侧不暴露任何"读通道已清空"的状态（无 AFI、无计数信号、无状态寄存器）。

⇒ 这条对**有读通道**的设计是硬约束：要么按判空握手确认排空，要么按 L1/L5 把 PS 侧也清掉。**本项目在 HP 口上只有写通道**，见第六节。

### 4.3 "哪些情况必须做更大范围的复位"（厂商 §2.5 问答 3 第 (3) 问）

| 情况 | 必须的动作 |
|---|---|
| 复位/重配置前**能由软件先排空** | 按第五节的流程执行即可，**不需要**复位 PS |
| **无法确认排空**，且复位/重配置由**外部按键、JTAG 触发**（软件来不及先排空） | **必须成对复位 PS 与 PL**，或在 PS 复位后由软件复位 PL |

## 五、五种场景的处置流程（厂商 §2.4，照抄）

### 5.1 L1 的 8 步（PL 时钟与复位都取自 PS 时）

1. PS 复位。链路自动断开（`USER_LEVEL_SHIFT` 清零）。
2. 等 PS 内部配置完成 —— **这期间 PL 不得发起任何 AXI 访问**。
3. 写 `AXI_HP_RST_CTRL = 0xF`，断言 HP/NIC 桥复位。**必须在第 5 步之前。**
4. 写 `FPGA_RST_CTRL = 0xF`，断言 PL 复位。**必须在第 5 步之前。**
5. 写 `USER_LEVEL_SHIFT = 0xF` 连通 —— PL 同时拿到时钟和低电平复位，它的状态机、指针、FIFO 在这一步被清零。
6. 写 `AXI_HP_RST_CTRL = 0x0`，释放 HP/NIC 桥复位。
7. 确认 PL 已复位（或等足够时间），写 `FPGA_RST_CTRL = 0x0` 释放 PL 复位。
8. PL 侧开始重新发起事务。

> **注意（原文）**：第 3、4 步必须排在第 5 步之前 —— **先断言、再连通**，复位信号才会在连通那一刻对 PL 有效（链路断开时断言送不进 PL）。复位要**保持足够多拍**才生效（`proc_sys_reset` 的 4 级滤波只能在 PL 有时钟时累积）。
> 前提分档：PL 的复位用 `proc_sys_reset` 且**时钟与复位都来自 PS** 的设计才需要这 8 步；**复位来自 PS、时钟来自管脚**的设计下 PL 会连带复位，不需要额外动作；**时钟与复位都与 PS 无关**的设计下 PS 侧复位不了 PL，只能整机上下电或人工成对触发。

### 5.2 L2（只复位 HP/NIC 桥）

写 `AXI_HP_RST_CTRL = 0xF` 断言，再写 `0x0` 释放。**不能替代排空**（下游残留清不掉），只适合在排空之后使用；也可以用来**单独隔离 PL 对 HP 接口的影响**。

### 5.3 L3 的 6 步（PL 重配置）

1. **停止发起新的 HP 事务**（PL 不再 push）。
2. **等在途事务自然完成**，直到 master 自身"未完成事务"为 0 并保持。
3. 确认排空后，写 `USER_LEVEL_SHIFT = 0x0` 关断 PS-PL 连通（使 PS 不受 PL 配置过程干扰）。**这一步不能省。**
4. 执行 `PROGRAM_B` 重配置。
5. 重配置后复位 PL 事务状态机：写 `FPGA_RST_CTRL = 0xF` 断言，写 `USER_LEVEL_SHIFT = 0xF` 连通，确认后写 `0x0` 释放。
6. 确认 PL 状态机已重新初始化，再开始发起事务。

> 重配置**没有自动屏障**，唯一可靠的保护就是"先排空"。

### 5.4 L4 的 4 步（PL 逻辑复位）

1. 停止发起新的 HP 事务。
2. 等在途事务自然完成，直到 master 自身"未完成事务"为 0 并保持。
3. 写 `FPGA_RST_CTRL = 0xF` 断言 PL 复位，保持多拍后写 `0x0` 释放（链路本来就连通，不需要关断）。
4. 确认 PL 状态机已重新初始化，再开始发起事务。

### 5.5 L5（整机上下电 / 成对复位）

与 L1 同序，只在中间多一步"重新配置 PL"：1 PS 复位 → 2 等 PS 配置完成 → 3 `AXI_HP_RST_CTRL=0xF` → 4 `FPGA_RST_CTRL=0xF` → 5 （按需）重新加载位流 → 6 `USER_LEVEL_SHIFT=0xF` 连通 → 7 `AXI_HP_RST_CTRL=0x0` → 8 `FPGA_RST_CTRL=0x0` → 9 重新发起事务。**五种场景里最安全。**

## 六、本项目落地（`sdi-cap`，2026-10-15）

本设计在 HP 口上是**唯一 master，且只有写通道**（`S_AXI_HP2`，PL→PS DDR；读通道恒空闲）。据此：

1. **判空由 PL 做，软硬件各一半**：写帧器里维护"在途写事务"计数（`AW` 握手加、`B` 握手减），**空闲判据 = 计数为 0 且状态机回空闲**，两级同步后作为只读寄存器 `WR_IDLE`（`0x74` bit0）给软件。这正是厂商推荐的"判空握手"的寄存器形态。
   - 注意判据**不是 FIFO 空**：源停了之后仍可能有 ≤15 拍（120 B）合法地留在 FIFO 里等写；`WR_IDLE=1` 同时保证最后一个 BRESP 已经回来。
2. **软件停用/复位次序**：`sdi_cap_stop()` 先关 `CTRL.ENABLE` → 轮询 `WR_IDLE` → 再动 PL 复位/重配置。L3/L4 的第 1、2 步在软件侧就是这两步。
3. **驱动不写死三个寄存器的地址**：`AXI_HP_RST_CTRL` / `FPGA_RST_CTRL` / `USER_LEVEL_SHIFT` 在本芯片上的地址没有本地资料（第七节），驱动里只留流程与注释，**不猜地址**（猜错就是拿 PS 全局连通开关做实验）。
4. **本设计不碰 4.2 的"旧读响应"风险**：HP 口上没有读通道，不存在"新旧读响应同通道无法区分"。**但如果以后加读通道，必须先按判空握手把 AR/RLAST 那一半也数起来**，否则 L3/L4 下旧 `RVALID` 会被新逻辑误收。

- 三个控制寄存器的**位宽与"写 `0xF`"的语义**：厂商写的是"写 `0xF` 断言 / 写 `0x0` 释放"，字面覆盖 4 位；**是否每一位对应一组口、`0xF` 是否就是"全部"** 未核（需 UG602）。
- **本芯片有没有等价于 US+ ATB 的超时机制** —— 厂商答复没提（ATB/AIB 是 Xilinx 的实现），**不假设存在**；原文只说 NIC 桥内被丢弃的事务"PL 只能靠读超时脱困"，也就是**超时得 PL 自己做**。
- `USER_LEVEL_SHIFT` 的写时机约束：厂商说"等 PS 内部配置完成"之后才能连通，但**没说怎么判"配置完成"**（软件约定？寄存器状态位？）。
- 本页所有"本项目落地"的具体寄存器号（`WR_IDLE=0x74` 等）**归 `sdi-cap` 工程文档**（`docs/寄存器手册.md`、`docs/上板检查.md`），本页不重复登记。
