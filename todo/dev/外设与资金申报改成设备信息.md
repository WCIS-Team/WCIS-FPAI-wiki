## 〇、一句话结论

四件里**三件可以直接买**（C270i、读卡器、MCP01，全部走内核内建的通用驱动，不需要下载任何厂商驱动），**一件必须换形态**：闪迪那张是**标准 SD 相机卡**，而板载卡槽是 **Micro 型**（Lite 与完整版两份手册口径一致），物理上插不进去。

**PL 直采那一类外设（I²S 麦克风、I²S 功放）现在不买**——它们在电气上完全可行（HEADER 有 4 根 3.3V，够一路共用时钟的收+发），但**买回来要自己写 PL 的 I²S 控制器并解决比特流加载**，属自研工作量而不是采购问题。判据与价格见第八节。

## 二、逐项依据与出处

### 1. 罗技 C270i 高清摄像头（带麦克风）

- **不需要下载驱动。** Logitech 从未为 C270 系列发布过 Linux 驱动；它是标准 UVC 设备，`uvcvideo` 自 2005 年起在 Linux 主线，而这块板子的出厂内核把它编成了 `=y`。任何"去下载 C270 的 Linux 驱动"的说法都是错的，且 `uvcvideo` 本来就是内建的（`=y`），板上也没有可装的外部模块文件。
- **板上先例（旁证，非成功样本）**：出厂镜像的 journal 里有一颗 UVC 摄像头被插在板载 hub 第一口并试过流，报 `uvcvideo: Failed to query (GET_CUR) UVC control 11 on unit 2: -110`、`(GET_DEF) UVC control 10 ... -110 (exp. 2)`，随后 `usb 1-1.1: USB disconnect` 与 `Failed to resubmit video URB (-19)`。`-110` 是控制请求超时，桌面 Linux 上接很多摄像头也会报且不影响出图；`-19` 是拔掉之后的报错。**枚举行没留下来，判不出型号**。
- **真正的瓶颈是带宽不是驱动**：四个 USB 口共用一条 480 Mbps 总线。YUY2 720p30 约 440 Mbps 会吃满整条线，所以按 **640×480 YUYV 15fps（约 110 Mbps）** 或 MJPEG 规划。
- **待验证**：真实支持的格式／分辨率／帧率列表，以及那颗内置麦克风的采样率与位宽。到板命令见第五节。
- 出处：本地提取件 `board_extract/34_kernel_config_from_Image.txt`、`08_journal_av_hotplug.txt`、`62_journal_dmesg_only.txt`；商品链接见第六节。

### 2. 闪迪 32GB SD 卡 —— 必须换成 microSD

- **两份厂商手册口径一致**：Lite 手册 §4.9 原文"悟净 Lite开发板包含了一个 **Micro 型**的 SD 卡接口"，完整版手册 §4.9 同样写"Micro型的 SD 卡接口"。标准 SD 卡（45×32 mm）**插不进** microSD 槽，且没有反向转接的可靠做法。
- **卡槽电气与引脚**（Lite 手册 §4.9）：4-bit 数据线 `SD_D0–D3` 走 `PS_MIO40–45`，插卡检测 `SD_CD` 走 `PS_MIO46`；Bank501 的 VCCIO 是 1.8 V，SD 侧 3.3 V，中间靠 **TXS02612** 电平转换器。启动方式由**跳线帽**（MIO3~MIO5 组合）选 SD 卡加载或 JTAG 加载。
- **容量够不够（这条是好消息）**：出厂镜像本体 `31,914,983,936 B`（含 512 B imageUSB 头），换算 `62,333,952` 个 512 B 扇区 = 29.72 GiB。市售"32GB"卡按十进制标称 = `32,000,000,000 B` = **62,500,000 扇区**，比镜像多约 16.6 万扇区（约 85 MB）→ **整镜像直写放得下**。之前"32GB 卡有风险"的担心，在按十进制标称的正规模拟卡上不成立；风险来自**按二进制算实际容量偏小的杂牌卡**，所以仍建议买标称规范的卡。
- **64GB / SDXC 支持**：技术上无碍（SDXC 与 SDHC 是同一套块寻址协议，"必须 exFAT"只是商业规范，重格成 FAT 即可；内核侧 `CONFIG_MMC` 与文件系统都在），但 **BootROM 能否从 >32GB 卡启动在这颗芯片上零实测**。属**待验证**，不阻塞本次采购。
- **可能根本不需要买卡**：**借到的完整版板上有 32GB eMMC**（珠海秒存 AT70B32G，eMMC 5.1，挂在 PL Bank11，SD 控制器需外扩 EMIO 才能访问）。若到板发现出厂软件栈已经接好 eMMC，就能直接从 eMMC 启动、这张卡只当备份盘；但 eMMC 的访问要改比特流与 dtb，**属待验证**。详见 [[板载接口与内核改造收纳进dev#一、板型：我们被分配到的是完整版|板载接口与内核改造——一、板型：我们被分配到的是完整版]]。
- 出处：本地提取件 `40_manual_lite_extracted.txt` §4.9、`41_manual_full_extracted.txt` §4.9、`59_boot_partition_capture.log`（`fdisk` 读出镜像 62,333,953 扇区）。

### 3. 连拓 USB 多功能三合一读卡器（SD/TF/MS/M2）

- **主用途是接 PC**：给 SD/microSD 卡烧镜像（Windows 用官方 `imageUSB`，Linux 用 `dd`）。这条链路完全在 PC 侧，与板子内核无关，**零风险**。
- **插到板子上也能用**：读卡器是 USB Mass Storage，`CONFIG_USB_STORAGE=y` 内建，插上会出 `/dev/sdX`。但注意两点：① `# CONFIG_USB_UAS is not set`，走 UAS 协议的高速读卡器会回落到 Bulk-Only，能用但慢；② 索尼记忆棒（MS/M2）在 Linux 侧需要额外的 `memstick`/`ms_block` 驱动，出厂内核未核实是否开启，**不要指望在板子上读记忆棒**。
- 结论：这件东西按"PC 配件"买没问题；它同时解决了"PC 没有 SD 槽"的实际问题。
- 出处：本地提取件 `34_kernel_config_from_Image.txt`。

### 4. 联想 thinkplus MCP01 会议全向麦（¥169 档，替代原 S150 + ReSpeaker 阵列）

**这台设备自身的全部事实——四个接口与端点、采样格式、numid 控件表、每一次测试与读数（T1–T15）、仍未测的缺口——只在 [[音频]] 登记**，本页不复制。此处只留"为什么买它"的判据。

- **驱动**：标准 USB Audio Class，走 `snd-usb-audio`（`=y` 内建）。不需要装任何厂商客户端。
- **第三方 Linux 实测（他板，成功）**：Milk-V Duo S 上用 MCP01 跑通"物理麦克风收音 → 云端大模型 → 物理扬声器发声"全链路，录音与播放共用同一个 ALSA 节点，代码两侧都填 `plughw:2,0`。
- **从他板记录里能确认的三条**：① 必须用 `plughw:` 而不是 `hw:`（设备原生只有 48 kHz 一档，ASR 侧一般按 16 kHz 走，重采样要有人做）；② 本板验证用的两条命令是 `arecord -l` 与 `aplay -l`；③ 它给出的 `amixer -c 2 sset 'Speaker' 100% unmute` 配方**在本板不成立**——UAC 设备在这块板上只认 `cset numid=N`，见 [[音频#三、ALSA 控件：按 numid 走|音频——三、ALSA 控件：按 numid 走]]。三条的逐板读数都在 [[音频#四、测试记录|音频——四、测试记录]]。
- **硬件构成**（拆解报告）：主控 **炬芯 ATS2836**（蓝牙音频 SoC），腔体两侧各一颗通话麦克风，360° 全向拾音、半径 3 米，主控自带**通话降噪与回声消除**——所以它是"双麦 + DSP"，**不是**能输出多通道原始数据的 XMOS 阵列；本项目不做波束成形，这个差别不影响使用。它按 D-16 替代了原计划的 S150 + ReSpeaker 阵列。
- **蓝牙模式在本板不可用**：出厂内核 `# CONFIG_BT is not set`，配对与连接一概不可能，**只能走 Type-C 有线**（线同时负责供电与传音频），见 [[音频#一、设备身份|音频——一、设备身份]]。
- **本板 E5 读数**（枚举与绑定、四个接口与端点、采样格式、numid 控件表、按键与灯解码、A/B/C 听测、全双工与控件写入）**逐条在 [[音频#四、测试记录|音频——四、测试记录]]**，控件用法在 [[音频#三、ALSA 控件：按 numid 走|音频——三、ALSA 控件：按 numid 走]]。两条与采购直接相关的总结：① 录放双向、全双工（边播边录）本板实测成立，回声不是本项目要解决的问题；② 采样格式只有 48 kHz 一档（S16_LE，播放 2ch／录音 1ch），`plughw` 是必需而不是可选。

- 出处：`https://gitcode.csdn.net/69e21b3c54b52172bc6a9160.html`（他板 Linux 实测与命令）、`https://www.52audio.com/archives/84093.html`（拆解：ATS2836、双麦、回声消除）、`https://m.lenovo.com.cn/wiki/product-doc-44909.html`（官方规格：USB 有线 + 蓝牙双模、360°/3 米、¥169）、`https://m.lenovo.com.cn/stryoutnew/report/96_13.html`（试用：Type-C 线"方便充电和连接电脑"，插电脑亮绿灯免驱）；商品链接见第六节。

## 三、已经否决的采购项（附内核依据）

这些不是"贵不贵"的问题，是**出厂内核直接不支持**，买了也无法工作。依据全部来自 `board_extract/34_kernel_config_from_Image.txt`（从镜像里的 `Image` 解出的 `.config`）。

| 被否决项 | 内核依据 | 结论 |
|---|---|---|
| USB WiFi 网卡（任何"免驱"型号） | `# CONFIG_WIRELESS is not set`、`# CONFIG_WLAN is not set` | 整个无线协议栈没编进内核，cfg80211/mac80211 都不存在。旧内核 `v2024.02` 曾内置 `ar5523`/`ath9k_htc`/`carl9170`/`ath6kl_usb`/`ath10k_usb` 五个 Atheros 驱动（journal 有注册行），**但出厂那颗 2025.04 没有**。要用只能重编内核 |
| USB 蓝牙适配器 | `# CONFIG_BT is not set` | 同上，无栈 |
| USB 转以太网（RTL8152 这类） | `# CONFIG_USB_NET_DRIVERS is not set` | 网口只有板上那一个（eth0，`fmql-dwmac`，eth1 在 dtb 里 disabled） |
| USB 转串口线（CH340/FT232/PL2303/CP2102） | `# CONFIG_USB_SERIAL is not set` | 板子的 USB 口上不再扩展 UART。不影响板载调试串口（那颗 CP2103GM 的驱动装在 **PC** 上），也不影响 USB Hub（hub 驱动是另一套，板载 USB2514 正常枚举）。CDC-ACM 类设备例外，`CONFIG_USB_ACM=y` |

| 拆机手机喇叭裸单元 | 无 DAC、无功放 | 要凑齐"USB 声卡棒 + PAM8403 功放板 + 喇叭"三段才响，总价与成品 USB 音箱持平、故障点更多，不划算 |

## 五、到板第一天：一件外设一条命令

| 目的 | 命令 | 通过判据 |
|---|---|---|
| 确认起的是哪颗内核 | `uname -a` | 与 [[板卡镜像实测取证#二、板子身份实测表（E2）\|板卡镜像实测取证——二、板子身份实测表（E2）]]登记的那颗出厂内核同名即可；换了构建号则配置结论要重算 |
| 确认可用内存与 CMA | `cat /proc/meminfo`、`free -h` | 看 `CmaTotal` 落在 [[板卡镜像实测取证#二、板子身份实测表（E2）\|板卡镜像实测取证——二、板子身份实测表（E2）]]两种构建里的哪一种，按那一档做预算 |
| 看 USB 枚举 | `lsusb` | 除 root hub 与板载 `0424:2514` 外，应出现新设备行 |
| C270i 出图 | `v4l2-ctl --list-devices`、`v4l2-ctl -d /dev/video0 --list-formats-ext` | 列出 YUYV/MJPEG 与支持的分辨率帧率组合 |
| MCP01 录放 | `arecord -l`、`aplay -l` | 出现 `MCP01 ... USB Audio` |
| MCP01 出声 | `amixer -c 0 cset numid=5 <0-151>`（master 音量；`sset 'Speaker'` 在本板无效、`numid=4` 是左右声道音量，改它听不太出来，见 [[音频#三、ALSA 控件：按 numid 走|音频——三、ALSA 控件：按 numid 走]]）后 `aplay -D plughw:0,0 <wav>` | 有声音（主观，须人在旁边确认；rc=0 与无 xrun 不足以判"出声"） |
| MCP01 收声 | `arecord -D plughw:0,0 -f S16_LE -r 48000 -c 1 t.wav`（设备只有 48k，`-r 16000` 要配 `plughw` 不能配 `hw`） | 录到且时长正确；再按 `peak`/`rms` 与无声底噪对比，才能判"录到人声"而非"链路空转" |
| 读卡器（若插板子） | `lsblk` | 出现 `/dev/sdX`；无 UAS 回落属正常 |
| 板型与座子 | 目视＋拍照：丝印、RJ45 个数、有没有 MIPI 座与 XADC 排针、J12／J26／J27 跳线位置 | 钉死 [[板载接口与内核改造收纳进dev#一、板型：我们被分配到的是完整版\|板载接口与内核改造——一、板型：我们被分配到的是完整版]] 第一、二节 |
| PL 里有没有比特流 | `dmesg` 过滤 fpga；`ls /sys/class/fpga_manager/fpga0/` 并 `cat state` | 决定自研 PL 模块怎么上板 |
| 运行时设备树覆盖 | `mount -t configfs none /sys/kernel/config`；`ls /proc/device-tree/` 找 `__symbols__` | "第四层"改造通路的成立前提 |
| UIO 现状 | `ls /dev/uio*` | 预期为空，能造出来说明 overlay 可用 |
| CAN0 是否成网 | `ip -details link show can0` | 唯一一个"零改动可能有现象"的板载外设，用来反证取证结论正确 |
| 系统时间 | `date`；`hwclock -r` | 预期归零（无 RTC 驱动）→ 台账时间戳要靠对时 |

## 七、关于"用 Arduino 帮板子读传感器、控舵机"

记这一条是为了以后不再重复讨论。结论：**当前项目不需要**，清单里没有这类外设。

真要用的时候，判据是这四条：① 需要硬实时（舵机 PWM、电机闭环）——Linux 用户态翻 GPIO 抖，且出厂内核 `# CONFIG_PWM is not set`；② 需要 5V 电平的旧传感器或 RS232/485 设备；③ 需要模拟量输入——XADC 因 `# CONFIG_IIO is not set` 在 Linux 侧不可达；④ 不想为此写 FPGA 逻辑。

不用 Arduino 的替代路线：内核里 I2C／SPI／CAN 控制器都编好了（`CONFIG_I2C_XILINX=y`、`CONFIG_I2C_CHARDEV=y`、`CONFIG_EEPROM_AT24=y`、`CONFIG_SPI=y`、`CONFIG_CAN=y`），挂 PCA9685（I2C 转 16 路 PWM）或 ADS1115（I2C 转 4 路 16 位 ADC）在**驱动侧零障碍**；要硬实时就进 PL 自己写。

> 一条修正：早期这里写过"板子 I2C 是开着的"。**不准确**——`i2c@e0002000` 与 `i2c@e0022000` 在随镜像的 dtb 里**都是 `status="disabled"`**。所以现在接 I2C 器件要先动设备树：好消息是**不用重编内核**，出厂内核的 `CONFIG_OF_CONFIGFS=y` 允许运行时插 overlay，见 [[板载接口与内核改造收纳进dev#第四层：其实存在一条"不重编内核也能动设备树"的路|板载接口与内核改造——第四层：其实存在一条"不重编内核也能动设备树"的路]] 第六节"第四层"（该条本身仍**待板验证**）。

**反过来，"为什么不直接让板子控制"这件事本身要回答清楚**——板子其实有三条原生路径，比外挂 MCU 更对：① **PL 里写状态机**输出 PWM／采样，这是异构芯片存在的理由，抖动 = 时钟周期级，且本项目的评审重点就在这条路上；② PS 侧 `CONFIG_GPIO_SYSFS=y` 内建，用户态直接翻 GPIO，能用于非硬实时场合；③ I2C／SPI／CAN 控制器都是内建的（`CONFIG_CAN=y`、`CONFIG_SPI_CADENCE_QUADSPI=y`）。外挂 Arduino 只在"不想动 PL、又能接受 Linux 的毫秒级抖动"这个窄缝里才划算——而这条缝在项目里不存在：**要硬实时的东西本来就该沉到 PL，作为 FPGA 成果交付**。

一个事实备忘：**Arduino Uno R3 插在这块板子的 USB 口上是能被识别的**——它的 USB 侧走 CDC-ACM（ATmega16U2 官方固件），而 `CONFIG_USB_ACM=y`，会出 `/dev/ttyACM0`。它做不了任何视频相关的事（2 KB 内存、无 USB Host 能力），只能当低速外设桥。

## 八、如果要把外设从 USB 挪到 PL 直连：买什么、什么时候才值得买

这一节是把"板级直采"这条路的外侧（花钱那一半）登记清楚；内侧（要写什么 RTL）在 [[板载接口与内核改造收纳进dev#十、"能不能全在 PL 端处理"——板级直采外设的判定|板载接口与内核改造——十、"能不能全在 PL 端处理"——板级直采外设的判定]]。

### 物理落点只有一个：HEADER 14×2

完整版手册 §4.23：**PL 端 16 路 GPIO HEADER，2.54 mm 插针，其中 4 根是 3.3V、12 根是 1.8V**。这 4 根 3.3V 决定了"能直连的模块必须是 3.3V 逻辑电平"。1.8V 那 12 根要接 3.3V 器件必须先电平转换，**而借来的板子不允许自己焊**（厂商用户须知："请不要对元器件进行改动或者焊接……未经技术支持的改动不予赔付"）。

**I²S 收+发的引脚账**（这是为什么"刚好够"）：I²S 需要 `SCK`(BCLK)、`WS`(LRCLK)、`SD`(data) 三根；麦克风与功放**共用同一对时钟**，各自一根 data → **2 根时钟 + 2 根数据 = 4 根 3.3V，正好用满**。任何第三个 I²S 设备都放不下。

### 候选外设与判定

价格是电商参考档，**下单前自己再核一次现价与库存**；本项目按"满足判据的最便宜档"选。

| 外设 | 参考价 | 电气与引脚 | 判据 | 结论 |
|---|---|---|---|---|
| **INMP441** I²S 全向数字麦克风模块 | ¥10–20／颗 | 3.3V，三根线（SCK/WS/SD），可与其他设备共时钟 | 引脚够；**但内核 `# CONFIG_SND_SOC is not set`，要自己在 PL 写 I²S RX 状态机** | **条件买**：只有决定做"PL 自研音频前端"时买，¥20 以内两颗 |
| **SPH0645LM4H** 模组（同上替代档） | ¥25–40 | 同上 | 同上 | 同上，二选一，按便宜且现货的买 |
| **MAX98357A** I²S D 类功放模块 | ¥15–30 | 3.0–5V 供电，3.3V 逻辑，三根线（共时钟 + 一根 SD） | 引脚够；要 PL I²S TX | **条件买**，与上一行成对出现才有意义 |
| 8Ω 2W 小喇叭 | ¥3–8 | 接 MAX98357A 输出端 | 无源器件，无驱动问题 | 条件买（同上） |

### 因此这一节的采购纪律（三条）

1. **先跑通 USB，再碰 PL**。C270i + MCP01 是本周期唯一"插上就有现象"的组合；PL 直采在比特流加载这一步还没验证过之前，买任何模块都会变成"到手即闲置"。
2. **PL 直采的瓶颈从来不是钱，是 RTL 与搬运通路**。I²S 麦克风和功放合计不到 ¥50，但要交付出"PL 里 I²S RX／TX + 一条到 PS 的 DMA／UIO 通路"。所以判据是**这一项工作量在不在排期里**，不是价格。
3. **一旦决定做 PL 音频，就同时买两颗麦克风**（一颗收、一颗做参考／差分对照），因为返工运费比模块贵。

### 什么条件下第八节整节翻案

到板做完 [[板载接口与内核改造收纳进dev#九、到板必查（这一页相关的项）|板载接口与内核改造——九、到板必查（这一页相关的项）]]的第 4、10、11、12 项（PL 里有没有比特流、configfs overlay 能不能插、`fpga_manager` 能不能写、`/dev/uio*`）之后：

- **四项都通**：PL 直采的成本降为"纯写 RTL"，I²S 那两行从"条件买"升级为"值得买"（作为自研前端的演示载体，比 ¥169 的全向麦更贴赛题）。
- **overlay 或 fpga_manager 不通**：退回重编内核方案，PL 直采在周期内不排，第八节全部维持"不买"。
