## Python 方案（AutoModel + 常驻）

优点

- 开发快 接口成熟 FunASR的ITN 标点 后处理直接开箱即用 不用自己移植
- 调试简单 出错信息清晰 模型切换只改一行参数
- 跨平台改下IPC就能跑 Linux UDS Windows命名管道/TCP

缺点

- 有Python本身固定开销 GIL限制 不能在同一个进程里同时充分跑多个CPU密集任务（所以我们分开进程）
- 内存会多占用一部分Python解释器本身的开销 几十MB级别 对你一般问题不大
- 线程控制麻烦 PyTorch/MKL容易自己乱开线程 你必须手动限制线程数

适合场景 现在优先选这个 快速搭链路 验证你的VAD逻辑

## FunASR C++ SDK（onnxruntime后端）

优点

- 没有Python解释器开销 同等推理任务CPU占用更低 延迟更稳
- 线程亲和性 核绑定更好控制 适合这种弱低频CPU
- 二进制程序 启动加载速度略快一点

缺点

- ITN 标点这些后处理组件需要自己集成 官方C++包很多配套文本工具不全
- 代码量大 排错门槛高 改逻辑周期长
- 模型导出转ONNX要额外操作 遇到算子兼容问题很头疼

适合场景 等整套链路跑通稳定之后 再考虑迁移
