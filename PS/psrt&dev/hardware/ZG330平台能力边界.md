> **本页回答什么问题**：把 2026-11-08 五轮能力调查（OS 与实时、ICraft API、Buffer、DDR/DMA/Cache、七节盘点）与同日两批板上只读探针合并去重后的**平台能力边界总表**——每条给结论、证据级别与正本链接。证据级别：**A**＝板上实测（raw_logs／提取件／生产读数）、**B**＝厂商文档与源码直证、**C**＝推断未测。

## 三、DDR / DMA / Cache / IOMMU

| 项 | 结论 | 级别 |
|---|---|---|
| PS DDR | 物理窗 **0x0000_0000–0x4000_0000**（`mem=1024M`；`/proc/iomem` 实证 `System RAM 00000000-3fffffff`）；可用约 993 MB；1 G swapfile（D-44）。`/proc/iomem` 六段 `reserved`＋`2fded000-3fffffff` CMA 预留段（与 `CmaTotal 262144 kB` 对上） | A |
| CMA/udmabuf | CMA 256 MiB（`CMA_SIZE_MBYTES=256`、ALIGNMENT=8）；`udmabuf0` 128 MiB @ 0x3010_0000 **静态**从池里划走（节点无 `reg`，overlay 挪不动）⇒ **池有效≈128 MiB 不是 256**；ZG 一次完整推理借走约 122 MB、用完归还 | A |
| GP0/GP1 | 0x4000_0000/0x8000_0000 是 PL 的 AXI 从窗**不是内存**（GP0：host_ctrl/AI 寄存器，自研可用 0x4008_0000–0x7FFF_FFFF；GP1：CDMA/ImageMake/IcorePost/Cache 块）；位流不对时访问＝互连挂死、零 printk、只能断电（三次同签名实测） | A/B |
| PL DDR | 约 2 GiB（规格 2 GB；ETM 占用比反推吻合）；NPU 主战场——硬算子参数/FTMP/INSTR/KV 住 PLDDR，软算子住 PSDDR。**DT 有 `memory@0` 但无 `reserved-memory` 子节点，PL DDR 在 PS 的 `/proc/iomem` 中完全不可见**（板证） | A/B |
| NPU 可达 | PLDDR 直达；PS DDR 只经 **CDMA @0x8000_0000** 交换 udma 窗（厂商栈搬运者）；自研 PL 主设备经 **HP 口**可访整段 PS DDR（中间无 IOMMU） | B |
| DMA 控制器 | 三套：① 厂商 CDMA（GP1）；② PS **dw_dmac e004b000 8 通道**（`/proc/interrupts` 9 号线 51563→53233 递增＝活动链在用）；③ **f0010000 8 通道＝DesignWare AXI DMA**（`DW_AXI_DMAC=y`、`snps,axi-dma-1.01a`、每通道独立 IRQ；**8 条 channel IRQ 全程计数 0 ⇒ 现役链不用内核 AXI DMA**，与"厂商走用户态 mmap＋CDMA"互证） | A |
| DMA 地址 | **本板 DMA addr==phys 成立（实测事实，非假设）**：`libaxizg330aiu.so` 自己 `open("/dev/mem")` mmap 物理窗＋`/dev/udmabuf0`（sysfs 直报 phys_addr），demo 把 `tensor.data().addr()`（物理址）直写硬件寄存器。**例外**：NPU 侧 `logic_addr` 走内部 MMU（`mmu_mode=True`＋XRT MMUMapTable/SegTable），logic≠phys，映射由 runtime 管。Rust 层把"==phys"编码成**启动时校验的常量**，不编码成前提 | A/B |
| IOMMU/SMMU | **收窄口径**：`ARM_SMMU=y`＋`IOMMU_API/DMA=y`＋`DISABLE_BYPASS_BY_DEFAULT=y`——SMMU **驱动在内核里**；但 DT 未布线：`/sys/kernel/iommu_groups` 空、dmesg 无 SMMU probe、**DT 无 `iommus`／`iommu-map`／`dma-ranges` 属性（板测 count=0）** ⇒ **运行时无跨设备隔离**。`OF_IOMMU=y`＋Default domain Translated ⇒ 未来重编可启用（可选能力，不是没有）。板上 MMU ABORT 全是设备**内部** MMU | A |
| Cache（板证补强） | **非硬件一致性已坐实**：DT `dma-coherent` 属性 count=0；`udmabuf0/dma_coherent = 0`（sysfs 直读）；`sync_mode=1`＝u-dma-buf 源码的 `SYNC_MODE_NONCACHED`。维护函数链直读板上 `/root/udmabuf/u-dma-buf.c`：写 `sync_for_cpu` → `dma_sync_single_for_cpu(phys,size,dir)`，写 `sync_for_device` → `dma_sync_single_for_device(...)`，命令字编码 offset/size/direction；现役链 `sync_size=1036800`＝960×540×2 **恰好一帧 UYVY**（按帧同步的实证）。XRT 侧＝`CacheSyncHostMemRegionNode::read/write/memcpy`＋GP1 cache 块 @0x8000_0C00；**dma-buf/sync_file 框架在**（`DMA_SHARED_BUFFER=y`＋`SYNC_FILE=y`，SW_SYNC 调试 fence 没开）⇒ 内核 fence 积木存在。**同步成本已测（A）**：用户态写 sysfs **~0.088 µs/op**（20 次连写实测，三轮复现一致；只含用户态下发开销，实际 DMA 同步在内核侧） | A |
| 对齐 | 相机/显示/PS-DMA **128 B**；ETM/权重/FTMP **4096 B**（厂商参考工程实测口径）；API 层 `malloc` 第三参即对齐（我方 KV 探针 4096 实证）；udmabuf 天然页对齐 | A |
| 所有权 | **内核不互斥**：两条链 mmap 同一物理窗无任何保护（实测教训）⇒ frame_lease 单所有者租约＋npuserv openDevice-每进程一次＋apply 窗口期相机让位，全部生产现役 | A |
| Recovery | 三档：① 运行时异常（11015/hardop sync failed）→ 进程退出 → CMA 全归还；② 互连挂死 → 只能断电；③ `Device::reset(level)` 有 0/1 两档实现（见 §二 反汇编），**等级语义未确认前不得据它设计故障恢复**（§七 B4，她建议前置此项） | A/B |
| 备用积木 | `REMOTEPROC`＋`FMQL_REMOTEPROC`＋`RPMSG=y`（dmesg 无 probe，配对固件未核）；`UIO`＋`UIO_PDRV_GENIRQ`＋`OF_OVERLAY=y`；**watchdog 驱动在（XILINX/DW）但 DT 未布线**（`/dev/watchdog*` 无、`/sys/class/watchdog/` 空、driver bind 目录无设备、dmesg 仅 GEM 网卡的 "HW Watchdog Timer" 非系统 WDT）⇒ 现役不可用，安全设计不能依赖它（§七 A11 闭合）；CPUIdle 无 C-state（§一） | A |

## 六、架构决策输入（G 节）

- **已定**：Linux（seL4/Theseus 无计划）；进程隔离＋systemd＋单 owner 仲裁；IPC＝HTTP/TCP 控制面＋udmabuf 共享内存数据面（无 ROS）。
- **内核强制面≈空**（§一）⇒ 安全约束落在用户态：进程边界＋RLIMIT_AS＋Rust 类型。rsop 的 Capability/Lease/统一资源管理**正好落在厂商没做的那一层**——ICraft 把"能编、能跑、内存可管"做成了正式 API，把"隔离、调度、并发、恢复"留给了应用层，这不是重复造轮子。
- **实时设计的板证输入**：FIFO/RR/DL 三策略在位且 `sched_rt_*` 只有全局一把尺；FIFO 绑核把 1 ms 唤醒尾延迟从 10.8 ms 压到 1.1 ms；无 C-state、无需 PREEMPT_RT；watchdog 需 DT 改造才有硬件兜底。
- **统一调度/资源 manager/Capability**＝rsop 落地的三个真工作量；统一内存、零拷贝、fence 都要按本页 §二/§三 的真实边界设计（零拷贝只在 128 MiB udma 窗内成立；跨 PS↔PL DDR 必过 CDMA；"DMA addr==phys"只在启动校验下成立）。

## 七、现在真正未解决的问题（A/B/C 分类与 2026-11-08 实测状态）
