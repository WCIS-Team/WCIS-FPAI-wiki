# ZG330平台能力边界

> **本页回答什么问题**：把 2026-11-08 五轮能力调查（OS 与实时、ICraft API、Buffer、DDR/DMA/Cache、七节盘点）与同日板上只读探针合并去重后的**平台能力边界总表**——每条给结论、证据级别与正本链接。证据级别：**A**＝板上实测（raw_logs／提取件／生产读数）、**B**＝厂商文档与源码直证、**C**＝推断未测。
> **本页不回答**：进度与裁定（[[状态源与决策记录]]）；逐模型可行性（[[1-NPU模型部署]]）；硬件规格全集与采集方法（[[硬件与基础运行环境档案]]——那边答"这台板子有什么"，本页答"这些能力能不能用、怎么用"。规格数字本页只在边界推理需要时引用）。
> **探针出处**：2026-11-08 板上只读探针（config 全文／meminfo／iomem／dmesg／dev 节点，root@192.168.1.113）；关键读数已全部收编本页，原始输出当日留存于会话记录，未落 `raw_logs/`（如需归档另行登记）。

## 一、板卡与 Linux

| 项 | 结论 | 级别 |
|---|---|---|
| 板卡/SoC | FMQL30TAI676H 悟净·完整版；dtb 自报 `FMQLMP FMQL100TAI`／`fmsh,fmsh-fmqlmp`＝复用 100TAI 参考树、不代表贴片 | A |
| Boot/BSP | FSBL＋bl31＋U-Boot v2022.10；bootargs＝`mem=1024M … clk_ignore_unused`（clk 链"不可动"的机制解释） | A |
| 发行版 | Ubuntu **20.04.4 LTS** focal，aarch64 | A |
| 内核 | **5.4.52** `#3 SMP Fri Mar 13 13:44:29 CST 2026`，Linaro GCC 7.5-2019.12，`ARCH_FMQLMP`，`LOCALVERSION_AUTO`（版本串干净）；两棵 5.4.52 源码树＋defconfig 在提取件 ⇒ 重编路径通 | A |
| CPU | 4×Cortex-A53 stepping **r0p4**，标称 ≤1 GHz；**运行时无 cpufreq 节点**（`CPU_FREQ`/`CPUFREQ_DT` 框架在、DT 未给 OPP 表 ⇒ 不可调也不可读）；BogoMIPS 200.00 不是频率读数 | A |
| 定时器 | `HZ=250`、`HIGH_RES_TIMERS=y`、`NO_HZ_IDLE`（非 FULL）、`SCHED_HRTICK=y` | A |
| 抢占 | **`PREEMPT_NONE=y`**（VOLUNTARY/PREEMPT 都没开）；非 RT（`/sys/kernel/realtime` 不存在，探针实测）。RT 重编＝条件项：源码与 defconfig 在，但 u-dma-buf/mali/amvx 三个厂商 `.ko` vermagic 绑 5.4.52 须重出（amvx/mali 是厂商黑盒） | A |
| 中断 | `IRQ_FORCED_THREADING=y` ⇒ `threadirqs` 启动参数免重编可用（除 `IRQF_NO_THREAD` 者） | A |
| cgroup | `CGROUPS=y` 但 SCHED/PIDS/MEMCG/CPUSETS/DEVICE/CPUACCT **全部 not set**；`/proc/cgroups` 零行、`cgroup.controllers` 空文件互证 ⇒ **零控制器**；systemd `MemoryMax`/`CPUQuota` 被静默接受但完全无效（D-43 实测）＝**假闸门** | A |
| Namespace/seccomp/LSM | `NAMESPACES not set`；`SECCOMP not set`（`HAVE_ARCH_SECCOMP_FILTER=y`＝架构支持在，开关没开）；`SECURITY not set` ⇒ **LSM 框架不存在**（config 里 `LSM="lockdown,yama,loadpin,safesetid,integrity"` 是死字符串）；全 root。**内核强制面≈空，安全只能落在进程边界＋RLIMIT＋用户态** | A |
| RT 调度 | FIFO/RR 可用；控制面＝`RLIMIT_RTPRIO`＋全局 `sched_rt_period/runtime` sysctl 一把尺（`RT_GROUP_SCHED` 随 `CGROUP_SCHED` 未编，无 per-group）；SCHED_DEADLINE 主线无条件编译＋HRTICK ⇒ 准入＝自带全局带宽制、不受 rt_runtime 节流。板证待补：`chrt -d` 冒烟（唯一 C 级口） | A/B/C |
| 现役配额方式 | `taskset`＋`nice`＋SIGSTOP/SIGCONT 占空比——全部生产实证（ASR 抢核 RTF 0.80、视频链钉 cpu0 满帧 30fps、闲时压缩 0.15s/0.85s） | A |

## 二、ZG330 与 ICraft

| 项 | 结论 | 级别 |
|---|---|---|
| 版本 | 本机 CLI **3.39.0**（`3.39.0.0-431be90`）；板端 runtime v3.39.0 compat=true；厂商 ModelZoo 条目多标 3.33.1（代差已记，复现不等于复现结论） | A |
| 正式 API 面 | xrt 的 Session/Device/Tensor/Backend/MemRegion/MemManager 族（C++＋Python 双参考）；CLI 八命令 parse/optimize/quantize/adapt/generate/compile/run/show | B |
| **Scheduler** | **不存在**：全文档 `(?i)scheduler` 0 命中、bin 11 个 exe 无此物。「按优先级创建Session」＝CreateByOrder 的**算子绑定后端尝试顺序**，不是任务优先级——别当调度器证据 | A/B |
| 并发/取消 | `forward` 同步阻塞；无 cancel/abort（超时抛 11015，错误码表 11002–11015）；多模型并发未承诺（Server 文档逐字"不要同时打开多个 Server，否则将导致不可预期的错误"）；`FForwardBackend` 签名带 `uint8_t priority` 形参但零解释；唯一并发线索＝"复制 Backend 用于多线程"＋yolov5s_multi_thread 进程内三级流水 demo。多模型分时编排一直是我方 OrchestrationLayer 的职责 | A/B/C |
| 量化面 | `qdtype`＝int8/bf16/fp16/tf32，**无 int4**；30TAI 不再支持 int16；`asymmetric` 暂不支持＝只有对称；校准仅 INT8 需要；`per`=tensor/channel/group、`saturation`=kld/ems/null、`mix_precision`=auto/csv；fp16 自 3.33.1 落地。LLM 用 fp16 是厂商选型不是硬约束（D-77） | B |
| 算子面 | ONNX 入口 opset 17（<15 直接解析错）；114 页 spec **无 RMSNorm**；`Where` 在 ZG 是软算子落 host；`Gather` 有定义没下降；`RopeDynamic` 只在 host；厂商 223 行模型表实测 44 行不支持黑名单 | A/B |
| LLM 通路 | 入口只有 PyTorch 1.9 `.pt`／ONNX，**GGUF 无入口**；长度编译期烘死（厂商件 `max_prompt_length 32`／`max_tokens_length 512`，**含 prompt**）；厂商大模型先例＝Qwen2-0.5B／Qwen2.5-7B 两条 | B |
| Buffer API | 分配＝`MemRegion::malloc(size, auto_free, align)`／`Tensor::mallocOn`／自备 chunk（1.3.2 指定输出地址，仅 ZG）；**外部导入三条**：`malloc(MemPtr begin, size, FChunkDeleter, auto_free)`、`MemPtr(PtrType::CPTR)` 包 host 指针、xir `ExternalMem(addr)`（ZG 后端直取 logic_addr）；同步＝`Tensor::waitForReady(timeout, poll)`＋自定义 check_func（自造 fence 的积木）；host cache 语义＝`CacheSyncHostMemRegion`；**复位＝`Device::reset(level)`/`check(level)`/`showStatus(level)` 正式 API** | B |
| 板证三口 | ① CacheSync 触发点与开销；② 11015 后不 reset 能否续跑；③ ZG330 的 reset 等级值（文档只给了 AXIQL100AIU 的 0/1 表） | C |

## 三、DDR / DMA / Cache / IOMMU

| 项 | 结论 | 级别 |
|---|---|---|
| PS DDR | 物理窗 **0x0000_0000–0x4000_0000**（`mem=1024M`；`/proc/iomem` 实证 `System RAM 00000000-3fffffff`，内核/保留段在其中）；可用约 993 MB；另有 1 G swapfile（D-44） | A |
| CMA/udmabuf | CMA 256 MiB（`CMA_SIZE_MBYTES=256`、ALIGNMENT=8）；`udmabuf0` 128 MiB @ 0x3010_0000 **静态**从池里划走（节点无 `reg`，overlay 挪不动）⇒ **池有效≈128 MiB 不是 256**；ZG 一次完整推理借走约 122 MB、用完归还 | A |
| GP0/GP1 | 0x4000_0000/0x8000_0000 是 PL 的 AXI 从窗**不是内存**（GP0：host_ctrl/AI 寄存器，自研可用 0x4008_0000–0x7FFF_FFFF；GP1：CDMA/ImageMake/IcorePost/Cache 块）；位流不对时访问＝互连挂死、零 printk、只能断电（三次同签名实测） | A/B |
| PL DDR | 约 2 GiB（规格 2 GB；ETM 占用比反推吻合）；NPU 主战场——硬算子参数/FTMP/INSTR/KV 住 PLDDR，软算子住 PSDDR | A/B |
| NPU 可达 | PLDDR 直达；PS DDR 只经 **CDMA @0x8000_0000** 交换 udma 窗（厂商栈搬运者）；自研 PL 主设备经 **HP 口**可访整段 PS DDR（中间无 IOMMU） | B |
| DMA 控制器 | 三套：① 厂商 CDMA（GP1）；② PS **dw_dmac e004b000 8 通道**；③ **f0010000 8 通道＝DesignWare AXI DMA**（`DW_AXI_DMAC=y`、`snps,axi-dma-1.01a`、每通道独立 IRQ——不是 Xilinx IP，2026-11-08 探针 dmesg 建档） | A |
| DMA 地址 | **本板 DMA addr==phys 成立（实测事实，非假设）**：`libaxizg330aiu.so` 自己 `open("/dev/mem")` mmap 物理窗＋`/dev/udmabuf0`（sysfs 直报 phys_addr），demo 把 `tensor.data().addr()`（物理址）直写硬件寄存器。**例外**：NPU 侧 `logic_addr` 走内部 MMU（`mmu_mode=True`＋XRT MMUMapTable/SegTable），logic≠phys，映射由 runtime 管。Rust 层把"==phys"编码成**启动时校验的常量**，不编码成前提 | A/B |
| IOMMU/SMMU | **收窄口径**：`ARM_SMMU=y`＋`IOMMU_API/DMA=y`＋`DISABLE_BYPASS_BY_DEFAULT=y`——SMMU **驱动在内核里**；但 DT 未布线：`/sys/kernel/iommu_groups` 空（探针）、dmesg 无 SMMU probe、dtb 无 iommu 节点 ⇒ **运行时无跨设备隔离**，NPU/PL 可直达整段 PS DDR。`OF_IOMMU=y`＋Default domain Translated ⇒ 未来重编可启用（可选能力，不是没有）。板上的 MMU ABORT 全是设备**内部** MMU（MVX/Mali/NPU），不提供跨设备保护 | A |
| Cache | 无硬件 I/O 一致性证据，**按不有一致处理**：直读 `/dev/udmabuf0` 不 sync 拿到陈旧行（实测作废过判据）。维护函数＝udmabuf fd write（`sync_for_cpu`/`sync_for_device`＋mode/direction/offset/size，trace 实证 8 节点常开）＋XRT `CacheSyncHostMemRegion`＋GP1 cache 寄存器块 @0x8000_0C00。**dma-buf/sync_file 框架在**（`DMA_SHARED_BUFFER=y`＋`SYNC_FILE=y`，SW_SYNC 调试 fence 没开）⇒ 内核 fence 积木存在。一致性责任划分挂厂商三问 | A/B |
| 对齐 | 相机/显示/PS-DMA **128 B**；ETM/权重/FTMP **4096 B**（厂商参考工程实测口径）；API 层 `malloc` 第三参即对齐（我方 KV 探针 4096 实证）；udmabuf 天然页对齐 | A |
| 所有权 | **内核不互斥**：两条链 mmap 同一物理窗无任何保护（实测教训）⇒ frame_lease 单所有者租约＋npuserv openDevice-每进程一次＋apply 窗口期相机让位，全部生产现役 | A |
| Recovery | 三档：① 运行时异常（11015/hardop sync failed）→ 进程退出 → CMA 全归还；② 互连挂死 → 只能断电；③ `Device::reset(level)` API 在但等级值未文档化、挂死时执行不到 | A/B/C |
| 备用积木 | `REMOTEPROC`＋`FMQL_REMOTEPROC`＋`RPMSG=y`（dmesg 无 probe，配对固件未核）；`UIO`＋`UIO_PDRV_GENIRQ`＋`OF_OVERLAY=y`；watchdog 驱动在（XILINX/DW，`HANDLE_BOOT_ENABLED=y`）但 **/dev 无 watchdog 节点**（DT 布线疑点，见 §七）；`ARM_CPUIDLE=y` ⇒ 四核可进深睡，唤醒延迟进实时预算，`/dev/cpu_dma_latency` 在位可压 | A |

## 六、架构决策输入（G 节）

- **已定**：Linux（seL4/Theseus 无计划）；进程隔离＋systemd＋单 owner 仲裁；IPC＝HTTP/TCP 控制面＋udmabuf 共享内存数据面（无 ROS）。
- **内核强制面≈空**（§一）⇒ 安全约束落在用户态：进程边界＋RLIMIT_AS＋Rust 类型。rsop 的 Capability/Lease/统一资源管理**正好落在厂商没做的那一层**——ICraft 把"能编、能跑、内存可管"做成了正式 API，把"隔离、调度、并发、恢复"留给了应用层，这不是重复造轮子。
- **统一调度/资源 manager/Capability**＝rsop 落地的三个真工作量；统一内存、零拷贝、fence 都要按本页 §二/§三 的真实边界设计（零拷贝只在 128 MiB udma 窗内成立；跨 PS↔PL DDR 必过 CDMA）。
