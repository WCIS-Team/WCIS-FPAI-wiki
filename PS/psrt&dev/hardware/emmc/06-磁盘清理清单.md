> **⚠ 旧版这里少列了 `/mnt/data`**（`mmcblk0p3` 30G），它是**同一张 SD 卡**上的第三个分区，不是独立盘。旧版只写了 p2 与 eMMC 两个，容易让人以为"SD 卡只有系统盘那 26 G"。

**三个分区的物理关系（`lsblk` 实测）**：

```
mmcblk0     58.4G   ← 这张 SD 卡
 |-p1          1G   ← FAT，/mnt/boot 的位流所在（本次开机没自动挂）
 |-p2       26.1G   ← /          系统盘
 |-p3         30G   ← /mnt/data  模型与 cli
mmcblk1     29.1G   ← eMMC 芯片（独立物理器件）
 |-p1       29.1G   ← /mnt/wcis-emmc  录像
```

⇒ **`/` 与 `/mnt/data` 是同一条 SD 卡的两个分区，`/mnt/wcis-emmc` 才是独立器件。** 这决定了"把东西挪到哪里"的策略（见第五节）。

## 五、根本解法：把项目挪到 `/mnt/data`（不是 eMMC）

> **旧版这一节写错了方向。** 旧版说"eMMC 有 28G 空闲，挪过去"——但 `/mnt/wcis-emmc` 的挂载参数是 **`nosuid,nodev,noexec`**，且上面跑着现役录像（`--quota-mib 4096`）。**更合适的落点是 `/mnt/data`**（`/dev/mmcblk0p3`，30G，只用了 2.1G）——它没有 `noexec`，`mount` 实测是 `rw,relatime`。

```bash
# 例：把从没用过的模型档挪到 /mnt/data 并软链回来（用候选目录先验一次）
mkdir -p /mnt/data/projects
mv /root/funasr/models/ContextualParaformer /mnt/data/projects/
ln -s /mnt/data/projects/ContextualParaformer /root/funasr/models/ContextualParaformer
```

注意：

- `/mnt/data` 是**同一张 SD 卡的第三个分区**（见第一节的 `lsblk`），挪过去**不换物理介质**，只是缓解 `/` 的 76% 压力；真要换介质只有 eMMC，而它 `noexec` ⇒ 适合放**纯数据/模型**（不放可执行）。
- 软链回 `/root` 后程序按原路径访问不受影响。
- 迁现役服务的目录前先 `systemctl stop` 再 `mv` 再 `ln` 再 `start`，别在跑的时候挪。

1. **先列出，再删** —— 先 `du -sh` 看清楚。
2. **缓存可以直接删，项目目录必须确认**。
3. 大批量删除前先 `tar` 备份到 `/mnt/data`。
4. **（10-31 新增）删之前先 `ps` + `find / -xdev -newermt "-15 minutes" -size +1M`** —— 这块板是共享的，看 `df` 静止不代表没人正要写（当天就撞过：另一条会话在我删完 2 分钟后就往同目录写回了同族产物，见台账 §24.3）。
5. **（10-31 新增）每删完一批当场 `df -h` 复读**，把读数记下来；别一次删到最后才看。
6. **（10-31 新增）删完复查现役服务**：`systemctl is-active klar-voice-gateway klar-nlu-engine klar-console klar-autotoken wcis-sdi-vpu-view wcis-face-recording wcis-face-photo wcis-heartbeat` —— **必须 8 个全 `active`**（2026-10-31 11:12 UTC 实测就是 8/8 active）。⚠ **判"是不是我删坏的"要连 `Active:` 那行一起看**：`wcis-face-photo` 在 10-30 20:41 曾因 `camera_interlock.py:33` 的硬件复核互锁（`RuntimeError: Hardware review required; no automatic SDK reuse`）失败过一次，**但在 10-31 10:20:46 那次重启后自己恢复正常**——所以它现在的 `active` 不是"清理没事"的证据，而是"重启把它带起来了"。真要验与本页清理的因果关系，看 `Active: active (running) since …` 的时刻是不是晚于你的删除动作。
