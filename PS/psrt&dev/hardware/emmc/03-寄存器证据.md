# 03 · 寄存器证据

所有读数通过 `busybox devmem <addr>` 只读获取，未做任何写操作。

## 一、MMC 控制器寄存器对比

```bash
# eMMC
busybox devmem 0xe0044000    # CTRL
busybox devmem 0xe0044070    # HCON
# SD
busybox devmem 0xe0043000
busybox devmem 0xe0043070
```

### 1.1 完整寄存器 dump（eMMC，boot `72a8f941`）

```
+0x000 = 0x00000010   CTRL        bit4 INT_ENABLE=1, bit5 DMA_ENABLE=0  ← PIO
+0x004 = 0x00000001   PWREN       电源已开
+0x008 = 0x00000002   CLKDIV      2  → 100MHz/(2×2) = 25MHz
+0x00c = 0x00000000   CLKSRC      0  → 用 ciu（内部时钟）
+0x010 = 0x00010001   CLKENA      bit0 cclk_enable=1, bit16 low_power=1
+0x014 = 0xFFFFFFFF   TMOUT       ← 全 1，见下方"不可信字段"
+0x018 = 0x00000001   CTYPE       **bit0=1 → 4-bit 总线**
+0x01c = 0x00000200   BLKSIZ      512（上次传输残留）
+0x020 = 0x00000200   BYTCNT      512（上次传输残留）
+0x024 = 0x0000B7FF   INTMASK
+0x028 = 0x00010000   CMDARG
+0x02c = 0x2000014D   CMD
+0x030 = 0x00000900   RINTSTS     W1C 残留
+0x034 = 0xFFFFFFFF   STATUS      ← 全 1
+0x038 = 0xF1FFFFFF   FIFOTH      ← 全 1 附近
+0x03c = 0x00000900   CDETECT     ← 可疑（non-removable 应为 0）
+0x044 = 0x00010000   GPIO
+0x048 = 0x00006906   TCBCNT      累计已传字节
+0x04c = 0x200F0010   TBBCT
+0x05c = 0x00000200   PLDMND
+0x060 = 0x00000200   DBADDR
+0x064 = 0x00FFFFFF   IDSTS
+0x06c = 0x5342220A   VERID       "SB" + 0x220A → DW MSHC 2.20a
+0x070 = 0x07E52CC1   HCON        **[17:16]=01 DWDMA**
+0x074 ~ 0x0FC = 0x07E52CC1（全部相同，见下方说明）
```

偏移表按 Linux `drivers/mmc/host/dw_mmc.h` 排列。0x000→0x06C 共 28 个 32 位寄存器，
与 `dw_mmc.c` 读 `VERID`(0x06C) 打印 `Version ID is 220a` 完全吻合，所以这张表是可信的。

### 1.2 交叉验证过的字段（可以直接引用）

| 寄存器 | 偏移 | eMMC | SD | 独立佐证 |
|---|---|---|---|---|
| CTRL | 0x000 | `0x00000010` | `0x00000030` | dmesg `Using PIO mode` / `Using external DMA controller` |
| CLKDIV | 0x008 | `0x00000002` | `0x00000001` | dmesg `actual 25000000HZ div = 2` / `50000000HZ div = 1` |
| CLKENA | 0x010 | `0x00010001` | `0x00010001` | 时钟确实在跑 |
| CTYPE | 0x018 | `0x00000001` | `0x00000001` | EXT_CSD[183]=1（卡侧也报 4-bit） |
| VERID | 0x06c | `0x5342220A` | `0x5342220A` | dmesg `Version ID is 220a` |
| **HCON** | 0x070 | **`0x07E52CC1`** | **`0x07E52CC1`** | mmc0 确实用了外部 DMA |

### 1.3 不可信字段（本 IP 变体未实现，读出来是全 1，不要引用）

`TMOUT`(0x014)、`STATUS`(0x034)、`FIFOTH`(0x038)、`CDETECT`(0x03C)、`IDSTS`(0x064)
读出来都是 `0xFFFFFFFF` / `0xFFFFFF` / `0xF1FFFFFF` 这类全 1 值。这是"寄存器未实现、
总线返回全 1"的典型表现，**不代表真实状态**。判断状态请用 dmesg 和 sysfs，不要用这些字段。

> ⚠️ 本节早期版本把 `STATUS` 写成 0x048、`FIFOTH` 写成 0x04C，是错的。
> 0x048/0x04C 实际是 `TCBCNT`/`TBBCT`（累计传输字节计数器），所以每次读都不一样。

### 1.4 0x074 以上全是同一个值

`0x074` ~ `0x0FC` 每个地址读出来都是 `0x07E52CC1`（HCON 的值）。
说明这个 IP 集成时**只解码到 0x070 为止**，更高地址没有寄存器。所以不要再往上找隐藏寄存器了。

### 1.5 CTRL 解码（关键）

```
eMMC 0x00000010 = 0b0001_0000  → bit4 INT_ENABLE=1, bit5 DMA_ENABLE=0
SD   0x00000030 = 0b0011_0000  → bit4 INT_ENABLE=1, bit5 DMA_ENABLE=1
```

**这就是"eMMC 在跑 PIO"最直接的硬件证据。**

### 1.6 HCON 解码（关键）

`0x07E52CC1` 二进制：

```
0000 0111 1110 0101 0010 1100 1100 0001
b31-b28: 0000
b27-b24: 0111
b23-b20: 1110
b19-b16: 0101     ← b17=0, b16=1
b15-b12: 0010
b11-b8 : 1100
b7 -b4 : 1100
b3 -b0 : 0001
```

| 位域 | 值 | 含义 |
|---|---|---|
| `[17:16]` TRANS_MODE | `01` | **DWDMA — 硬件支持 DesignWare 外部 DMA** |
| `[27]` ADDR_CONFIG | `0` | IDMAC 32-bit 地址模式（本机未用 IDMAC） |
| `[9:7]` HDATA_WIDTH | `1` | 32-bit FIFO 访问宽度（`dw_mmc.c:3258`） |

驱动里的定义（`dw_mmc.h:410-417`）：

```c
#define DMA_INTERFACE_IDMA   (0x0)   // 内部 DMA
#define DMA_INTERFACE_DWDMA  (0x1)   // Synopsys DW-DMA  ← 本机是这个
#define DMA_INTERFACE_GDMA   (0x2)   // 通用 DMA
#define DMA_INTERFACE_NODMA  (0x3)   // 仅 PIO
#define SDMMC_GET_TRANS_MODE(x)   (((x)>>16) & 0x3)
#define SDMMC_GET_HDATA_WIDTH(x)  (((x)>>7)  & 0x7)
#define SDMMC_GET_ADDR_CONFIG(x)  (((x)>>27) & 0x1)
```

**结论：控制器硬件明确报告支持外部 DMA，不是 `0x3 (NODMA)`。**

## 二、驱动为什么还是选了 PIO

`dw_mmc.c:2890-2960` 完整逻辑：

```c
host->use_dma = SDMMC_GET_TRANS_MODE(mci_readl(host, HCON));   // = 1 (DWDMA)
if (host->use_dma == DMA_INTERFACE_IDMA) {
        host->use_dma = TRANS_MODE_IDMAC;
} else if (host->use_dma == DMA_INTERFACE_DWDMA ||
           host->use_dma == DMA_INTERFACE_GDMA) {
        host->use_dma = TRANS_MODE_EDMAC;                       // 走到这里
} else {
        goto no_dma;
}

...
} else {
        /* TRANS_MODE_EDMAC: check dma bindings again */
        if ((device_property_read_string_array(dev, "dma-names", NULL, 0) < 0) ||
            !device_property_present(dev, "dmas")) {
                goto no_dma;                                    // ← eMMC 卡在这里
        }
        host->dma_ops = &dw_mci_edmac_ops;
        dev_info(host->dev, "Using external DMA controller.\n");
}
```

eMMC 节点既没有 `dmas` 也没有 `dma-names`，所以落到 `no_dma`，打印 `Using PIO mode.`

## 四、时钟树

### 4.1 CPU 与 SDIO 是两条独立的时钟链（重要）

```bash
cat /sys/kernel/debug/clk/clk_summary
```

```
armpll_int        1  1  0  1000000000        ← ARM PLL，喂 CPU
   armpll         1  1  0  1000000000
      armpll_clk  2  2  0  1000000000

iopll_int         2  2  0  1000000000        ← IO PLL，喂外设
   iopl_clk       6  6  0  1000000000
      sdio_mux    1  1  0  1000000000
         sdio_div 2  2  0   100000000        ← 固定 /10
            sdio1 1  1  0   100000000        ← eMMC 用这个
            sdio0 1  1  0   100000000        ← SD 用这个
```

父节点链（`/sys/kernel/debug/clk/<name>/clk_parent`）：

```
sdio1    → sdio_div
sdio_div → sdio_mux
sdio_mux → iopl_clk      ← 不是 armpll
iopll    → iopl_int
```

**结论：CPU 在 `armpll` 分支，SDIO 在 `iopll` 分支，两者从 PLL 层就分开。改 SDIO 分频碰不到 CPU。**

### 4.2 CPU 频率不可调（硬件锁定）

```bash
ls /sys/devices/system/cpu/cpu0/cpufreq
# 不存在
```

- 没有 `cpufreq` 接口
- 没有 `cpu_opp_table`
- 设备树 `operating-points-v2` 被注释掉
- `cpu@0` 无 `clock-frequency` 属性

CPU 频率由 `armpll` 硬件决定，**软件没有任何调节入口**，本方案也不涉及。

### 4.3 SDIO 时钟与分频

运行时实际时钟（`/sys/kernel/debug/mmcX/ios`）：

```
mmc1 (eMMC): clock: 25000000 Hz, bus width: 4 bits, timing: mmc high-speed, vdd 3.3V
mmc0 (SD)  : clock: 50000000 Hz, bus width: 4 bits, timing: sd high-speed,  vdd 3.3V
```

DW MSHC 分频规则：`实际时钟 = ciu / (2 × CLKDIV)`（CLKDIV>0 时）
- eMMC：100MHz / (2×2) = **25MHz**
- SD：100MHz / (2×1) = **50MHz**

## 五、DMA 控制器寄存器

```bash
busybox devmem 0xe004b018   # chan0 CTL_LO = 0x00304801
busybox devmem 0xe004b040   # chan0 CFG_LO = 0x00000E00
busybox devmem 0xe004b1e8   # DWC params = 0x00000000
```

| 通道 | CFG_LO | 解读 |
|---|---|---|
| chan0 | `0x00000E00` | bit9 FIFO_EMPTY、bit10 HS_DST、bit11 HS_SRC → 双向硬件握手（被 SD 占用） |
| chan1 | `0x00000E20` | bit5 置位 |
| chan2 | `0x00000E40` | bit6 置位 |

`DWC_PARAMS` 读出来是 0，说明该偏移不适用（DW_DMA_MAX_NR_CHANNELS 不同），参数以设备树为准：8 通道 / 16 请求线。

### 6.2 能力（DEVICE_TYPE[196] = `0x57`）—— 这是"能不能提速"的答案

| bit | 含义 | 值 |
|---|---|---|
| 0 | High Speed 26/52 MHz | **支持** |
| 1 | HS200（200MHz SDR @1.8V） | **支持** |
| 2 | HS400（200MHz DDR @1.8V） | **支持** |
| 3 | HS400 Enhanced Strobe | 不支持 |

**结论：卡本身完全不是瓶颈。** 52MHz / HS200 / HS400 卡都支持，
瓶颈全在控制器侧（`max-frequency` 钉在 25MHz + ciu 只有 100MHz + 没有 1.8V 稳压器）。

### 6.3 当前实际配置

```
BUS_WIDTH   [183] = 1  → 4-bit      （不是 8-bit）
HS_TIMING   [185] = 1  → high speed （不是 HS200/HS400）
PARTITION_CONFIG [179] = 0x00  （无 boot 分区切换，正常）
BOOT_BUS_WIDTH   [177] = 0x00
EXT_CSD_REV [192] = 8  → eMMC 5.1
```

### 6.4 健康度

```
PRE_EOL_INFO                [267] = 0x01  → 正常
DEVICE_LIFE_TIME_EST_TYP_A  [268] = 0x01  → SLC 已用 0~10%
DEVICE_LIFE_TIME_EST_TYP_B  [269] = 0x01  → MLC 已用 0~10%
```

**这块盘几乎没用过，随便写。** 之前担心的"录像会不会写坏 eMMC"可以放心了。

### 6.5 8-bit 能不能上？——EXT_CSD 不告诉你

eMMC 规范里**没有**"最大总线宽度"字段，`BUS_WIDTH[183]` 只反映当前设置。
8-bit 是否可用只能靠试：改 DTB `bus-width = <8>`，重启看 dmesg 是否报
`Bus width 8` 且数据校验正常。**读寄存器读不出来，别浪费时间找。**

## 七、内核 overlay 能力

```
CONFIG_OF_OVERLAY=y
CONFIG_OF_CONFIGFS=y
/sys/kernel/config/device-tree/overlays/   ← 存在，可写
```

`drivers/of/overlay.c:349-361` 确认：给**已存在节点新增属性**走 `of_changeset_add_property`，是允许的。只禁止修改 `#address-cells`、`#size-cells`、`phandle`、`name` 这类关键属性。

```
NO __symbols__      ← 运行中的 DTB 没有符号表，overlay 不能用 &label 引用
dmahost0 phandle    = 0x0a (10)   ← 只能硬编码这个值
```
