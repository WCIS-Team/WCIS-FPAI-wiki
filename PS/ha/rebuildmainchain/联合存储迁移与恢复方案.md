# 联合存储迁移与恢复方案

## 迁移输入与清单

本页是目标迁移协议，**本轮没有执行迁移**。目标主存储从第一版即为 SQLite，数据模型见 [[联合人员与业务数据设计#数据归属总表|联合人员与业务数据设计——数据归属总表]]。实施工具应先提供只读 plan 和离线 staging，正式切换必须对应已核实的目标版本与维护窗口。

| 输入 | 必须盘点与保留 |
|---|---|
| 视频 schema 2 gallery | 所有 person/sample UUID、name、revision、pipeline_id、向量原值、original 元数据和原始媒体；models.json 原始字节及模型工件哈希、verification 与阈值来源 |
| 旧 schema 1 或历史迁移件 | photos、removed／trash 和用来找回精确原图的 samples/runtime 输入；不能当旧垃圾删除 |
| 旧 boards 声纹库 | version、dim、name→单向量；模型路径、可核实工件哈希、来源资料；无模型指纹的记录待核对 |
| 新 lang 声纹库 | name→多样本向量及 updated、replace 语义、配置阈值与模型档；与旧声纹分别识别格式 |
| 特征历史 SQLite | 一致性数据库快照、schema/pipeline/dimension/capacity、source 标识与 URI/SHA、帧序号/PTS、quality/policy、box、向量与旧 row ID |
| 设备实体和设置 | klar entity/area、executor 目标映射、现役 YAML 覆盖、录像 retention/compression 策略及服务启动参数；分别标默认、用户显式和无法判定来源 |
| 录像及照片目录 | 完整媒体、frames.jsonl、摘要、压缩副本／元数据、.trash、purging、part／ready 和未完成作业；不因扩展名像临时件就清理 |
| 运行与发布证明 | 服务版本、BOOT／模型证明、owner/current／stream-current、硬件隔离标记、停止回执和回滚清单；锁及内存状态只能重新建立，不能从文件复制恢复“已持锁” |

每份清单包含 source_store_id、源角色、绝对位置与受控相对位置、格式版本、文件数／字节数、哈希、mount UUID、扫描时间及读失败项。数据库与媒体不是源码，不入 Git；本次规划核对哈希保存在工作区 `workenv/ha-video-plan/source-hashes.json`，不是未来板端迁移清单。

源码证据：[gallery 持久化与挂载保护](../../repos/FPAI30TAI图像FPGA/yuanma/submission/reference_release/app/persistent_gallery.py#L48)、[现有图库迁移校验](../../repos/FPAI30TAI图像FPGA/yuanma/submission/reference_release/app/migrate_gallery.py#L22)、[历史库事务](../../repos/FPAI30TAI图像FPGA/yuanma/submission/source/fpga_project/model_backend/face_history/store.py#L36)、[录像文件协议](../../repos/FPAI30TAI图像FPGA/yuanma/submission/reference_release/recorder/recording_service.py#L78)。

## 迁移流程

### 只读预演

1. 分清开发树、视频 reference_release、实际启动文件和 lang 安装包。查实际启动命令及模型指纹，不凭目录名推断现役版本。
2. 探测目标数据盘 UUID、ext4、可用字节、inode、读写权限和 SQLite 能力。保留旧数据、候选库、导出与备份共存所需空间；空间不足时停止，不能通过删除旧库或录像为迁移腾位。
3. 从已应用配置、旧文件和服务参数生成设置来源报告。CLI 默认 auto 与冻结 unit 的 off 不可混同；没有持久化证据的运行值标 uncertain，不自行当用户偏好导入。
4. 两套声纹读取器只解析、不加载模型。保留单向量／多样本来源与匹配方法；坏 JSON 报错并保全原件，禁止按空库处理后覆盖。
5. 生成身份映射与冲突表：同名跨库、多对一、重名、旧 UUID 冲突、缺模型、缺媒体等逐条定位。不会因名字相同自动合并。

### 候选库导入

在隔离 staging 创建候选库，带 migration_id 与 schema 版本；源资料不改、不覆盖既有目标。每个源记录的唯一迁移键包含 source_store_id、旧 key 和源内容摘要；重复运行完全相同则跳过，内容不同则冲突，不静默覆盖。

顺序为模型／pipeline 与存储根 → 人员及旧 ID 映射 → 媒体目录 → 登记样本 → 设备实体与设置 → 录像状态 → 历史关联和事件引用。可以分批短事务，整批迁移状态单独记录；中断后按已提交批次恢复，不假设所有批次一起回滚。

登记样本保留原维度与精度，不经历史库 FP32 编码器强制重算。未知模型或不合法向量导入隔离记录和异常报告，不能成为 active 模板。旧人员原图可能只有一份，后续多样本没有各自原图；缺失引用如实登记，不能根据照片文件名伪造磁盘路径。

历史库保留 source_id、sequence、face_index、质量 policy 和向量原值，旧整数 row ID 另存映射，不能用作 person_id。原模块满库拒写且不自动淘汰；新保留策略未显式设置前维持原语义。新增 event_id 等字段采用 schema 迁移，不直接重编号或改写旧 URI 来躲唯一约束。

### 离线核对

必须输出机器可读报告，至少包括：

- 每种人员、样本、模型、设备、录像和状态的源／目标计数，孤立与冲突记录清单；异常全部有归属，无静默漏项。
- person/sample 旧 ID 的保留或完整映射，重名与跨模态关联的确认状态；改名后模板仍引用相同 person_id。
- 每个向量形状、有限值、归一化及编码 round-trip；旧聚合中心和目标中心的误差、余弦、原阈值附近判定对照。第一轮优先保持原算法，不把多样本 max 改成均值当作存储迁移的一部分。
- 媒体原字节、SHA 和引用可达性；仅在复制后内容相同但 mtime 变化的情况下，明确重建压缩校验状态，不能无条件信任旧 size/mtime 缓存。
- SQLite integrity_check、foreign_key_check；导出 schema、哈希、模板与引擎加载对照。模型加载测试与实际推理另标证据等级。
- 声纹的模型、预处理、单／多样本判决和阈值分别记录；历史少量样本不算安全标定。

### 增量与最终快照

预演时可以读一致性旧快照；最终切换必须短暂停止登记、资料修改、录像配置变更及其他旧写入，并正常封闭在途媒体。记录最终源 revision、哈希与队列排空回执，应用快照后的增量，再复核候选库。若源变了又无法获取完整增量，重做候选，不能强行切换。

不启用新旧双写主库。正式实现可以用影子只读对比，但所有业务修改在任一时刻只能有一个权威入口。切换前未受兼容适配的旧页面写入口必须冻结或退役，否则会分叉。

## 文件与数据库的一致性

SQLite 事务只保护库内数据，不能覆盖文件系统、另一个 WAL 数据库或设备动作。以下为必须可恢复的领域状态机。

| 操作 | 提交顺序与故障恢复 |
|---|---|
| 新登记／快照媒体 | 分配 operation_id，在受控根写临时文件并验证／fsync → 同文件系统原子改名并 fsync 目录 → 事务提交 media 与模板关系 → 记录完成。崩溃留下的无引用文件按 operation_id 隔离对账，不能启动即清整个 originals |
| 录像封段 | recorder 继续写 part、帧索引、remux ready、fsync 和最终文件发布；文件齐备且验证后提交目录 complete。回执重复按 recording_id／operation_id 去重；库不可用时保留已发布文件与有界本地回执，不把缺媒体的行标 complete |
| 软删除／恢复 | 事务保存意图与 outbox → recorder 验证状态并落可恢复回执 → 主库确认 applied。软删媒体仍占配额；恢复不得用于 purging |
| 永久清理 | 先持久化 purging 决定 → recorder 禁止新 reader 并等待现有 reader 释放 → 逐文件删除和 fsync／进度回执 → 目录墓碑。崩溃后继续已提交 purge，不将半删录像重新开放恢复 |
| 双库历史关联 | 历史 writer 与业务事件各自事务，使用 event_id 对账；缺历史标 pending/dropped。登记模板在业务库，历史库写失败不得改变身份 active 模板 |
| 配置应用／命令 | 主库保存 desired／命令和 outbox → 域服务按 operation_id 应用并核对 → 回执更新 applied／结果。失联时 unknown，查询真实状态后处理 |

历史回执是**有界、可重放的故障日志**，数据库恢复后确认消费并按保留规则处理；它不是可编辑的第二业务主库，也不成为“长期先留 JSON”的替代路径。

回执容量与动作准入一起管理：为正在封闭的一段录像及故障回执预留空间，给未确认条数／字节设硬上限。达到高水位先停止接收新持久操作，recorder 在预留空间内封闭当前段并暂停新录制；普通采集、预览和在线语音继续。达到硬上限或预留盘也不可写时，明确报告 recording／persistence unavailable，保留已存在媒体及回执，不覆盖旧回执、不无界增长、不以成功回应新登记／拍照。磁盘确已耗尽而无法完整封段时保留 part 与失败状态，不能宣称 complete。主库恢复后先对账和补录，再解除暂停，不自动承诺无限离线录像。

设置／模板应用的不同 operation_id 仍须按世代与 revision 防乱序；幂等只解决重复请求，不能防旧版本覆盖新值。域适配器持久保存已接受／已应用版本，主库丢弃迟到旧 ACK 的覆盖，规则见 [[联合人员与业务数据设计#设置的期望值与实际生效|联合人员与业务数据设计——设置的期望值与实际生效]]。

媒体路径以 storage_root_id＋受控相对路径保存，拒绝越界和符号链接逃逸；资料服务不能根据用户任意路径 unlink。实际永久删除始终由拥有媒体生命周期的 recorder／媒体模块执行。对账仅处置明确属于自身目录、能证明归属的产物；未知文件列清单而非删除。

## 录像迁移不变量

1. 原录制预缓冲、分段、帧新鲜度、容量上限和磁盘预留继续有效；回收站、part、索引和压缩副本均计入预算，不能以数据库索引替代磁盘真实字节核算。
2. 旧 soft delete 仅写 marker、不挪媒体；迁移必须保留 deleted_at 和 purging，避免旧录像复活。新库成为目录权威后，旧 marker 只能是经版本标记的兼容回执，不能双方各改一份状态。
3. MJPEG 的 offset/length 与 H.264 重封装后的源片段采集时间索引不是同一种寻址。保留 format、index_format、timestamp_basis 与 source frame 范围，回放交给原读取模块。
4. 原图、原录像不因压缩副本生成就移除；源文件／压缩 profile 校验和“验证后更小才发布”规则保留。
5. 原保留策略以 received_unix 等字段老化，captured_at 是同 boot/session 单调时间，历史 pts_ms 是媒体位置。导入保留原语义并显式记录转换；没有时区信息不能假装 UTC。新计划采用明确 IANA 时区。
6. 未完成 part／ready 不导成 complete；本次任务不清理它们。后续恢复只能根据可验证文件协议处理，保留错误证据。

## 切换与回滚

最终切换记录 cutover_id、源摘要、数据库 generation、schema、模型／模板 revision、导出 revision、软件清单和媒体根。切换前验证数据挂载与权限、备份可恢复，原子更新服务引用，启动后依次校验资料、导出消费者、视频和语言动作。

旧 JSON／设置文件变成只读备份或明确版本的导出，旧写入 API 关闭。状态页显示主库 store_id 与 active generation，防止换目录后读到空库却继续服务。

回滚分两种：

- **切换后尚无新业务写入**：停止候选服务，核对 generation 与记录，恢复成套旧配置、文件和服务，验证原接口。不靠重启硬件或清隔离标记回滚资料。
- **已经有新写入**：优先修复前滚；若必须退回，冻结写入并执行有测试的反向转换，或选择兼容旧程序的有版本导出。无法表示的新增身份／状态必须报出，不能直接拿切换前快照覆盖新登记。纯回退程序也必须确认支持当前 schema；未知新 schema 拒绝写。

软件、数据库、导出和媒体引用必须成套恢复。schema 升级不默认支持降级；每个发布说明列兼容矩阵和可行回退，且在候选副本演练。

## 备份与灾后恢复

业务主库使用 SQLite 在线 backup API 或停写后的一致性快照；活动库只复制 `.sqlite3` 会漏 WAL 提交，禁止作为备份方法。历史库同样处理，各备份写入 generation、游标和完整性结果；多库在线备份不假定同一瞬间，按事件游标恢复对账。需要严格关联点时停写两库取得成套快照。

媒体备份使用固定清单：数据库快照中的已发布媒体集合对应文件哈希，备份期间文件删除／变更需要 pin 或短时暂停相关处置。仅有数据库没有原媒体的备份不得叫完整恢复包。大媒体按容量策略另存，但缺失必须显式标出。凭据单独按权限备份，不输出进普通审计包。

恢复先验证存储 UUID／路径 → 恢复候选库与媒体 → integrity/foreign_key → 文件清单与模板兼容性 → 按恢复世代对账回执／outbox → 生成新导出 → 分域恢复服务。未核实的数据进入只读诊断，不自动重建空库、自动合并身份或自动授权。

从旧备份恢复不同于同代进程重启：旧库里的 accepted／pending 动作可能早已在备份后执行。恢复默认暂停所有执行型 outbox、计划和确认会话，分配新的 restore_epoch／fencing token；旧 worker、租约和迟到执行回执不能推进新世代状态。资料导出等无外部副作用投影可重新生成；执行型操作须先核对域服务持久回执和真实状态，不能证明未执行的转 unknown，重新检查 deadline、操作者权限及确认后才可恢复。不得直接重放旧“待执行”记录造成重复删除或重启。

recorder 已在外部持久提交的 purging 等领域状态有独立证据。旧业务备份不得将它降为普通回收站或开放恢复；先隔离对应对象、核对原操作编号和文件集，再由 recorder 按原已提交决定续处置或人工修复。新恢复世代的回执关联保留旧 operation_id 作为证据，而不授权旧进程继续发新命令。

运行时数据有其保留政策；工作区 `workenv/` 的本次规划脚本和日志按仓规永久保留，不能把运行时媒体清理规则套到工作区。
