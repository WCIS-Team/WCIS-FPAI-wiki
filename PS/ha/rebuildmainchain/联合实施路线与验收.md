# 联合实施路线与验收

## 实施顺序与依赖

本页是联合规划的工作包与通过条件，不是第二份进度总账。编号是本页工作包序号，不新开全库任务卡；实际开工时按 [[任务卡与台账规范#1. 任务卡模板|任务卡与台账规范——1. 任务卡模板]] 落卡并映射既有卡，确需新增范围时先登记决策和分母变化。总进度仍只看 [[进度计算与实时看板#3.1 任务卡总账（唯一进度真值，一行一卡）|进度计算与实时看板——3.1 任务卡总账]]。

**关键路径：版本与安全基线 → 数据契约和主库 → 旧资料离线迁移 → 单一写入口切换 → 统一控制与视频 → 语音闭环 → 联合发布与恢复演练。** 不先发布新的 JSON 主存储再安排另一期迁库。

## 第一轮用户场景

| 场景 | 贯穿链路与成功条件 |
|---|---|
| 登记同一人 | 创建 person_id → 明确选此人登记人脸／声纹 → 两种模板显示在同一资料页 → 重启后仍关联；不同人同名不合并 |
| 看看是谁 | 音频／文本 → 统一命令 → 当前帧识别 → 展示对应画面与姓名／未知 → 播报实际结果，事件关联请求和帧 |
| 拍照存档 | 同一动作保存媒体 → SQLite 目录可查 → UI 缩略图／下载 → 重试同幂等键不重复存图 |
| 开始／自动／停止录制 | 语音和按钮均控制 recorder，回读模式与实际录制分别显示；等待画面时不假报正在录 |
| 查今天录像 | 按明确设备时区筛选 → 选择 recording_id 回放 → Range／拖动正常；单调采集时间不能直接当日历日期 |
| 修改人员和设置 | 改名 person_id 不变；删除模板立刻撤销新请求可用集合；多键设置整体成功或整体拒绝，页面可见 applied 状态 |
| 连续视频中处理语音 | 直播＋录像运行时发语音请求；视频 owner 不被重开，不因主库事务或语音全局锁停采 |

第一轮目标为这些完整场景。复杂 OCR/VLM、任意家居自动化或真实门锁不作为补齐资料层的隐含工作；以后接入同一个动作和事件体系。

## 联合验收矩阵

下列数字是**拟定的最低测试规模或预算门槛，尚无板端测量结论**。不据它们宣称当前系统已通过，也不替代原全项目 S1～S5／DoD。

| 编号 | 测试与规模 | 通过条件 |
|---|---|---|
| 验收01 | schema、FK、revision 与并发：2 个客户端各 100 次更新同一对象 | 无丢更新；冲突明确返回；审计和资料在同事务；未知 schema 拒写 |
| 验收02 | 两套声纹＋人脸 schema 2＋历史库迁移，含重复、同名、坏 JSON、缺图／缺模型 | 源不变；计数／映射可对账；异常隔离；不自动置空或错合并；重复执行无新增重复 |
| 验收03 | 向量精度和模板等价 | 所有迁移样本维度／finite／模型合规；同编码 round-trip 一致；FP32 转换如改变临界判定则保留 FP64，不放宽阈值过关 |
| 验收04 | 同主体与新鲜度：A脸+B声、旧帧回放、跨会话、多人、PAD未标定 | 均不得产生安全放行；不把未知或跳过标成功；原风险18不因本次测试自动关闭 |
| 验收05 | 命令语义：不少于30条正向、否定、引用、询问、复合与取消用例 | 预期动作与不动作100%对照；“不要重启系统”不重启；危险动作需绑定确认 |
| 验收06 | 三种入口调用同一动作：按钮、文本、语音 | 使用相同 action/参数/权限/结果语义；不能依赖绕过执行器的专用捷径 |
| 验收07 | 幂等与未知结果：每动作至少10次重复请求，注入回执丢失／超时 | 可重复安全动作不多执行；非幂等未知先查询，不盲目重试；同键异参409 |
| 验收08 | 文件协议每个持久化边界注入进程崩溃，每边界至少3次 | 无缺媒体complete、无半删恢复、回收站不复活；待提交产物可对账；原数据保全 |
| 验收09 | 数据盘缺失／错误UUID／只读／磁盘满、历史队列满，以及主库离线直到本地媒体回执满 | 不建SD空主库；关键写失败可见；回执不覆盖，按预留空间封段并暂停新持久操作；历史降载有计数；采集／预览／普通语音不被锁住 |
| 验收10 | 媒体：预览、会话切换、MP4 Range、回收站／恢复／purge与活动reader | 沿用原codec／索引；purge遵守reader；无第二owner；配额含回收站与残件 |
| 验收11 | 设置、导出与缓存故障：导出失败、消费者离线后撤销人员、两个UI改同值、应用与ACK乱序及重启后旧版本迟到 | source revision可追溯；current／applied不倒退；旧JSON不反灌；删除显示待同步；最终授权必须核权威世代和撤销版本，断连旧缓存不能放行 |
| 验收12 | 事件与计划：重连、重复、墙钟回拨、重启跨boot、错过到期 | 事件ID不重复执动作；不跨boot比较单调时钟；missed_policy可复述；lease过期可核查恢复 |
| 验收13 | 备份／恢复／升级：空机导入、覆盖安装、失败升级、已有新写后的回退，以及备份后已执行动作和旧worker迟到 | 两库／媒体／导出／软件版本配套；新资料不被旧快照覆盖；新世代隔离旧租约，旧pending不重复执行，领域purging不降级 |
| 验收14 | 真实音频与显示 | 真麦→动作→真喇叭，网络故障与打断分别验；浏览器播放、文件模拟、PNG预演不替代HDMI/鼠标实测 |
| 验收15 | 整机资源：固定同负载对照＋至少2小时并行冒烟，最终至少8小时 | 无OOM/异常重启、无新增owner/内存持续爬升/库无限增长；视频帧新鲜度与录像连续性达冻结目标 |

资源测试分时点进行：阶段1记录同版本视频单独运行与加入现有语音的基线；阶段3形成资料层后，再加入SQLite写入负载做对照。记录CPU、各进程 RSS/PSS、MemAvailable、CMA、I/O、数据库／WAL增长、写入排队、预览新鲜度和录像缺口。阶段3完成后冻结数据库 cache／队列／额外常驻内存预算，阶段8前冻结各动作 p50/p95 和视频允许退化目标；没有基线和预算不得进入最终通过。目标数字由实测确定并登记，不能事后为通过放宽。

2小时是早期定位问题的最低冒烟窗口，8小时是本联合发布的最低建议长稳窗口；原任务卡要求更长时取更严格者。SQLite metadata 测试与模型装载、推理、云往返分别计时，不能把纯SQL延迟称整机响应。

## 部署与回退交付物

- 发布 manifest 包含 HA／lang／视频版本、架构、schema兼容区间、动作协议、模型／pipeline／模板格式、导出 schema 与数据 generation。
- 目标 Ubuntu20.04 arm64 的包安装、服务用户、数据盘挂载依赖、目录权限及正常关闭超时有可复跑检查。主库路径必须在服务可写范围内，不能误把数据库写入程序目录；YAML 默认与 secret 保持单独权限。
- 持续复用程序、配置、状态、模型的分离布局。安装脚本仅初始化缺失默认值，升级不覆盖 SQLite 用户设置，不自动暖启全部本地模型，不为共享运行时再开多份常驻模型。
- systemd argv 与实际 --help、内部 import／服务调用合同一并测试；现有 executor 的 --serve 参数与 speak 依赖漂移列入阶段1核对，不能只用 unit syntax通过作为可运行证明。
- 正常停止排空命令／历史写入／媒体回执，保留视频 owner 的关闭规则。控制服务恢复不清硬件隔离标记，资料迁移不改 BOOT、引脚和时序数据库。
- 回滚包必须配合 [[联合存储迁移与恢复方案#切换与回滚|联合存储迁移与恢复方案——切换与回滚]]，不能只恢复代码忽略数据库schema或新登记。

## 启动实施前的具体输入

先完成版本与存量只读 plan，输出目标服务清单、数据源及模型映射、候选 schema、迁移异常清单、原有视频性能基线和拟定维护窗口。输入齐备后即可从工作包2／3推进；身份冲突只阻塞冲突记录的激活，不阻塞无冲突 schema／接口开发。

本次已确定 SQLite 方向和联合规划，不把细节待实测等同于要重新询问是否采用 SQLite。正式写运行资料、切换服务和发布按当次实施授权执行；当前只交付文档，不因总规划自动上板。
