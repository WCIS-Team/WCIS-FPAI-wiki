## wheel 构建

⚠ Python 3.14 的 venv **默认不带 setuptools**，`--no-build-isolation` 会报
`BackendUnavailable: Cannot import 'setuptools.build_meta'`；开隔离在慢网下又卡
`Installing build dependencies`。正解是先把纯 Python 的 setuptools/wheel 放进 venv 再关隔离：

```bash
python -m venv /tmp/v && /tmp/v/bin/pip install setuptools wheel
/tmp/v/bin/pip wheel --no-deps --no-build-isolation -w /tmp/out .
```

## deb 构建

```bash
# 依赖 dpkg-deb 的容器里
sh workenv/ha-small/build_deb.sh    # 输出 ha-small_0.1.0_all.deb
```

内含：wheel + `requirements-voice.txt`（pymicro-vad/pyspeex-noise 预编译轮）+ `/etc/ha-small` 配置
（conffiles）+ `/usr/bin/ha-small` 启动器 + `ha-small-setup`（自动挑 Python≥3.14，支持
`HA_SMALL_WHEELHOUSE` 离线装）+ systemd unit。

### 离线安装（目标机）

```bash
dpkg -i ha-small_0.1.0_all.deb
HA_SMALL_WHEELHOUSE=/path/to/wheels ha-small-setup
systemctl enable --now ha-small     # 或直接 ha-small
```

### wheelhouse 必须包含

- 全部运行时依赖轮
- `setuptools` + `wheel`（`PyRIC` 是唯一 sdist，构建隔离要用它们）
- 预编译 `pymicro_vad` / `pyspeex_noise`（`assist_pipeline` 运行时要装，现场编译需 g++/cmake/libspeexdsp）

## 三个必踩的坑

1. **旧实例不杀 → 新实例被单实例锁拒绝**，表现为前端 404。HA 的提示是
   `Please stop the existing instance before starting a new one`。
2. **只装 wheel 不够**：`assist_pipeline` 还要求 `pyspeex-noise`/`pymicro-vad`，缺了就
   `Setup failed for 'assist_pipeline'`，进而 `assist_satellite` 也失败。
3. **`Depends: python3.14` 现在没有发行版能满足**（Debian 13=3.13、Ubuntu 24.04=3.12、板端=3.8）。
   deb 能装（`--force-depends`）但只有装了 Python 3.14 的机器才跑得起来。
