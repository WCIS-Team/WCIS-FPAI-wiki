# 01-来源与基线

## 怎么取源

官方 PyPI sdist（非 archive 复制、非 fork）：

```
https://pypi.org/project/homeassistant/2026.10.4/
sha256 = 8410fecb434ab94b3f7724cd80584050f0ceeb856c16ee70202c24037d62238a（235,925,308 B）
```

下载后先 `sha256sum` 核对与 PyPI 元数据一致，再解包到容器 `/upstream/`。

## 为什么不走 HA4FPAI archive

archive 是另一条线的快照，里面混着 HA4FPAI 自己的 `control/`/`lang/`/`klar/` 栈。ha-small 的定位是**从官方源裁出可独立运行的同类物**，所以基线必须是干净的官方 sdist——这也是后续逐文件 SHA256 审计能成立的前提（对照物只有上游）。

## 基线的硬前提

- **Python ≥3.14.2**：上游 `Requires-Python` 写死；裁文件不会降低它，也不为演示删版本门禁
- **容器内构建**：本机 Linux 容器（python:3.14-slim），不污染系统 Python
- **裁剪原则**：先删除；保留文件按上游哈希核对；只有实际运行证明确实无法靠恢复必要依赖解决时才考虑补丁（至本轮为止补丁数为 0）

## 复现

```bash
# 容器内
python -m venv /venv && /venv/bin/pip install /path/to/cut-tree
/venv/bin/pip check
/venv/bin/hass --script check_config -c /cfg
```

判据：`pip check` 无冲突、`check_config` exit=0 且**正文无** `Integration error/not found/ImportError/Invalid config/Setup failed`（见 [[02-依赖闭包与三轮试删教训]] 的严格判据）。
