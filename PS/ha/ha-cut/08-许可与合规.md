# 08-许可与合规

## 结论

**ha-small 继承 Home Assistant Core 的开源许可：Apache License 2.0（`Apache-2.0`）。**
删除式裁剪**不改变许可**——ha-small 只是上游的一个子集，不是“修改文件”，因此不需要逐文件加变更声明。

## Apache-2.0 的义务与我们的满足情况

| 义务（条款） | 要求 | ha-small 状态 |
|---|---|---|
| 随分发附许可副本（§4(a)） | 分发时带上 LICENSE | ✅ `LICENSE.md` 逐字节保留；wheel 经 `license-files=["LICENSE*"]` 自动打包 |
| 修改文件需显著标注（§4(b)） | 改过的文件要标“已修改” | ✅ **改了 0 个文件**（`modified_upstream_files: 0`，源审计实测），条款不触发 |
| 保留版权与归属声明（§4(c)(d)） | 不得移除版权/归属 | ✅ LICENSE.md + pyproject 元数据完整保留 |
| 商标不授权（§6） | 许可不授予商标权 | ⚠️ **必须自守**：“Home Assistant” 是 **Nabu Casa** 注册商标，不得宣称官方版、不得用其 logo 做宣传 |

## 删文件是否违反 Apache-2.0

**不违反。** Apache-2.0 不要求保留原作品的**全部文件**；分发一个“去掉了若干模块”的子集是被允许的，
前提是：① 保留 LICENSE 与归属；② 若改了保留文件才需标注（我们没改）。
所以 `128 → 117` 的纯删除裁剪在许可上完全成立。

## 分发时的合规清单

打 wheel / deb / 源码包时逐条核对：

- [ ] `LICENSE.md` 打进了包里（wheel: `license-files` 已覆盖；deb: 打包脚本确认含 LICENSE）
- [ ] 对外分发附一句来源声明，例如：
      `ha-small — derived from Home Assistant Core 2026.10.4 (Apache-2.0)`
- [ ] 不使用 “Home Assistant” 官方 logo / 图标 / 官方名义
- [ ] 自命名为 **ha-small**（本项目已如此），不冒称 “Home Assistant”
- [ ] 若曾修改任何保留文件（当前为 0）：在改动文件头部加 `# Modified by ha-small: <说明>`

## 与裁剪原则的关系

- **零补丁原则**（见 [[02-依赖闭包与三轮试删教训]]）不仅省维护成本，也直接简化许可负担：
  只要“只删不改”，Apache-2.0 的 §4(b) 变更标注义务就永不触发
- 源审计（`cut/verify_source.py` → `modified_upstream_files: 0`）是这条合规结论的**机器判据**，
  每次裁剪后跑一遍即可复核“确实没改上游”这件事
