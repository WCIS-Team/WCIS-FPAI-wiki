# 09-裁剪后设计总览

综合 wiki 记录与源码实测，对「裁剪后的 ha-small」做一次整体设计梳理。逐步骤的证据与规程见 01~08 各页；本页只做**总览与取舍判断**（判据以各页为准，不复制其表格）。

> **口径**：本页只讲 **ha-small 切片**（HA4FPAI 的 `ha/` 子项目）。**整机**（control/lang/klar/视频域/boards…）的总览在 [[HA4FPAI-设计总览]]，两页互链、不重复。

## 〇、定位与边界

- **在整机中的位置**：ha-small 是 HA4FPAI 的 **`ha/` 子项目**——把 Home Assistant Core 裁成一个可独立运行的子集，用于补齐「**对话代理 + 意图执行器 + 实体表 + 状态查询**」那一层的可替换实现。
- **不是 Home Assistant 的替代**：它是 HA 官方代码的**删除式子集**（同类物），不是重写、不是 fork 改造。
- **不是整机**：整机的业务权威（control SQLite 业务库）、语音十级链（lang）、NLU（klar）、视频视觉链、boards 门禁都**不在** ha-small 范围内——见 [[HA4FPAI-设计总览]] §二/§七。
- **运行位置**：HA 跑在**本机/容器**（Python ≥3.14.2）；**板端只出流**（板端 Python 3.8 装不了，见 §九）。

## 一、裁剪哲学

- **不是 fork，是子集**：从官方 Home Assistant Core **2026.10.4** 的 sdist（sha256 `8410fecb…`）出发，**只删不改**
- **逐字节可验**：保留的 5557 个 `homeassistant/` 文件全部有 SHA256 审计（`cut/source-audit.json`），`modified_upstream_files = 0`
- **零补丁**：删到依赖闭包固定点为止，绝不打补丁改造（因此也免除了 Apache-2.0 §4(b) 的变更标注义务，见 [[08-许可与合规]]）
- **安全取向**：减少集成数 = 减少攻击面与审计面；**裁剪从不为省磁盘/内存**（见 §七）

## 二、架构对比

```
Home Assistant Core 2026.10.4 : 128 integrations / 6096 上游文件
        │  删除 11 个叶子（无任何依赖方）
        ▼
ha-small v0.1.0              : 117 integrations / 5557 上游文件（-539，-8.8%）
```

**删掉的 11 个叶子**：`ai_task, air_quality, calendar, geo_location, local_file, radio_frequency, schedule, switch_as_x, todo, command_line, shell_command`

**保留的核心支柱**（被其他集成引用 / 提供已验收功能）：
`generic`（摄像头/RTSP/HLS）、`mqtt`、`rest`、`rest_command`、`counter`、`wyoming`（TTS）

三条裁剪规则与收敛过程见 [[02-依赖闭包与三轮试删教训]]。

## 三、ha-small 内部结构（子系统地图）

```
ha-small（= HA4FPAI 的 ha/ 子项目，orphan 分支 ha-small）
├── homeassistant/           # HA 核心包（本页主体）
│   ├── components/          # 117 个保留集成（generic/mqtt/rest/camera/...）
│   ├── bootstrap.py         # 集成预加载名单（裁剪规则③的判据来源）
│   └── backports/           # 移植自 CPython（PSF 许可）
├── cut/                     # 裁剪工具链与证据（verify_source/next01_removable_v3/各探针 + results/）
├── examples/                # 可直接跑的 configuration.yaml / automations / board-readonly.yaml
├── ha-cut.md                # 逐项勾选正本（52 已勾 / 6 待办）
└── UPSTREAM.md / LICENSE.md / pyproject.toml
```

与整机其他子系统的区别：ha-small 只覆盖 HA 这一层；视频域三 C++ 进程、control 业务库、klar、npuserv 都在**板端/整机**，ha-small 通过 HTTP 只读消费它们（见 §四）。

## 四、跨机部署与接口边界（核心设计点）

**为什么 HA 不在板上跑**：HA Core 基线要求 **Python ≥3.14.2**，而板端 FMQL30TAI676H 只有 **Python 3.8.10 / 993MB RAM**——跑不了。所以架构是：

```
[板端 192.168.1.113]                         [本机/容器 ha-small]
SDI→PL→PS→VPU(H264)
  vpu_live_server(8092 /api/status, /h264/manifest.json  fMP4 分片)
  serve_photos  (8091 /api/camera/h264/live.mp4?session=)
        │  只读 GET
        ▼
  board_hls_bridge (ffmpeg 拉 live.mp4 → 重封装滚动 m3u8)
        │
        ▼
                                 HA generic camera(stream_source=bridge m3u8) → 前端 <video> 960×540
板端 recording_service(8093 /api/status · /api/recordings · /api/mode[POST])
        │  只读 GET（mode POST 仅 guard 保护时用）
        ▼
                                 HA rest 只读传感器（recorder mode/state/counts）
                                 board_mqtt_adapter（GET 后重发布为 MQTT 设备，持自身客户端证书）
                                  → HA mqtt 自动发现（7 传感器 + 1 事件 + 设备 + LWT）
```

**接口边界规则**（贯穿 ha-small 部署）：
- **板端拥有 camera/SDK/DMA/VPU 唯一所有权**；HA 侧只经 HTTP 域接口（8091/8092/8093）**只读消费**
- **板端零代码改动**：adapter/bridge 都是**本机外部进程**，不改板端任何服务（“转接而不是真改”）
- **写操作仅一处且受保护**：`POST /api/mode` 只用于录像磁盘守护（10GB 阈值），其余全只读
- **优雅降级**：token 30 分钟过期需刷新；bridge 需先杀旧进程再起（旧 ffmpeg 占口会使分片冻结）

## 七、关键取舍：裁剪省的是什么，不省什么

**这是本项目最需要说清的设计判断**（实测见 [[07-运行时内存RSS实测]]）：

| 维度 | 裁剪前→后 | 结论 |
|---|---|---|
| **攻击面 / 集成数** | 128 → 117 | ✅ 真收益：少 11 个入口、少 11 份待审代码 |
| **静态代码 / 认知负担** | 6096 → 5557 文件（-539，-8.8%） | ✅ 真收益：待读代码少近 9% |
| **磁盘（venv）** | ~759 MB → ~759 MB | ❌ 几乎不变：大头是 hass_frontend 269MB + av 127MB + numpy 60MB，与集成数无关 |
| **运行时 RSS** | 253.3 MB → 253.3 MB | ❌ 不变：删的叶子本就不在 config、从不 import，RSS 贡献≈0 |

**机制**：运行时内存是「**加载了什么**」（configuration.yaml 决定）的函数，不是「**盘上有什么**」（代码树）的函数。删死代码省磁盘与攻击面，不省 RSS。想省 RSS 要关功能（config 层）；想省磁盘要动 wheel（依赖层）——两者都不在“删集成”这个杠杆上。

## 八、现状实测（本机容器 ha-small-dev，2026-11-08）

- **HA 主进程 RSS 253.3 MB** + ffmpeg 子进程 60 MB（2 流）= **~313 MB**（全功能实验室配置）
- **venv 站点包 759 MB**：hass_frontend 269 / av.libs 101 / homeassistant 73 / numpy+libs 60 / botocore 31 …
- **集成 117 / 上游文件 5557 / 修改 0**
- 逐项内存构成与测量方法见 [[07-运行时内存RSS实测]]；**整机**（服务本体 18MB、qwen3 +290MB、视频链 157MB）见 [[HA4FPAI-运行时内存RSS实测]]

## 九、边界（必须与结论同读）

- **Python ≥3.14.2**：板端仅 3.8，装不了 → HA 跑本机/容器，板端只出流（见 §四）
- **摄像头源当前未就绪**：短录 `received_frames` 不增（SDI→PL→PS 链路无 H264 输出），guard 未触发真实写入
- **mTLS CA 30 天**：实验室证书，生产需替换
- **商标**：Apache-2.0 不授商标权，“Home Assistant” 属 Nabu Casa，对外只能用自命名 ha-small（见 [[08-许可与合规]]）
