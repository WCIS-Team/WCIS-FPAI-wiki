# 02-依赖闭包与三轮试删教训

## 裁剪的三条规则（2026-11-07 定稿）

某集成可删必须**同时满足**：

1. **manifest 硬依赖**：没有任何*保留*集成的 `manifest.json` 的 `dependencies` 里出现它（`after_dependencies` 是软依赖，不算）
2. **跨行感知静态导入**：没有模块 `from ...components.X` / `from .components import ( ... X ... )` —— 必须先把括号多行导入折叠成一行再匹配，否则会漏（见坑 1）
3. **bootstrap 预导入**：不在 `homeassistant/bootstrap.py` 的预导入列表里（`search` 因在 bootstrap 的 `from .components import ( ... search as search_pre_import ... )` 而被保护）

判据来自 HA4FPAI 文档 §五与 2026-11-07 实测。

## 三轮试删与教训

| 轮次 | 做法 | 结论 | 教训 |
|---|---|---|---|
| v1 | 按行扫描导入 + 干净 venv | **错**：129→119（删了 `search`），30/30 却通过 | **坑 1**：漏了 `bootstrap.py` 的跨行括号导入，`search` 被误删；但 x86 容器里残留旧文件导致“假通过” |
| v2 | 修正扫描支持跨行 + 干净 venv | **错**：129→120（删了 9 个叶子），30/30 却通过 | **坑 2**：漏了 manifest `dependencies` 检查！HA 内置 `generic` 的 `dependencies` 包含 `map_tiles`，删掉后 HA 启动会 `ImportError`，但因为容器安装时覆盖了旧目录，实际没报错 |
| v3 | **三规则全量扫描整个树** | **对**：128 集成里 111 被锁、17 是叶子 → 裁掉真正无用的 11 个（`ai_task/air_quality/calendar/geo_location/local_file/radio_frequency/schedule/switch_as_x/todo/command_line/shell_command`） | ✅ clean venv + check_config(零错) + pip check + 30/30 全部通过 → **128→117** |

## 关键坑总结

- **镜像缓存污染**：`pip install --force-reinstall` 不会删除新版本不存在的文件，旧集成残留在 site-packages 会掩盖真实缺失；必须用全新 venv（`rm -rf /venv && python -m venv /venv`）
- **忽略 manifest dependencies**：不能只看导入，还要看其他集成的 `manifest.json` 有没有 `dependencies: ["X"]`，HA 有几十处硬依赖关系
- **bootstrap 预导入**：`bootstrap.py` 里 `from .components import ( ... )` 块里的名字必须预导，这些集成即使无导入也必须留
