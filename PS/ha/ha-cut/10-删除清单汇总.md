# 10-删除清单汇总

一页说清 **ha-small 到底删了什么**：分阶段、数量、以及"删了也能取回"的路径。**1400+ 个集成名不在本页逐个复制**（一个事实只写一处），完整清单指向机器可读文件。

> **口径提醒**：ha-small 集成数＝**117**（`homeassistant/components/` 下 117 个带 `manifest.json` 的目录；`ls` 看到的第 118 项是 `__init__.py` 文件，不是集成）。此前若干页误写 118，本页为准，已回改。

## 一、总账（Home Assistant Core 2026.10.4 → ha-small v0.1.0）

| 指标 | 上游 | 最终 | 删除 | 来源 |
|---|---|---|---|---|
| **集成目录** | 1523 | **117** | **1406** | `cut-report.json` `total_integrations` / `retained_integrations`(117) / `removed_integrations`(1406) |
| 被删集成目录内文件 | — | — | **49,026** | `cut-report.json` `removed_upstream_files` |
| 组件源代码体积 | 228.7 MB | **34.6 MB** | ~194 MB | `component_bytes` / `retained_component_bytes` |
| 修改的上游文件 | — | **0** | — | `modified_upstream_files: 0`，`patches: []` |

> 校验：117 + 1406 = 1523 ✓；逐字节审计见 `cut/source-audit.json`。

## 二、三个阶段（勾选史见 ha-small 分支根 `ha-cut.md`）

| 阶段 | 集成 从→到 | 删了什么 | 依据 |
|---|---|---|---|
| **A 首轮闭包** | 1523 → 129 | 不在「seed 74 项 ＋ 其依赖闭包」里的 **1394** 个集成 | `cut/next01_removable_v3.py`＋seed 清单 |
| **B 单点** | 129 → 128 | `plex`（**1** 个，干净 venv 验证） | `cut/results/plex-results.json` |
| **C 最后一公里** | 128 → 117 | **11** 个"无依赖叶子" | 全树三规则扫描 |
| **合计** | **1523 → 117** | **1394+1+11 = 1406** | — |

## 三、B/C 阶段逐一列出的 12 个（有独立论证的确定性删除）

- **B 阶段（1）**：`plex`
- **C 阶段（11 叶子）**：`ai_task`、`air_quality`、`calendar`、`geo_location`、`local_file`、`radio_frequency`、`schedule`、`switch_as_x`、`todo`、`command_line`、`shell_command`

**判定理由（三规则全满足才删）**：① 没有任何保留集成的 `manifest.dependencies` 引用它；② 没有跨行感知的静态导入引用它；③ 不在 `bootstrap.py` 预导入名单。详见 [[02-依赖闭包与三轮试删教训]]。

> A 阶段的 1394 个是按「seed 74 ＋ 依赖闭包」之外一律剔除，不逐个论证；名单同样在 `removed_integrations` 里。

## 四、完整清单在哪（不在此页复制 1400 个名字）

- **`cut/cut-report.json`** → `removed_integrations`（**1406 条**，字母序）、`retained_integrations`(117)、`seed_integrations`(74)、`reasons`、`closure_policy`
- **`cut/source-audit.json`** → 保留的每个文件 path/bytes/sha256（逐字节审计）
- **`ha-cut.md`**（ha-small 分支根）→ 逐项勾选史与判据

复现查询：
```bash
python -c "import json;print('\n'.join(json.load(open('cut/cut-report.json'))['removed_integrations']))" | wc -l   # 1406
```

## 五、最终保留的 117 是怎么算的

- 阶段 A 起点 = **seed 74 项**（HA 运行核心：`http/api/websocket_api/frontend/recorder/history/conversation/assist_pipeline/mqtt/rest/rest_command/generic/camera/stream/stt/tts/wyoming/…`，见 `cut-report.json` `seed_integrations`）**＋ 依赖闭包补集** = **129**
- 阶段 B 删 `plex` → 128；阶段 C 删 11 叶子 → **117**
- 权威清单 = `cut-report.json` 的 `retained_integrations`（117 项）；删其中任何一个都会断启动

> 注意：`seed_integrations`(74) 是**阶段 A 的起始种子**，其中 9 个叶子（air_quality/calendar/command_line/geo_location/local_file/radio_frequency/schedule/todo + …）在 C 阶段又被删了，故"117 ≠ seed 74 + 闭包"的简单等式不成立——以 `retained_integrations` 为准。

裁剪规则与收敛详见 [[02-依赖闭包与三轮试删教训]]；保留集成的设计定位见 [[09-裁剪后设计总览]]。

## 六、删了 ≠ 丢了：本地/远端可取回

| 媒介 | 位置 | 说明 |
|---|---|---|
| **容器纯净副本** | `ha-small-dev:/src-clean`（130 集成全在）、`/upstream/homeassistant-2026.10.4` | podman 容器内，容器删则失 |
| **git 历史** | commit **`d976fc0`**（129 全集，6158 上游文件）是 `origin/ha-small` 的祖先 | **远端可取回，durable**：`git show d976fc0:homeassistant/components/<name>/…` |
| **兜底** | 官方 sdist sha256 `8410fecb434ab94b3f7724cd80584050f0ceeb856c16ee70202c24037d62238a` | 从 PyPI 重下可还原整棵上游 |

## 七、边界

- **删的是「集成目录」**，不是上游全部文件；上游其它代码按需保留
- **零补丁**：`modified_upstream_files = 0`、`patches = []`，所以是**纯子集**而非 fork（许可解读见 [[08-许可与合规]]）
- **删集成不省磁盘/RSS**（只省攻击面与代码量）——见 [[07-运行时内存RSS实测]]
