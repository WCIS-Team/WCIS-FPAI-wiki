# 视觉链路：FPGA 统一视觉前端

视觉流水线是**主要 FPGA 核心**。目标（已确认长期决策，见 [[09-开发计划]]）：形成**多模型共享、可配置的视觉预处理加速器**，而不是为每个模型重复写一套专用前端。OCR 和人脸识别共享同一前端。

## 数据流

```
USB UVC 摄像头（V4L2 采集）→ PS 图像采集 → FPGA 统一视觉前端 → ┬ NPU 人脸／目标识别
                                                                ├ NPU OCR
                                                                └ 按需图像抓拍（供云端 VLM）
```

> OpenCV 用于采集、显示与调试，**不承担核心实时预处理**（已确认）。

## 模块设计

| 模块 | 职责 |
|---|---|
| video_stream_ctrl | 接收和调度视频数据流，处理 valid／ready 与背压 |
| video_frame_ctrl | 维护像素、行、帧边界和分辨率状态 |
| resize | 将摄像头分辨率转换为模型输入尺寸；先完成可验证版本（最近邻），再决定是否升级为双线性等更复杂实现 |
| crop／letterbox | 按目标模型要求裁剪、补边和生成 ROI |
| color_convert | 完成 RGB／BGR／YUV 等格式转换 |
| normalize_quantize | 完成归一化、定点化或 INT8 量化前处理 |
| buffer／line_buffer_ctrl | 组织行缓存与阶段间缓存；存储本体优先使用厂商 BRAM／FIFO IP |
| mode_router | 根据 CPU 配置在 FACE、OCR、VLM 等模式间切换处理参数和输出去向 |

跨链路的 config_regs／stream_router／status／top 见 [[02-系统架构]]「系统控制与集成」。

## 服务对象与目标尺寸

| 去向 | 模型（候选） | 说明 |
|---|---|---|
| 人脸／目标识别 | YOLOv8n、MobileFaceNet／ArcFace | 识别结果形成身份或目标事件，由 CPU 执行权限与业务逻辑 |
| OCR | CRNN（第一版）、PP-OCR Mobile（完整版） | 神经网络放 NPU，FPGA 只做其前端图像预处理 |
| 图像抓拍 | — | 按需抓拍单帧，PS 做 JPEG 压缩后发送云端多模态 VLM |

> **待验证**：摄像头实际输出格式、分辨率与帧率，以及人脸、OCR 和 VLM 路径各自需要的目标尺寸与颜色顺序（见 [[11-待验证清单]]）。

## 验证方法与推进顺序

- **验证方法**：与**软件 golden model 逐像素比较**（每个核心模块都应有可重复的验证方法）。
- **推进顺序（P0）**：建立软件参考结果 → 从小尺寸图像开始依次验证 frame control、crop／letterbox、色彩转换、normalize／quantize → 再进入 resize 和可配置 mode router。
- 性能测量（P1）：FPGA 相对 CPU 预处理的延迟、吞吐、CPU 占用、资源消耗和稳定性——视觉流水线必须成为能够测量这些指标的主要 FPGA 成果（已确认决策）。
