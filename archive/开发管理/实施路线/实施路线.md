## 四步的分工

| 步 | 干什么 | 明确不做 | 做完的标志 | 页面 |
|---|---|---|---|---|
| ① | 现成模型**原封不动**跑在 NPU 上 | 不量化调优、不改结构、不上 FPGA | 模型台账每个候选都有转换结论与（到板后）实测列 | [[1-NPU模型部署]] |
| ② | 其余环节先在 **CPU** 上实现，端到端跑通一条可用链 | 不追求性能，只追求跑通 + 可复现 + 有向量 | S1~S5 全绿，golden 向量与容限表齐备，打上 `baseline-v1` | [[2-CPU可用链]] |
| ③ | 组件**逐个**从 CPU 换写成 RTL | 不一次全换，不带 bug 合入 | 每个组件与基线逐样本比对通过，且有可一键切回 CPU 的开关 | [[3-FPGA组件下沉]] |
| ④ | NPU 跑不了的算子用 FPGA 硬算子补 | **不是预设必做项** | 仅在 ③ 中确认存在值得硬件化的瓶颈后启动 | [[算子缺口处理]] |

四步在看板与台账里的别名是任务卡号 **① = M1、② = M2/GOLD、③ = A1–A8、④ = A9**；`准备期 P0…P4` 与 `交付期 V/DEP/DOD` 是四步之外的地基与收尾。

**顺序不能换的原因**：② 冻结的黄金基线是 ③ 的**唯一裁判**——FPGA 版本对不对不靠感觉、不靠讨论，只比对基线输出。基线没冻结，下沉就没有判据。

**②与③可以并行的部分**：不等板卡的动作见 [[2-CPU可用链#6. 基线性能摸底（B8：给加速比准备分母）|2-CPU可用链——6. 基线性能摸底（B8：给加速比准备分母）]]（x86 上先建 golden model 与测试向量）。

## 推进纪律（两人作业的最小集合）

本项目**没有阶段门禁、没有重量级流程**，只保留下面这几条——它们是硬件在途时唯一能防止自我放宽的东西。

| 条 | 内容 | 违反的后果 |
|---|---|---|
| 铁律一 | **没有误差容限就不开工**：容限与黄金参考在同一步冻结 | 做出来的东西无法判断对不对 |
| 铁律二 | **没有运行时开关就不算完成**：CPU 通路必须永久保留、可一键切回 | FPGA 版本出问题时现场没有退路 |
| 拆分 | 每一步都显式切成"无板可做"与"必须等板"两半，⛔ 项必须出现在看板阻塞清单里 | 等板 → 全线停摆 → 后期压缩 |
| 条件通过 | 允许带着 ⛔ 项推进下一步，但**条件通过不改变任何卡的计数，也不降低完成判据** | 把"还没做"混成"做完了" |
| 证据 | 每个 ✅ 后必须带证据等级（E0–E6），只能逐级提升，不得跳级 | 答辩现场会崩 |

证据等级与状态标记的定义在 [[状态源与决策记录#2. 状态标记与证据阶梯|状态源与决策记录——2. 状态标记与证据阶梯]]。

### 无板可推进的子集

| 步 | 无板可做（现在就能推进） | 必须等板（标 ⛔ 并写解锁条件） |
|---|---|---|
| 环境 | 容器导入、工具链自检、`toolchain.cmake`、arm64 源可用性、CI 打通、x86 本机构建 | 板端烧写、串口/SSH/scp、板端 `import torch` |
| ① | iCraft 模型编译与算子支持验证（主机侧） | 板端 NPU 推理、精度/延迟实测 |
| ② | 在 x86 上用 CPU 参考实现建立 **golden model 与测试向量**、桩程序打通数据流、误差容限表定稿 | 板端端到端冒烟 |
| ③ | 定点化 CPU 仿真、RTL/HLS 实现、testbench 仿真与逐样本比对、综合与时序报告 | 上板性能测量、灰度长跑、运行时开关的板端回归 |
| 交付 | 交付包脚本、可追溯 tag 规则、文档 | 上板回滚演练 |

### 范围优先级与步骤的对应

`P0/P1/P2` 一律指**范围优先级**（做不做、先做哪个），不指步骤；指步骤写全名"第 ② 步"。

| 优先级 | 含义 |
|---|---|
| **P0** | 本周期必须交付，构成最小可答辩系统 |
| **P1** | 计划内后置，P0 未闭合前不得启动 |
| **P2** | 可选/条件项，只有在实测暴露瓶颈后才评估 |

| 优先级 | 内容 | 落在哪一步 |
|---|---|---|
| P0 | 1-entry 握手缓存 + 自检 TB | ③ 的前置地基（已完成 `✅(E3)`） |
| P0 | 厂商 FIFO／BRAM IP 的参数配置与流式接口应用 | ③ |
| P0 | 核对官方参考工程的 PS↔PL／DMA／时钟复位 | ③ 第②步（⛔ 等到板） |
| P0 | 视觉前端：frame ctrl → crop/letterbox → 色彩转换 → normalize/quantize → resize → mode_router | ③ 主线 |
| P0 | 音频前端：PCM 流控、分帧、VAD、缓存；SRC 条件性 | ③ 第二链路（同步推进） |
| P0 | 视觉前端接 NPU 人脸/目标，音频前端接 NPU ASR，形成第一版双链路闭环 | ②→③ |
| P1 | OCR 共享视觉前端，完善多模式配置与意图路由 | ③ 后段 |
| P1 | 测量 FPGA 相对 CPU 预处理的延迟、吞吐、CPU 占用、资源、稳定性 | ③ 第⑥步 + 交付 |
| P2 | 双线性 resize、流水线并行度、更复杂 VAD、其他后处理 | **不在本周期承诺**，实测瓶颈驱动 |
| P2 | CustomOP 自定义硬算子 | ④，条件项 |
| 范围外 | FPGA JPEG、FPGA TTS 后端、TOE 网络卸载 | 下版 backlog，见 [[状态源与决策记录#D-02 · 收缩 FPGA 下沉范围（本 Wiki 编制时消解的最大冲突）\|状态源与决策记录——D-02]] 决策 D-02 |
