## 四、10-19 出库：站点跟着主库走，代价是两处手工

文档库出库成子模块本身不是站点的事（那是 [[状态源与决策记录#D-63 · wiki 出库成子模块（WCIS-FPAI-wiki）、repos 远端改名跟进、站点日期改由两库合并取数|状态源与决策记录——D-63]]），但它逼着 CI 改了四处，每一处都留下代价：

- `actions/checkout` 要 `submodules: wiki` ＋ 一个能读两库的 `SUBMODULE_TOKEN`——**私有同账户库用默认 token 读不到**。
- 触发路径从 `wiki/**` 改成 `wiki` 这一个 gitlink ⇒ **页面提交不再自动发布，要发布就得回主库 bump 指针**。
- 日期要两库合并取数，否则 `modified` 冻在改造日。
- 实测到的红叉形状：`run 39196358140` 红在第 2 步 checkout 的 `Input required and not supplied: token`——secret 没建时那个表达式展开成空串，**在发出任何一次访问之前就失败**。那次加的保护步因此至今零执行。

这一节真正重要的是那第二条：它就是她 10-20 那句"不用我再手动更新"要消掉的东西。

## 六、10-20 防爬那一层

她那句话的范围是"不管是搜索引擎的还是 ai 的任何爬虫"。

- 10-20 · 三件一起做 · deny-all 的 robots.txt（再按名字点名一批抓取器）、每个 HTML 注入 `noindex` 那条 meta、删掉 `sitemap.xml` 等爬虫索引。**缺一件都不算**，而且这一步是硬门禁：注不进去就当场失败、不发布。
- 10-20 · 删 sitemap 的连带代价当场付 · 验收脚本原来靠线上 sitemap 枚举全站页源，sitemap 一删页数会静默变 0，看着像"全站没有图"。页源改成吃构建制品，只多要一个 run id。
- 10-20 · 强制边界要说清 · robots 与 meta 都是**请求不是强制**；GitHub Pages 这一层**没有给用户设 HTTP 头的口子**，发不出 `X-Robots-Tag`（Netlify 那种 `_headers` 文件在这里不生效）。
- 10-20 · 一处内在矛盾 · `noindex` 要靠爬虫真来抓那一次才生效，而 `Disallow: /` 恰好把这次抓取挡住 ⇒ 对新 URL 最优，对**已被收录的 URL 会滞留下线不掉**。
- 10-20 · 拿不到读数的地方 · "搜索引擎到底收录过没有"没有可用读数，只能说没有证据显示已收录，不能说未被收录。

正本：[[状态源与决策记录#D-67 · 全站禁止爬虫：deny-all robots.txt ＋ 每页 noindex ＋ 删掉 sitemap，Pages 这一层发不出 X-Robots-Tag|状态源与决策记录——D-67]]。

## 七、10-20 发布开关：极性反过来才成立

她先问的是"我是不是自己去 Pages 上开关就行"。这一条的价值全在开头那个前提纠正上。

- 10-20 · 前提纠正 · Settings → Pages 那个 **Unpublish 不是"关住"的开关**：官方原文写明一次成功的工作流运行就会重新创建部署 ⇒ 在第五节那套形态下它只顶到下一次成功构建为止。
- 10-20 · 闸加在部署那两步，取"不等于 false" · **不建变量＝照常发布**，开关只能被显式关掉。若写成"等于 true"，这笔改动本身就冻住站点，必须她先去网页上建变量——那正好违背她要的"不用我再手动"。
- 10-20 · 三档分清楚 · `PUBLISH=false`＝构建照跑、不部署、整笔仍绿、现有 URL 全 200；禁用工作流＝构建都不跑、分钟归零、手动触发一起失效；只有 Unpublish／改 Source／删库这三条会让现有链接变 404。
- 10-20 · 双向都验 · 变量不存在→发布、建 `false`→跳过、删掉→再发布，三笔作业；关闸期间四页 ETag 不动、字节一字未变。

正本：[[状态源与决策记录#D-68 · 发布开关：仓库变量 PUBLISH 只掐部署那一步，站点冻结在最后一次部署|状态源与决策记录——D-68]]。

## 八、10-21 剪正文、改根、剔除 agent.md

她这条指令给的理由是"给全部正文太大了要加载侧栏"——数是对的：正文占索引的九成以上，而且**每个 HTML 都要抓它一遍**。

- 10-21 · 上游没有"不写正文"的开关 · 所以只能构建后重写：逐条删掉正文再以紧凑分隔符写回，硬门禁（文件不在／不是对象／一条都没删掉 ⇒ 当场不发布）。不破坏别的东西的依据是客户端两处本来就按"可能没有正文"写。
- 10-21 · `agent.md` 是凭据事故驱动的 · 上一笔推送把我方内网主机的口令带进 `agent.md`，而它一直在内容集里，线上 `/agent` 随即发出去。剔除按文件名、**`--all` 也放不进来**。这与第五节那条"厂商印在手册上的公开口令"不是同一件事，按 D-21 第 2 条本来就不该上公开面。
- 10-21 · 决定 3 不在她指令里，但不修就没有"侧栏搜索"可交付 · 客户端硬写三处域名根路径，站点挂在子路径下时这些请求全落到域名根、回 GitHub 的 404 HTML。**侧栏树、搜索、关系图、结果链接、预览自搬库那天起就是坏的**，只是页面正文与图片照常，所以从没被发现。修法是从配置里取站点根、在构建后改写捆包，计数写死成硬闸。
- 10-21 · 这条链学到的验收口径 · **这类故障 HTTP 侧一律看不出来**——第五节那轮验收是"页面 200 ＋图片审计"，够不着客户端 JS。要么开浏览器控制台，要么把字面量计数写成脚本闸。
- 10-21 · 我自己写错的一处 · 改根表第三条的新值漏了等号，产物是坏 JS；抓法是本地动态 `import()` 过一遍——能过解析就报缺 DOM，过不了就报语法错。那一版从没进 git、也没上线。

## 九、10-21 检索字段加进标签

- 10-21 · 她的答复照做，但前提先纠正 · 「不要，用标题+标签」是对第八节那条"只搜标题"的答复。改法＝捆包里那条查询字段列表加上 `tags`（1 处，同一个硬闸循环）。**但全库 124 条索引的 `tags` 都是空的**：555 个 md 里只有一个文件带 frontmatter 的 `tags:` 键，而它在 `modellist` 原料目录里、根本不进内容集；正文里那 954 处 `#` 形 token 有 906 处是转档表格里的十六进制颜色。⇒ "标题＋标签"在当前库上**逐字等于"只搜标题"**：改做了，今天一个词都没多召回。
- 10-21 · 为什么不改数据形状 · 也可以把标签塞进 `content` 让它命中，但那是把同一份信息写进两个字段、还要动剪正文那一步的判据；加查询字段是唯一不碰数据的改法。`content` 留在列表里不删——它现在是空串、不参与命中，删掉反而每次升级要多改一处。
- 10-21 · 本地四态验过 · 现状输入、把改根反着退回去再造"改前形态"、对产物再跑一遍（幂等）、两处故意做错（原形态出现两次、字段整段改名）——前三种产物逐字节相同，后两种当场中止。语法闸是动态 `import()`。
- 10-21 · 召回不够时剩下两条 · 给页面真打标签，或在索引里留首段 N 字（各档体积是真数、不是估）。这两条是她的选择，挂在 D-71 未决①。

## 十、10-21 每页重复的样式表抽成一个外链

- 10-21 · 她为什么下这道令 · 第八节收尾时我报的是"每页 HTML 里 42 万 B 是内联 CSS、本次没动"。她问了一句"42 万 B 内联 CSS 是啥、会影响什么"，我把这块拆开量了一遍，然后她回「外置，记录到Markdown让每次重新构建的时候都补上这个补丁」。**这两句我读成两件事**：补丁做进构建后那一步（CI 每次构建都跑，不是手工改一次产物），判据与过程落到页面里。
- 10-21 · 量出来的真相跟"体积大"关系不大 · 首页 473,309 B 里那块最大的 `<style>` 占 417,916 B，124 页逐字相同。但 Pages 回 gzip，**她手机上真正要下的是 61,051 B**，所以这条不是"下载太慢"而是"**这笔字节每页一份、且每次站内点击都重付一遍**"——内联块没有 URL，缓存拿它没办法；而这个站的导航是抓整篇文档再换 body。
- 10-21 · 为什么只动最大那一块 · 另三块合计 9,774 B，占 2.3%，再拆要多开两三个请求，换不来什么。**切在 97.7% 那一刀，风险最小。**
- 10-21 · 两处细节是设计不是顺手 · ① 外链放回**原来那个位置**：那块 CSS 以 `@layer quartz-base, obsidian-theme, …` 这句层序声明开头，前面还有两条外链，位置一动层序就变。② 文件名用样式表字节的 sha256 前 12 位：主题一改名字就变，缓存自己失效。③ href 写成站点根绝对路径（跟第八节改根同一口径）——写成 `./` 的话根页与嵌套页拿到两个 URL，"共享"就没了。
- 10-21 · 差点漏掉的一坑：`data-persist` · 捆包每次导航会把 `document.head` 里**不带** `data-persist` 的节点全删再贴新的。这个属性站点自己的两条外链本来就有。**不给的话外链每点击一次被删掉重加，而样式表重新生效是异步的，中间那一帧没样式**——正是第八节那种"HTTP 侧看不出、只有浏览器里才暴露"的故障。这条是从 `postscript.js` 里读 `document.head.querySelectorAll(":not([data-persist])")` 那一段反推的，没读上游 TS 正本（C）。
- 10-21 · 硬门禁照旧 · 各页最大那块不一致（Quartz 哪天改成按页出样式）、或树半改（一部分外链一部分内联）⇒ 当场中止不发布。幂等那一关与改根、检索字段同族：对已外置的树再跑一次报 `already externalised`、页面一字节不动。
- 10-21 · 这道门禁第一次真红，是被自己的文档判倒的 · 把 D-73 写进 SOP 第七节之后推上去，作业 `39540461698` 红在 `Harden and trim output`：`1 of 126 pages already link an externalised stylesheet - mixed state`。根因是判"已外置"用的是裸前缀 `/assets/site-` 的子串匹配，而**那节新写的 curl 样本正文里就带着这串字符**（代码块只转义 `<`、`>` 与引号，`/`、`-`、`[`、`]` 原样进产物）——**写这条链的文档自己就是这条链上的一页**，它引用的每个字符串都会进产物。**这一步没退**：改判据（`16be89d`，只认整条 `<link … data-persist="true"/>`，正文再怎么写都撞不到）而不是把文档改薄，也不给这一步加开关。
- 10-21 · 本机验收被骗了一次 · 第一版测试报出"改后首页 566,491 B，比原来还大"，CSS 文件也落成 428,098 B 而不是 417,916 B。根因是 `Path.write_text()` 不带 `newline=` 时把 `\n` 换成 `os.linesep`：**CI 在 Linux 上等于没这件事，本机 Windows 会把整棵树改成 CRLF**。脚本内所有写入改走一个 `write()`。**上线字节一个都没因此变化**，但如果不修，我报给她的体积读数全是虚的。

## 十一、这条链现在长什么样

一句管线（细节与失败查表都在 [[Quartz搭建到Pages发布SOP]]）：

push 到本库 `main` → checkout（默认 token、`fetch-depth: 0`，日期要全史）→ 保护步确认历史真到位 → 按 tag 拉 Quartz 到 `qbuild/` → 恢复插件缓存 → 拷两份配置 → 装配器生成内容副本 → 构建 → **加固与裁剪那一步**（robots.txt／noindex／删爬虫索引与 RSS／剪正文／改根／检索字段／样式表外置）→ Pages 制品（挂 `PUBLISH` 那道闸）→ 部署。

承重的文件六个，全在文档库根：`site/quartz.config.yaml`、`site/quartz.lock.json`、`site/make-content.py`、`site/robots.txt`、`site/harden-site.py`、`.github/workflows/deploy.yml`。**职责表与每一项的判据在 SOP 第一节，这里不抄第二份。**
