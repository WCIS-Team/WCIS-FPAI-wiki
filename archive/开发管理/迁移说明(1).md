# 换号迁移说明（决策 ID 改为 UTC 时间戳）

> 本说明对应本轮交付的 `开发管理.zip`、`wiki-换号迁移.zip` 与主库根四份文档。看完这一页就知道改了什么、怎么落地、怎么核验。

## 一、改了什么

### 1. 决策 ID：连号 → UTC 时间戳

- **旧**：`D-01`…`D-78` 连号。连号是**全局共享计数器**——两个人各加一条决策必然改到同一行 ⇒ git 合并冲突。
- **新**：`D-<UTC Unix 秒>`，那个秒就是 **Unix 时间（`0` ＝ 1970-01-01 00:00:00 UTC）**。标题里紧跟在 ID 后面的就是这条的 UTC 日期，例：

  ```markdown
  ### D-1790553603 · 2026-09-28 · 凭据单点记账：全库只记一次，其余页面用链接指过去
  ```

- **新条目怎么取号**：直接取写作当刻的 UTC 秒，**不连号、不预约、不改号**。同一秒内不会出现两条；万一撞了，后到者用下一秒。
- **只记到日期的老条目**：同日的第 2 条起把秒 +1 s，**只为保证唯一与可排序**，不代表真实时刻；真实时刻以标题里的日期与条目「日期」行为准。
- 旧号 → 新号的完整对照见 `开发管理/决策编号对照表.md`（78 条）。

### 2. 注册表（`开发管理/状态源与决策记录.md`）

- 全部 78 条换号；第 4 节开头新增**取号规矩表 + 全量索引**（ID ／ UTC 日期 ／ 标题，按时间排序）。
- 「待补决策占位（编号已预留）」一节**改为「待补议题」**：时间戳 ID 不需要预约，也不该替没写的东西占号；原 D-09／D-10／D-11 三条议题沿用登记当日（2026-09-19）的时间戳占位，**引用它们的地方不用改号**。原「编号提示」（提醒别把 D-16 写成 D-19）随连号一起作废、删除。
- 第 6 节第 7 条改写：条目**永不删除**，**决定／依据／读数／回退条件不改写**；**只允许压缩「过程性错误叙述」**。
- 第 7 节模板改为 `### D-<UTC 时间戳> · <YYYY-MM-DD> · <标题>`。

### 3. 压缩「过程性错误叙述」（没有回顾价值，只留避免方法）

按第 6 节第 7 条的新口径，把「谁写错了脚本／哪次工具报错／编码或遗漏类事故」压成一行**避免方法**，数字与结论一律保留：

| 原来写成 | 现在只留 |
|---|---|
| 「我自己写错的三处公开更正……此后改完脚本先 grep 再跑」 | 「**改完脚本先 `grep` 再回读校验**」 |
| 「本机验收被骗了一次……`Path.write_text()` 不带 `newline=`」 | 「**跨平台写入必须显式 `newline=`**」＋原读数 |
| 「我上一轮判错过一次……把 archive 不存在读成树已重组」 | 「**判断工作区状态要看 git，不看目录在不在**」 |

| 「我上一轮写 ≥6 处是抽查」 | 「**计数必须全量遍历**」 |

| 「决定编号我报错两次……教训是现读现取」 | 整条删除（时间戳取号后不可能再报错） |

**保留不动**的是**实质性更正**（错的读数、错的语义、错的件名）——它们有回顾价值，是别人引用的依据。注册表里那几组「三条更正」「九条更正」都属这一类，只把「公开更正」的措辞改成「更正（现读）」。

# 第二轮：全库编号体系（不止 D-）

## 结论先行：短记号不能用全局正则改

普查全库 14 类编号后发现，同一个短记号在不同语境是**完全不同的东西**，盲替换会改坏技术事实：

| 记号 | 它同时是 | 实测 |
|---|---|---|
| `A8`／`B8`／`C1`／`A9` | **URL 百分号编码** ＋ **FPGA 管脚名** ＋ 任务卡号 | `%A8%A1`、`PACKAGE_PIN A9`、`D10/A10/C10/C11/A8/B8/B9/C9` |
| `M1` | **ARM 核名** ＋ 任务卡号 ＋ 台账名 | `Cortex-M3/M1/M0` |
| `Q4` | **GGUF 量化档名** ＋ 厂商问题单号 | `Q4_K_M`，全库 18 处 |
| `P0`–`P2` | **优先级** ＋ 任务卡号 | 「优先级口径：P0 = 当前必须…」 |
| `L1`–`L4` | **验证阶梯** ＋ （`L-01`…`L-14` 是长期决策） | 两者差一个连字符，极易看混 |

所以：**「改号」一律逐处看语境，代码块与行内代码里的记号一概不动。**

## 这一轮实际改了什么

1. **注册表新增第 8 节「编号体系（全库唯一一张表）」**——这是本轮真正的产出。它把七类记录的写法、时间戳取法、存量列成一张表，并写明：
   - **新记录直接取写作当刻的 UTC 秒**，不要找「下一个连号」（连号是全局共享计数器，两人各加一条必然改到同一行 ⇒ 合并冲突）；
   - **历史记录用「假时间」**＝`UTC 0 时 + 原编号`——**数值等于原编号，所以上下顺序一个字都不变**（统一整理时拿不到每条记录的创建时刻）；
   - 明确列出**不在表内**的等级与枚举（`E0–E6`、`L1–L4`、`S1–S5`、`P0／P1／P2／条件 P0`、`GS3`、`§章节号`、停用的 `M3／M4`）与那条 ⚠️ 警告。
2. **补上分隔符**（假时间＝原编号，只规范成 `前缀-时间戳`）：`风险 N` → `风险-15`（22 处）、`C1–C6` → `C-1`–`C-6`（44 处）、`Q1–Q7` → `Q-1`–`Q-7`（99 处）。共 16 个文件。
3. **`L-01`…`L-14` 与 `#176` 这类台账行号不动**——它们**本来就已经是 `前缀-数字` 形式**，数字即假时间戳，改了没有收益。
4. `AGENTS.md` 与 `CONTRIBUTING.md` 各加一条指针指向第 8 节，并把「不许全局正则改短记号」写进规矩。

## 仍然没动的（要动得逐处定语境，等你点头）

| 体系 | 为什么没动 | 影响面 |
|---|---|---|
| 任务卡号 `A3`／`M2`／`P3`／`B7` | 与 URL 编码、FPGA 管脚名、ARM 核名、优先级记号**同形**，得逐处判语境 | 约 450 处正文引用 |
| 台账行号 `#176` | 已经合规（`#` + 假时间戳），且台账表无日期列，无真实时刻可用 | 0（不需要改） |

要动卡号的话，建议顺带**给卡号换一个不与技术记号同形的前缀**（如 `PC-3` 平台卡、`MC-2` 模型卡），而不是把 `A3` 改成 `A-3`——`A-3` 仍会与管脚名 `A3` 的写法混在一起。
