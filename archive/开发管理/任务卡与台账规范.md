# 任务卡与台账规范

> **本页回答什么问题**：一张卡怎么写才算能开工、实测数据填到哪张表、哪些字段是强制的。
> **前置阅读**：[[状态源与决策记录#2. 状态标记与证据阶梯|状态源与决策记录——2. 状态标记与证据阶梯]]（三态结论、四态执行、证据阶梯）、[[进度计算与实时看板]]
> **产出物去向**：卡的状态进看板；台账数据是任何一张卡升为 ✅ 的判据来源，也是答辩性能对比材料的原始记录。

## 1. 任务卡模板

看板总账里一行只有 14 列（卡号／任务卡／分组／路线／负责／备份／预估／实际／状态／证据／更新／无板／备注／详情），装不下这些细节；细节按下面的模板写在本页或代码仓的卡文件里，**卡号与总账行一致**。缺任一必填字段不得进入 🔄。

```
【任务】<组件或交付物名>
【范围优先级】P0 | P1 | P2 | 条件项
【负责人】甲/乙　【备份】甲/乙　【预估】__d　【实际】__d
【前置】<依赖的卡或条件，例如「M2 端到端全绿并打上 baseline-v1」>
【输入】<可核查的实物：文件、tag、测试向量数量与来源>
【输出】<可核查的实物：位流、报告、脚本、文档页面>
【验收标准】
  1) <可测量判据 + 目标值>
  2) <可测量判据 + 目标值>
  3) <可测量判据 + 目标值>
  4) 运行时开关可切回 CPU 且全量回归通过
【证据计划】<用什么证据、在哪一级 (E2/E3/E4/E5/E6) 闭合>
【状态】⬜ | 🔄 | ⛔ | ✅ | ➖　【证据】E<级别> <可核查指向>　【更新】YYYY-MM-DD
【阻塞】— 或 <原因 / 解锁条件 / 预计解锁日>
```

### 字段规则

| 字段 | 规则 | 违反的典型样子 |
|---|---|---|
| 验收标准 | **必须可测量**：数字、命令、判据 | "基本可用"、"效果良好"、"稳定运行" |
| 验收标准 | 下沉类卡**必须**含第 4 条（一键切回 CPU） | 只写功能不写退路 |
| 输入 | 必须给到能独立复现的程度（向量数量、路径、tag） | "参考 CPU 实现" |
| 前置 | 必须写**卡号或可核查的条件**，不写"等基线好了" | 空 |
| 备份人 | 必填，且备份人要能独立完成该卡关键操作 | 空、或写"甲乙" |
| 证据计划 | 必填；决定该卡能升到哪一级 | 只有状态没有证据 |
| 状态／证据／更新 | 三个字段**逐列对应看板总账的同名三列**，抄卡时不要合并成一格 | `✅(E3) 差不多好了` 混在一格 |
| 预估 | **以 [[进度计算与实时看板#3.1 任务卡总账（唯一进度真值，一行一卡）\|进度计算与实时看板——3.1 任务卡总账（唯一进度真值，一行一卡）]]总账那一格为唯一真值**，本页与甘特图只引用不另计。超过 5d 的卡必须已经给出内部分解（步骤表、逐模型行或逐组件子卡），并在卡的"验收标准"里能逐项对上；没有分解的长卡不允许存在 | 一张 15d 且无分解的卡 |

**硬性规则**：没有「验收标准」的卡不允许进入 🔄。开卡时先在看板 §3.1 加一行（⬜），再写卡。

## 3. 示例卡（可直接照抄格式）

```
【任务】VFPGA-Resize 下沉（最近邻）
【范围优先级】P0
【负责人】乙　【备份】甲　【预估】4d　【实际】__d
【前置】M2 端到端全绿并打上 tag `baseline-v1`；A1 流控与帧控制已 ✅(E3)
【输入】CPU 黄金参考 resize 实现（deploy/golden/resize/）+ 测试向量 200 张
        来源：V4L2 采集的 1280x720 原图，覆盖纹理/边缘/纯色三类
【输出】resize.v + resize_tb.v + 综合报告 + 逐样本误差报告
【验收标准】
  1) 与 CPU 参考逐像素误差 ≤ 2 LSB，200 张全通过
  2) 1280x720 -> 300x300 单帧延迟 ≤ __ ms（该值在 ① 步与黄金参考一起冻结，不得事后调整）
  3) LUT ≤ __% / BRAM ≤ __% / DSP ≤ __ 个（预算值同上冻结）
  4) 运行时开关可切回 CPU 且 S1~S5 全量回归通过
  5) testbench 自动输出 PASS/FAIL，不依赖人眼判波形
【证据计划】E3 仿真逐样本比对 → E4 与 x86 golden 一致 → E5 上板冒烟 → E6 性能测量+回归
【状态】⬜
【阻塞】`baseline-v1` 未冻结（依赖板卡）
```

第二张示例（非下沉类，说明同一格式普适）：

```
【任务】iCraft 编译 Paraformer 并核对算子支持
【范围优先级】P0
【负责人】乙　【备份】甲　【预估】3d　【实际】__d
【前置】P2 环境搭建容器侧 3 项 ✅
【输入】官方 Paraformer 模型包 + icraft v3.36.1 或 v3.39 + 30TAI 目标配置
【输出】编译日志 + 算子支持清单 + 失败算子登记行
【验收标准】
  1) 编译成功或给出明确失败算子（两者都算闭合，模糊结果不算）
  2) 失败算子已进算子缺口登记表并选定尝试路径 ①/②/③/④
  3) 结论回写 [[状态源与决策记录]]，候选→已确认或维持候选
【证据计划】E2 编译结果（主机侧即可闭合，不需板）
【状态】🔄
【阻塞】—
```

> 第二张卡是典型的**无板可推进**卡：E2 级证据在容器里就能拿到，不该等板。这类卡应当优先排满。

## 6. 命名与书写约定

| 对象 | 约定 | 例 |
|---|---|---|
| 任务卡号 | 分组前缀 + 序号，全大写 | `P2`、`M1`、`A5`、`V` |
| 灰度阶段号 | `GS` + 数字，仅用于下沉灰度 | `GS2` |
| RTL 模块名 | 小写下划线，与状态源一致 | `video_stream_ctrl`、`mode_router` |
| git tag | 用途 + 语义版本 | `cross-v0.3`、`baseline-v1`、`v1.0` |
| golden 目录 | `deploy/golden/<模块>/` | `deploy/golden/resize/` |
| 构建目录 | `build-x86/`、`build-arm/` | 见 [[交叉编译环节]] |

脚本与配置文件（`.sh`、`.cmake`、`.yml`）内容一律英文、不含中文字符，避免 Windows codepage 与 CI 环境编码问题。
