| 术语                            | 全称与含义                                                                                                                                 | 在本项目里指什么                                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PS                            | Processing System，处理器侧                                                                                                                | 芯片里的 4 核 Cortex-A53 子系统及其 DDR／外设控制器                                                                                                                      |
| PL                            | Programmable Logic，可编程逻辑                                                                                                              | FPGA 本体，我们自研模块放这里（125K 逻辑、78 600 LUT）                                                                                                                    |
| APU                           | Application Processor Unit，应用处理器单元                                                                                                    | 就是 PS 里那 4 个 Cortex-A53，**最高 1 GHz**。规格见 [[芯片]] 第 12 行                                                                                                   |
| 原语（primitive）                 | 器件里最小粒度、有固定行为的单元，如 `BUFG`、`PLLE2_ADV`、`RAMH36_EXP`、`DSP`                                                                              | 综合后 RTL 会变成原语互连；原语仿真模型厂商不给明文                                                                                                                             |
| 网表（netlist）                   | 门级互连描述——"哪个单元的哪个脚接哪根线"，没有行为、没有源码                                                                                                      | 综合的输出。类比：RTL 是菜谱，网表是已经摆好的食材和线路图                                                                                                                          |
| EDIF                          | Intermediate Format，一种**网表**的文件格式（`.edif`）                                                                                            | 复旦微把 NPU 的网表以 EDIF 交付，见 `AI_Mate.edif`。等价于"只给你电路，不给代码"                                                                                                   |
| 器件壳／器件库补丁                     | 让厂商硅片借用 Xilinx 器件模型在 Vivado 里跑的一套数据补丁（`.paspd`／`.btl`／`.xng`）                                                                         | JFMQL30TAI 套的是 `xc7z030ai`（Zynq-7030）。正本见 [[官方demo时序基线与器件库补丁]] 第四节                                                                                       |
| IP（核）                         | Intellectual Property core，别人写好的可复用功能块（FIFO、PLL、DDR 控制器、调试 hub）                                                                       | 它的时序约束常自带在 IP 内部，不在工程 XDC 里                                                                                                                              |
| VCO                           | Voltage-Controlled Oscillator，压控振荡器，PLL 内部那个高频振荡节点                                                                                    | `f_VCO = f_IN × M / D`。1 GHz 那颗是 `200 × 5 / 1`，见前述页第二节                                                                                                   |
| min period check              | 最小周期检查：时钟类资源（BUFG、PLL 输出脚）有个物理上能翻转的最短周期上限                                                                                             | **它不是"逻辑来不及"，是"这个时钟本身超频"**，重跑实现、优化逻辑都救不了，只能降频或换速度档                                                                                                       |
| WPWS                          | Worst Positive Pulse Width Slack，最差正脉冲宽度裕量                                                                                            | Vivado 把 min period 违例报在**脉冲宽度**这一栏，所以会看到 WPWS 是负的而不是 WNS                                                                                                |
| WNS                           | Worst Negative Setup Slack，最差建立时间裕量                                                                                                   | 判断实现是否收敛只看这个，且只看 route 之后的                                                                                                                               |
| SDF 反标                        | Standard Delay Format，把每个门和每根线的真实延时数值回填进仿真                                                                                            | 时序仿真（后仿）的前置步骤                                                                                                                                            |
| 前仿／后仿                         | 前仿＝行为级（RTL）仿真，无真实延时；后仿＝综合／布局布线之后的网表或时序仿真                                                                                              | 时序收敛的两道关                                                                                                                                        |
| P1735 / `pragma protect`      | IEEE 加密标准，用 AES 加密模块体、再用收件人 RSA 公钥封装 AES 会话密钥                                                                                         | 复旦微 1 238 个 `.vp` 全是这个，收件人只有 Mentor 一把公钥                                                                                                                 |
| GSR／glbl.v                    | Global Set/Reset， FPGA 全局复位脉冲；`glbl.v` 是产生它的辅助仿真模块                                                                                    | 门级仿真不带它，结果常为全 X                                                                                                                                          |
| `set_false_path`              | 告诉静态时序分析"这条路径不用检查"                                                                                                                    | 官方 demo 用它处理跨时钟域，**没有**用它绕开 min period                                                                                                                   |
| `set_output_delay`            | 声明"我这个输出到外部器件的采样沿之间还剩多少时间"                                                                                                            | 那个 15 ns 的来源，属于 IP 自带约束                                                                                                                                  |
| `sln`                         | Visual Studio Solution https://learn.microsoft.com/en-us/visualstudio/extensibility/internals/solution-dot-sln-file?view=visualstudio |                                                                                                                                                          |
| CMA                           | Contiguous Memory Allocator，连续内存分配器——内核启动时从物理内存里预先圈出一块**必须物理连续**的预留池，专给做不了散射映射（scatter-gather）的大块 DMA 用户                              | 板上 `CmaTotal` 262,144 kB（256 MB），大户是 VPU／相机这类外设；泵工作态 `CmaFree≈130 MB`＝**池还剩一半**，不是"被白白占掉"，属常态，不用动。读数与结论见 [[ARM CPU TTS性能测试]] 第十八节、[[状态源与决策记录]] D-69 决定 4 |
| GEM                           | Gigabit Ethernet MAC，千兆以太网 MAC，PS 里的 Synopsys DesignWare 硬核（DWMAC），芯片内两颗                                                              | dtb 里 gmac0＝`ethernet@e0047000`（＝eth0，PS 直连那颗 YT8521）、gmac1＝`ethernet@e0049000`（出厂 disabled，对应 PL 侧第二颗 YT8521）；Linux 走 stmmac 驱动                         |
| MIO                           | Multiplexed I/O，PS 专用引脚复用器，PS 外设直接到芯片引脚、**不经过 PL**                                                                                    | eth0 的 gmac0 就是走 MIO 直连，开箱即用                                                                                                                             |
| EMIO                          | Extended MIO，把 PS 外设的接口信号**延长进 PL 阵列**，变成 PL 内部信号，由 PL 逻辑再接线                                                                          | 要用第二颗 GEM 必须经 EMIO 把它的 GMII 引出；"PS GEM 经 EMIO 到 PL"即此                                                                                                    |
| GMII                          | Gigabit Media Independent Interface，MAC 侧千兆接口，单沿采样、约 20 根数据线                                                                          | GEM 经 EMIO 露出的就是 GMII，引脚多，不能直接接 PHY                                                                                                                      |
| RGMII                         | Reduced GMII，DDR 双沿采样、引脚减半（12 根），板上 PHY 侧最常用标准                                                                                        | 板上两颗 YT8521 都是 RGMII；PL 口引脚在 Bank13（引脚表见完整版手册 4.8 节）；千兆 125 MHz 对 2ns 时延极敏感                                                                              |
| GMII-to-RGMII 核               | Xilinx 免费 IP（PG160），GMII↔RGMII 转换，并用 IDELAY／ODELAY 做千兆时延校准                                                                            | 方案 A（PS GEM 经 EMIO 出 PL 口）的必备核；千兆协商 up 但不通多半是 RGMII-ID 时延没配对                                                                                             |
| TEMAC（AXI Ethernet Subsystem） | Xilinx 三速以太网 MAC 软核（PG138），把 MAC 放 PL 里、经 AXI 总线挂 PS                                                                                  | 方案 B（PL 网口不占 PS GEM）用它，可做多口／SGMII；Linux 走 axienet 驱动                                                                                                     |
| FMC                           | FPGA Mezzanine Card，ANSI/VITA 57 通用子卡连接器标准；HPC 为高引脚数规格，引出多对 GT 收发器和专用差分时钟                                                             | 板载 FMC-HPC 接 SDI 子卡；子卡定义信号，载卡定义引脚                                                                                                                        |
| GT（MGT）                       | Gigabit Transceiver，FPGA 内高速串行收发器（7030 为 GTX，约 12.5 Gbps），走 SerDes 串并转换、内嵌时钟                                                          | SDI、SFP、PCIe 都用它；板上几路高速口靠 MUX 互斥，不能同时全开                                                                                                                  |
| MGTREFCLK（GT 参考时钟）            | 每个 GT quad 必须有一对**外部低抖动差分参考时钟**，进片内 PLL（QPLL/CPLL）倍频出线速率；只能接专用时钟脚、不能换普通 IO                                                            | SDI 用 148.5 MHz（xdc 里 `period 6.734`），即 R6/R5 那对脚；这对脚不对 GT 就锁不上、SDI 无帧                                                                                   |

### 工具链与模型侧

| 术语 | 全称与含义 | 在本项目里指什么 |
|---|---|---|
| `-pc` / `-pt`（`kld-pc`、`kld-pt`、`ems-pc`、`null-pc`） | 官方性能/精度表里 `Quantization`（benchmark 汇总 xlsx）与 `qt_strategy`（模型 README「模型性能记录」表）两列的**量化配置缩写**：前段是饱和方式 `saturation`（`kld`＝KL 散度最小／`ems`＝误差平方和最小／`null`＝非饱和），后段是量化粒度 `per`——`pc`＝`per_channel`（按通道，每通道一个 scale）、`pt`＝`per_tensor`（按层，整个张量一个 scale）。**官方任何一处都没给这两个缩写立图例**（`AIBS/modelzoo_index` 的 README 与 `index.md` 都没有），页末「引用与出处」第 1–4 条是三条证据还原出来的读法（判级 B） | 读官方表**必须先看这一格**：它说明「这个精度数是在什么量化粒度下拿到的」，与「在 PC 上测还是板上测」**完全无关**（2026-11-01 曾按「上位机仿真／板端」误读过一次，已在 [[00_总览]] 与 [[00_模型清单与性能]] 两处更正）。厂商默认档是 `kld-pc`（`saturation` 默认 `kld`、`per` 默认 `channel`） |
| iCraft whl（`icraft-<版本>-cp38-none-<平台>.whl`） | iCraft 的 **Python API 包**——官方安装包自述里写作「pythonAPI，可选」：把编译五阶段与运行时编成 pybind11 模块（`parse`／`quantizer`／`adapt`／`codegen`／`buyi_codegen`／`zhuge_codegen`／`buyibackend`／`zg330backend`／`host_backend`／`xir`／`xrt`，各配 `.pyi` 类型桩），**只出 cp38（Python 3.8）**，`win_amd64`／`manylinux2014_x86_64`／`manylinux2014_aarch64` 三平台各一颗。**它不是调 NPU 的必经之路**：C/C++ 走 onchip deb 里的 `.so`＋头（`Icraft_3.39.0_onchip.deb`＝23 颗 `.so`＋386 个头＋28 个 cmake），板上还有现成 CLI `/usr/bin/icraft-run`；我方 YOLOv8n 5000 张评测走的就是官方 C++ demo（aarch64），全程无 Python。whl 只有跑官方工程 `pyrt/*.py` 那套时才必须 | 板上或主机上用 Python 调 iCraft 的那层绑定。**两条硬约束**：① 必须先装**同版本**的 deb／exe 再 `pip install` 这颗 whl，版本不一致时 `import icraft.xir` 报 `undefined symbol: _ZN6icraft3xir6Params4loadEv`（ABI 不匹配，实例见 [[板端我方代码与产物台账]] #157）；② wheel 元数据零依赖声明，装它不会牵动 numpy。实物位置：v3.36.1 三平台在 `largefiles/04_ICraft/v3.36.1/ICraft_V3.36.1安装包/`；v3.39.0 的 aarch64／x86_64 在本机 `S:\apps\llm\agentwork\icraft-whl\`（板上那颗 .whl 安装包文件已于 2026-10-31 删除——`pip install` 是成功的，装好的模块仍在 `site-packages`＝3.39.0；3.33.1 旧版整包备份在板上 `/root/icraft-py-3.33.1.bak/`） |

## 引用与出处

### `-pc` / `-pt`

1. **取值域（官方文档原文）**：`C:\Icraft\CLI v3.39.0\docs\quantizer\zhuge\zhuge.html` —— 「`saturation string`（optional）表示统计饱和点的方法（`kld`/`ems`/`null`）」；「`per string`（optional）表示按层还是按通道量化（`tensor`/`channel`），默认为 `channel`」。同页正文：「当 `per = tensor` 时所有权重对应 1 个 scale 值；`per = channel` 时 co 个通道的数据对应 co 个 scale 值。一般来说，`per_channel` 量化的表现会优于 `per_tensor`」。
2. **全称证据**：官方索引原始数据里出现全称 `ems-channel`（渲染进 Markdown 时缩成 `ems-pc`），共 6 处 —— `wiki/PL/MOD/modellist/09_FPAI-ICraft网络资料/01_ModelScope-ICraftModelZoo/raw/index_tables.json`。
3. **toml 对证两例**（一例 `pt`、一例 `pc`）：
   - `AIBS/yolox`，tag `v3.36.1`，`yolox_icraft/2_compile/config/ZG/yolox_s_int8.toml`：`saturation = "kld"` ＋ `per = "tensor"`；官方索引里 yolox 的 ZG 精度标 **`ZG_30TAI_int8_kld-pt`**。
   - `AIBS/CAMpplus`，tag `v3.31.0`，`CAMpplus_icraft/2_compile/config/ZG/CAMpplus_int8.toml`：`saturation = "kld"` ＋ `per = "channel"`；官方索引里 CAM++ 的 ZG 精度标 **`ZG_30TAI_int8_kld-pc`**。
4. **官方确实没有注释**：`AIBS/modelzoo_index` 仓库 `README.md` 只写「本仓库用于放置不同 icraft 版本上经过批量性能测试的已支持模型名单：`index.md`」；`index_mdz_v3.36.md` 全文无「上位机／仿真／板端／图例」字样。⇒ 本条是**按证据还原的读法**，不是官方定义。

5. **官方自述**：`largefiles/04_ICraft/v3.36.1/ICraft_V3.36.1安装包/readme.md` —— 「`icraft-3.36.1-cp38-none-win_amd64.whl`（**pythonAPI，可选**）／Icraft pythonAPI Windows10版，**仅支持python38**／务必先安装 `Icraft_Setup_v3.36.1.exe` 再安装本程序／`pip install …`／`pip uninstall icraft`」，同段另列 `manylinux2014_x86_64` 与 `manylinux2014_aarch64` 两颗。
