## 关键：mel 不是我拼的，是 sherpa 的 tokenizer 给的

token 序列由 **sherpa-onnx 2.0.1 自己的 debug 输出**直接给出（不是我按 lexicon 猜的）：

```
Sentence 0 tokens: [ni2(1116), hao3(597), ,(2), wo3(1737), shi4(1518),
                    ni3(1117), de(314), yu3(1872), yin1(1845), zhu4(1993),
                    shou3(1522), .(3)]
Sentence 0 final IDs (25): [1, 1116, 1, 597, 1, 2, 1, 1737, 1, 1518, 1, 1117,
                            1, 314, 1, 1872, 1, 1845, 1, 1993, 1, 1522, 1, 3, 1]
```

两个此前搞错的地方：

1. **「你」读 `ni2`(1116)，不是 `ni3`(1117)** —— 变调，按 lexicon 逐字查会查错。
2. **标点 `,`(2) 和 `.`(3) 是 token**，且每个 token 之间要插 `pad=1`（`add_blank`）。

打开 sherpa debug 的方法：
```python
mc = sherpa_onnx.OfflineTtsModelConfig(matcha=..., num_threads=1, debug=True)
```

> 更正：上一版这里写「hifigan 四条都很低（0.029／0.154／−0.141／−0.031）」——**那是我比对对象搞错了**：
> 拿 HiFi-GAN 的 NPU 输出去比 **vocos** 的 CPU 参考，两个不同声码器本来就该不相关。
> 换成同模型参考后是 **0.998 以上**。详见 `wiki/PS/Backend/MatchaVocosNPU.md` §10.8 / §8b.3。

## 怎么听

- **先听 `01_问候_vocos_npu.wav`** —— 应与 `01_问候_cpu.wav` 几乎一样。
- 再听 `04_长句_vocos_npu.wav` 比较长句。
- **HiFi-GAN 那条也成立**：听 `01_问候_hifigan_npu.wav`，它直出波形、没有 iSTFT，听感可能与 vocos 不同（两个声码器音色本来就不一样），但**它忠实于自己的 CPU 版**（0.9991）。
- **两个声码器的音色不同是正常的**，不要互相比较波形；要比就比同模型的 CPU 版。
