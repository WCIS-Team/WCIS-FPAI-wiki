# SOP 1：ASR 模型性能 Benchmark

CPU限制在4核心，每核1GHz

## 1. 目标

对指定 ASR 模型进行可复现的性能测试，评估中文识别准确度、启动开销、内存占用、CPU 使用率、推理速度、实时性和运行稳定性。

硬件与基础运行环境保持一致，不在本 SOP 中采集或分析硬件规格。测试过程中只记录模型推理所需的配置，以及解释性能结果所必需的运行参数。

必须实际运行模型，不得使用论文数据、官方成绩或理论估算代替实测结果。

## 2. 测试前检查

1. 检查模型名称、版本、权重来源、模型文件大小、模型格式及输入输出接口。
    
2. 确认模型可以在 CPU-only 模式运行。
    
3. 记录推理框架及版本、模型运行模式、线程配置、解码参数和预处理设置。
    
4. 确认测试集及参考文本可用，记录测试集版本和固定测试清单。
    
5. 固定音频预处理、文本归一化和评测工具的配置。
    
6. 检查是否存在超时、异常退出、空输出或无法处理的样本。
    
7. 无法执行的项目标记为 N/A，并注明原因；不得伪造实测数据。
    

## 3. 中文测试集

必须检查以下数据集，并在汇总表中分别报告各数据集的结果。

### 3.1 通用中文 ASR

- **AISHELL-1**：优先采用官方 test 集，作为基础普通话识别基准。
    
- **WenetSpeech**：选择许可允许、具有可靠参考文本的固定测试子集，补充多领域语音评测。
    
- **MagicData-RAMC**：采用可获取的官方评测划分或明确标注来源的固定子集，评估自然普通话对话。
    
- **AISHELL-ASR0009-OS1**：检查其官方测试划分和数据可用性，作为额外的中文语音测试集。
    

### 3.2 家居语音 ASR

- **AISHELL-2023A-EVAL**：优先检查其家居语音控制评测数据是否可获取、是否提供音频及可靠参考文本，以及使用许可是否允许当前用途。
    
- **自建家居指令音频集（暂无）**：必须覆盖项目实际支持的设备和指令，包括灯光、窗帘、空调、风扇、插座、加湿器、空气净化器、电视等；按实际项目调整设备范围。测试内容应包括设备开关、参数调节、状态查询、房间名称、数字、相似发音词、口语变体、否定表达和复合指令。
    
- **NLP-CSmHomComC**：检查其智能家居命令文本语料的可用性和许可。该语料是文本，不是音频，不能直接计算 ASR CER。仅用于设计录音脚本、检查指令覆盖率或构造补充测试用例。
    

如果公开家居音频不可获取，应明确报告缺失情况，并使用经授权的家居命令文本制作项目自建录音集。不得将自建数据标记为公开测试集。

### 3.3 测试集管理规则

- 优先使用官方测试划分，不使用训练集代替测试集。
    
- 固定数据集版本、测试子集、样本清单及清单哈希。
    
- 记录样本数、总音频时长、采样率、声道数和可获取的场景信息。
    
- 不得针对单个模型修改测试样本或归一化规则以提高成绩。
    
- 各测试集分别计算指标，不将不同测试集简单合并为单一成绩。
    
- 无可靠参考文本的样本不得纳入正式 CER 计算，但应记录其数量及原因。
    

## 4. 模型运行配置

每个模型配置必须记录：

- 模型名称、版本和权重来源。
    
- 模型格式及文件大小。
    
- 推理框架及版本。
    
- CPU-only 执行模式。
    
- 推理线程数、线程池设置和进程数。
    
- 离线或流式识别模式。
    
- 音频输入参数。
    
- 解码参数、分块大小和缓存设置（适用时）。
    
- 预处理与后处理设置。
    
- 测试脚本版本、配置文件哈希。
    

不同模型可以使用各自必需的推理配置，但必须保持测试数据、统计口径和评测规则一致。比较不同线程配置、模型格式或推理框架时，应分别记录为独立配置。

本 SOP 不采集 CPU 型号、物理核心数、内存总量、驱动版本等硬件档案信息。

## 5. 启动与资源测量

分别测量以下阶段：

1. 冷启动。
    
2. 模型加载。
    
3. 首次推理。
    
4. 预热。
    
5. 稳态推理。
    
6. 完整测试过程。
    

记录指标：

- 冷启动耗时。
    
- 模型加载耗时。
    
- 首次推理耗时。
    
- 启动阶段平均 RSS。
    
- 启动阶段峰值 RSS。
    
- 稳态平均 RSS。
    
- 全程峰值 RSS。
    
- 稳态平均 CPU 使用率。
    
- 稳态峰值 CPU 使用率。
    
- CPU 用户态时间、内核态时间和总 CPU 时间。
    
- 配置线程数和实际观察到的线程数。
- CPU核心使用数量
    
- 监控工具、采样间隔和 CPU 百分比统计口径。
    

资源监控必须覆盖启动到测试结束，并说明是否包含子进程。

RSS 为进程驻留内存，不等于模型文件大小。多进程共享内存时，不得简单累加各进程 RSS 并宣称为实际物理内存消耗。

CPU 使用率必须注明统计口径，包括单个逻辑核心满载是否计为 100%，以及多线程累计是否允许超过 100%。

## 6. 推理性能

逐条记录：

- 音频时长。
    
- 预处理耗时（可分离时）。
    
- 模型推理耗时。
    
- 后处理耗时（可分离时）。
    
- 端到端耗时。
    
- 识别结果。
    
- 执行状态、异常和超时情况。
    

汇总：

- 单条端到端延迟均值。
    
- 延迟 P50、P95、P99。
    
- RTF 均值及分布。
    
- 音频处理吞吐量。
    
- 流式首个识别结果延迟（适用时）。
    
- 流式分块大小、分块间隔及最终结果稳定性（适用时）。
    

计算规则：

RTF = 推理耗时 / 对应音频时长。

RTF 越低越快。RTF 小于 1 表示该次处理速度快于对应音频的实时播放速度。

吞吐量 = 成功处理的音频总时长 / 对应推理总墙钟时间，单位为音频秒/墙钟秒。必须明确是否包含预处理、后处理、排队和模型加载时间。

流式 ASR 必须额外评估实时输出延迟，不能只用完整音频的离线 RTF 代表流式体验。

## 7. 中文准确度

主要指标：

- CER。
    
- WER。
    
- 替换数 S。
    
- 删除数 D。
    
- 插入数 I。
    
- 参考文本字符总数。
    
- 参考文本词数。
    
- 成功样本数。
    
- 空输出数、异常数和超时数。
    
- 失败率。
    

CER = (S + D + I) / 参考文本字符数。

WER = (词替换数 + 词删除数 + 词插入数) / 参考词数。

中文 WER 必须固定分词工具及版本。所有模型使用相同的评测工具、参考文本和归一化规则。

必须记录以下文本归一化设置：

- 是否统一简繁体。
    
- 是否移除标点。
    
- 空格处理规则。
    
- 数字、日期及时间的归一化规则。
    
- 英文字母大小写处理。
    
- 特殊符号、设备名称及缩写的处理方式。
    

保存原始识别文本、归一化后的识别文本及参考文本。不得针对某个模型单独调整规则。

CER 和 WER 仅针对具有可靠参考文本且成功完成识别的样本计算，同时报告失败率，避免通过丢弃失败样本美化结果。

## 8. 重复运行与稳定性

每个固定模型配置至少进行 3 次独立运行。

- 记录每次运行的原始数据。
    
- 报告均值、标准差和适用的 P50/P95/P99。
    
- 固定预热次数、测试顺序和采样间隔。
    
- 执行连续推理测试，观察内存增长、延迟变化、异常退出和超时。
    
- 记录测试持续时间、总样本数、成功样本数和失败样本数。
    

不得只报告表现最好的一次运行。

## 9. 最终唯一汇总表

最终只输出一张 Markdown 汇总表。每行代表一个模型配置在一个固定测试集上的结果。同一模型测试多个数据集时分别成行。

|字段类别|必须包含的字段|
|---|---|
|模型标识|模型名称、版本、权重来源、模型格式、模型文件大小|
|推理配置|推理框架及版本、CPU-only 模式、进程数、配置线程数、实际线程数、离线/流式模式|
|数据集|数据集名称、版本、测试子集、样本数、总音频时长、采样率、声道数、清单哈希|
|启动|冷启动耗时均值、模型加载耗时均值、首次推理耗时均值|
|内存|启动平均 RSS、启动峰值 RSS、稳态平均 RSS、全程峰值 RSS|
|CPU|稳态平均 CPU%、稳态峰值 CPU%、用户态 CPU 时间、内核态 CPU 时间、总 CPU 时间、统计口径|
|推理速度|单条延迟均值、P50、P95、P99、RTF 均值、吞吐量、流式首结果延迟|
|准确度|CER、WER、S、D、I、参考字符数、参考词数、归一化规则|
|稳定性|独立运行次数、成功数、失败数、超时数、异常数、失败率、测试总耗时、内存增长情况|
|可复现性|测试脚本版本、配置文件哈希、评测工具版本、原始日志路径、逐条结果路径|

所有字段必须填写实测值或 N/A。数值应带单位；无法测量的字段必须注明原因。

## 10. 交付物

1. 一张 Benchmark 汇总表。
    
2. 逐条识别结果及参考文本。
    
3. 原始性能监控日志。
    
4. 测试配置和复现命令。
    
5. 数据集版本及固定测试清单。
    
6. 异常、超时、缺失数据及无法完成项目的说明。
    

最终结论应分别比较识别准确度、推理速度、内存占用、CPU 开销及稳定性。不得只依据 CER 或 RTF 单一指标判定最佳模型。
