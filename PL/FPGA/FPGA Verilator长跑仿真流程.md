## 一、结论

1. **可行，而且快两个数量级**。同一个 Verilog 测试台：xsim 约 **4 分 22 秒**，
   Verilator 约 **10 秒**；C++ 测试台（真实视频）约 **0.4 秒 / 源帧**。
   60 帧真实视频 + 12 种图案 + 事件注入全套 **约 20 分钟**。A 级。
2. **真实视频是唯一能暴露某些判据缺陷的用例**。这一轮真实 H.264 帧一跑就报
   `2345/921600 像素不符`，而 DUT **一个像素不差**——是判据的帧相位模型漏了
   跨帧边界的那 2 行；**合成图案逐帧不变，天生看不见这类错**。A 级。
3. **它也能暴露「只在扰动之后出现」的设计缺陷**：源与光栅的帧相位差一旦超过
   行槽环的吸收窗口（约 ±7 行），画面就永久留在 1～24 行的稳定横带上（不自愈）。
   单看「上电能出图」的用例会全部漏掉。A 级。
   ✅ 2026-10-17：这一条已被修复（读侧跟写侧帧标记走、一次性拉长），
   **16 个相位点全部 0 损失**；修的过程中又被这套测试台自己骗过两次（等待把源停住 ⇒ 极限环、
   事件窗口没跟上比较的滞后），见第四、五节。
   ⚠️ 与之配套的教训：**这个缺陷一开始被错误的判据掩盖了**——测试台的默认相位
   （源与光栅同时起跑）是真板做不到的对齐相位，于是整整两轮套件报「全过」。
   见第六节第 2 条。
4. **C++ 测试台比扩展 Verilog 测试台值得**：长跑、复位、失锁重锁、运行中换几何、
   源相位扫描这几件事在 Verilog TB 里写起来极其别扭，而且它给信号随便赋值
   的自由度**会诱导出真板上不存在的激励**（见第六节第 1 条）。A 级。
5. **不含 TMDS 编码、OSERDES、GT 与厂商加密核**——那些仿不了，这条链的上限是
   「本工程自己写的 RTL 全部覆盖」。A 级（边界陈述）。

## 二、怎么跑（校机 `D:\yzd\sdi2hdmi\`）

Verilator 5.050 + MSYS2 mingw64 gcc 16.2.0。两条构建入口：

```bash
export PATH="/mingw64/bin:/usr/bin:/bin:$PATH"     # 必须，见第五节
cd /d/yzd/sdi2hdmi || exit 1

# ① Verilog 测试台（短用例、单模块）——--binary 自带 main，也能吃 +plusarg
verilator --binary --timing -CFLAGS "-O2" -Wno-fatal -Wno-WIDTHEXPAND \
    --top-module tb_scaler_720 -j 8 -Mdir obj_sc720 -o sc720 \
    rtl/scaler_720.v sim/tb_scaler_720.v
./obj_sc720/sc720.exe +w1920 +h1080 +f4

# ② C++ 测试台（长跑、真实视频、事件注入都走这条）
verilator --cc --exe --build -j 8 -CFLAGS "-O2" \
    -Wno-fatal -Wno-WIDTHEXPAND -Wno-UNUSEDSIGNAL -Wno-UNDRIVEN \
    --top-module vlt_top -Mdir obj_harness -o harness \
    rtl/scaler_720.v rtl/hdmi_out.v sim/vlt_top.v sim/harness.cpp
./obj_harness/harness --pattern noise --frames 60
./obj_harness/harness --src data/frames/bbb.rgb565 --frames 30
```

一次跑完全套（写成一个 `suite.sh`，逐用例留日志；**脚本正本**：
`S:\work\WCIS\workenv\fpga-src\sdi2hdmi\sim\suite_school.sh`（2026-10-17 归口后；
窗口扫描是同一目录的 `suite_school_window.sh`），拷到校机后跑）：

```bash
bash D:/yzd/sdi2hdmi/suite_school.sh          # 全量套件，约 20 分钟
bash D:/yzd/sdi2hdmi/suite_school_window.sh   # 16 点相位窗口表（验收判据），约 7 分钟
```

窗口表是**帧相位对齐这一条的验收判据**（16 个点全部 `steadyDrop 0 / steadyHeld 0`）；
`suite_school.sh` 里也有相位列，但那是**累加计数**，含启动瞬态，不替代窗口表。

**从开发机驱动校机**：不要把命令塞进 `ssh` 的引号里（cmd → PowerShell 会吃掉引号）。
写成脚本、`cat` 进去：

```bash
cat 'local.sh' | ssh -o BatchMode=yes <校机别名> 'D:\yzd\MSYS2\usr\bin\bash.exe -ls'
```

**真实视频素材**（每帧 `1920*1080*2` 字节的 RGB565 裸流）：

```bash
ffmpeg -i clip.mp4 -vf scale=1920:1080 -pix_fmt rgb565le -f rawvideo frames.rgb565
```

Python 是原生 Windows 二进制：脚本里的路径要写 `D:/yzd/...`，**`/d/yzd/...` 会失败**。

## 三、测试台的形状（`sim/vlt_top.v` + `sim/harness.cpp`）

* `vlt_top.v` 把**工程真正要发的模块**（这里是 `scaler_720` + `hdmi_out`）按顶层一样
  的方式接起来，端口只暴露**测试需要观察/驱动**的那些。这样给出的激励和真板一致。
* `harness.cpp` 负责：时钟相位表、驱动一个源帧、采集一个输出帧、黄金模型、
  判定、事件注入、诊断打印。
* **驱动模型：源必须一直开**。每帧严格驱动 `总宽 × 总高` 个 camclk，**背靠背**，
  测试台自己不许暂停源（等待/跳过/默认值都是激励的一部分，见 §四 第 4 条与 §五）。
  比较对象是「**最新一个完整输出帧**」；没有新输出帧的这一轮就**不比较**。 
* **时钟模型**：主时钟一个周期切成 4 个相位，每个相位调一次 `eval()`；
  采样相位固定，避免「同一拍看到两个值」。这条要写死，不要靠 `eval()` 的次数凑。
* 诊断开关（只在排查时用，别进判据）：

```bash
--diag           每源帧打印一次内部状态（生产者行数/丢弃/停顿/几何/锁定）
--start-phase N  复位后先把源空拖 N 个主时钟再送第一帧（制造源与读侧的帧相位差）
--vs-rise-x N    vs 相对第一条有效行晚 N 个主时钟（相位敏感度扫描）
--reset-frame N  第 N 帧中途复位（事件恢复）
```

## 四、判据：三层，缺一层就会报假错

1. **前置断言**：`locked` 必须置位、必须有行推出、几何必须等于期望、捕获缓冲与
   黄金模型**都不许全零**（[[验证方法学]]：拿两个 0 比 0 等于什么都没验）。
2. **内容**：逐像素等于规范模型。
3. **相位**：允许一个**恒定**的帧相位偏移，**相位一旦漂移就算失败**。
   流水线式的结构（环形行槽 FIFO）给不出 0 偏移，硬要 0 就是把「设计给不出的东西」
   写成判据——但**偏移跨帧边界**这件事必须建模：显示帧最上面几行属于**上一帧**。
   黄金模型要**跨两帧**取（`golden(f)` + `golden(f-1)`）。

**失败时先分半，再定位**：把「写侧流」和「显示侧」各自比一次黄金模型
（`[bisect] ...` 那两行），一眼就能看出故障在链的哪一半。
这一轮就是靠它把 `scaler_720` 一次摘干净的：

```
[bisect] scaler stream :      0 of 921600 pixels differ   <- 写侧一个像素不差
[bisect] hdmi capture  : 72630 of 921600 pixels differ    <- 差异全在行槽环这一侧
```

**事件用例要看稳态**：复位/失锁之后**跑十几帧再判**（这一轮的缺陷是「每帧丢 23 行」
的稳态，头两帧还在收敛，只看头两帧会得出相反的结论）。

4. **激励必须连续**：源一旦起跑，测试台**每一帧都要驱动它**，不许自己暂停。
   环形行槽 FIFO 的契约是「生产者不停」，「等一个输出帧完成」不能做成
   「只推时钟、不驱动源」——那是一次**源停机**，把源的帧边界在**时间上**挪走。
   实测：对齐机制把一帧拉长到 ~1481 行时，750 行的驱动窗口里可能一个输出帧边界都没有，
   等待最长跑到 ~731 行 = **16 ms 的源停机**，刚被校正掉的相位又被造了回来 ⇒
   **每帧重校正一次的极限环**（15 帧 15 次、幅度每次都对）。
5. **事件窗口要跟得上比较的滞后**：比较「最新完整输出帧」意味着它可能是 `f-1` 或 `f-2`
   （黄金搜索本来就覆盖 `f / f-1 / f-2`），复位还会打掉几何锁（要重量一帧）。
   窗口取 **事件长度 + 4 帧**。只留 1 帧时的签名很有辨识度：**只有一次比较失败**、
   前后帧全部逐像素通过 —— 那是「比较落在过渡里」，不是「没恢复」。

## 五、踩过的坑

| 现象 | 根因 | 处置 |
|---|---|---|
| `invalid use of incomplete type 'class Vvlt_top___024root'` | Verilator 把子层次**摊平**进根对象；`Vvlt_top.h` 只有前置声明 | 再 `#include "Vvlt_top___024root.h"`；内部寄存器走 `du->rootp->vlt_top__DOT__u_scaler__DOT__xxx`。**只有 `vlt_top` 的端口算稳定接口**，内部探针只用在诊断打印里 |
| 链接期 `undefined reference` 到 `std::basic_string` 的移动构造 | mingw64 GCC 16 在 Verilator 默认的 `-Os` 下不导出它 | `-CFLAGS "-O2"`，**不是可选项** |
| `--exe` 链接报缺 `main`/符号 | `--binary` 生成的 main 需要它 | C++ 侧提供 `double sc_time_stamp() { return 0.0; }` |
| Verilator 报 `unexpected STRING, expecting ')'` | Verilog-2001 **不拼接相邻字符串字面量** | `$display({"a", "b"}, x)`；`"a" "b"` 只在 xsim 那边侥幸能过 |
| `harness` 报 `libstdc++-6.dll: cannot open shared object file` | 脚本头少了 `export PATH="/mingw64/bin:..."` | **不是构建失败**，别误判成测试台崩了（这一轮踩了两次，两次都表现为「日志是空的」） |
| 真实视频报几个像素不符，DUT 却是对的 | 判据的帧相位模型只在**单帧内**循环移位，漏了跨帧的那几行 | 黄金模型跨两帧取；**用真实视频做这类用例的守门人** |
| 12 种合成图案全过，真实视频却挂 | 图案**逐帧不变**（种子固定），帧间差异为 0 | 判据/相位类的缺陷必须有**帧间会变**的源才能暴露 |
| 测试台测出「源帧少了 1 行」 | 测试台把 `vs` 挪到了第一条有效行**之后**，而真板上 `data_en = vs & hs` 逼着两者同拍 | **测试台里的每个信号都要能追到厂商 RTL 的某一行**；追不到的激励就是在造不存在的场景 |
| 判据读的计数器永远不变 | 那个计数器是另一个 always 块的**局部变量**；同类前科还有「拿两个 0 比 0」 | 判据里每个计数器都要能指到**产生它的那个赋值** |
| 换几何/换相的用例报一堆假失败 | 只换了激励、**没重算黄金模型**；而且换的用例本身得是**合法**光栅 | 用例与黄金模型一起换；不合法的用例只能当**测量**，不能当通过/不通过 |
| 二分定位打印「写侧已经错了」，而写侧差异是 0 | 「写侧还是显示侧」的判据写成了 `sb != cb`，而语义是「`sb` 必须为 0」；典型下游故障恰好命中 `!=` | 判据改成 `sb > 0`；**打印出来的结论也要能被同一段数字支持**，比较运算符照着物理含义写 |
| 相位表的 8 个点**全过**，于是写下「上电干净、不挡点亮」 | ①那个全过是**旧二进制**给的假 PASS（改了源码重建后同一张表只剩相位 0 干净）；②更要紧的是**测试台默认相位本身不物理**——源与光栅同时从复位释放点起跑，真板上 SDI 是自由运行输入、相位任意 | 判据「全过」时要问「**这组点为什么全过**」；相位类失配通常是**越大越坏**的连续函数，全过就是可疑信号。有疑问先做**确定性对照**（同二进制跑两遍＋重建跑一遍），再谈结论。相关默认值要能追到「板上是谁决定的」 |
| 修好对齐机制后，两个大相位点**每帧都重校正一次**（幅度每次都对，测量和装载都没错） | 每帧「等一个输出帧完成」的等待**只推时钟、不驱动源**；拉长帧时等待变成一次最长 16 ms 的**源停机**，源帧边界在时间上被挪走，刚校正掉的相位又回来了 | **等待也是激励**：帧**背靠背**驱动，比较「最新一个完整输出帧」，没有新帧就跳过。见 §四 第 4 条 |
| 复位用例只差**一次比较**（1278 px ≈ 一行），前后帧全对 | 比较可滞后驱动最多 2 帧，复位还要重量一帧几何 ⇒ 事件窗口只留 1 帧不够 | 事件窗口 = **事件长度 + 4 帧**；先分清「没恢复」与「比较落在过渡里」（签名是「只有一次、且前后全对」） |
| 诊断探针 `align_pos`/`align_add` 重建后读不到 | 它们**只写不读**，Verilator 的优化器直接把寄存器删了 | 诊断改读**功能信号**（`wf_s3`、`v_extra`）；**没有功能读者的信号不是信号** |

## 六、这一轮的方法结论（可以搬走的）

1. **判据的错误比 DUT 的错误贵**。这一轮两次大失败（真实视频 2345 像素、
   复位 72630 像素）里，第一次完全是判据的错，第二次是判据把 DUT 的稳态缺陷
   准确地量了出来。先修判据，再谈设计。
2. **「守恒量」要显式打印**：生产者行数、消费者取行数、丢弃、停顿，
   每帧一行。缺陷的形状（丢 23 / 重复 23）比「画面不对」这句话有用得多。
3. **一个只有 8 个缓存的环，对齐窗口是 ±7 行左右**：源/光栅的帧相位差在窗口内
   完全干净，越界之后永久留下 1～24 行的稳定横带。这类结论只有**扫相位 + 稳态判据**能测出来。
   ⚠️ 一开始写成「双稳态」（上电干净、复位变坏）是**错的**，而且是被错误的判据掩盖的：
   测试台默认相位（源与光栅同时起跑）真板做不到 ⇒ 整整两轮套件报「全过」，
   差点让一个上板阻塞项带着「干净」的结论上板。
4. **契约要用等式写下来**：这一轮的契约是**两条**等式
   （`有效行数 × 总宽度 = 常量` 且 `总行数 × 总宽度 = 常量`），
   而文档上一版只写了后者——半条契约会漏掉一整类失败。
5. **修 bug 之前先确认测试台能产生这个 bug**（[[验证方法学]]）。
   这一轮为此专门加了「源相位扫描」「中途复位」两个注入口的对照用例。
6. **测量对、装载对、结果却不动的时候，先问「是什么把输入又造了回来」。**
   对齐循环的公式、计数器、死区全对，问题出在测试台的等待把源停住 ——
   环境里的等待、跳过、默认值都是**激励**的一部分，
   一个「每帧都以同样幅度重复」的校正就是环境在造输入的签名。
7. **给测试台加激励旋钮时，先证明旋钮拧得动。** 对同一份 DUT 取**两个差别足够大的
   取值**，输出必须真的不一样；`hold=0 / 1091 / 1113` 三次运行逐字节相同 ⇒ 旋钮
   的单位没换算（源行 vs cam_clk），三个值全退化成同一个相位，而且**全绿**。
   打印要带**换算后的物理量**（`+hold=1091 lines = 2400200 cam_clk`），
   只打印「参数被解析了」证明不了它变成了时间。
   同一轮还有一个同类的**读数**漏洞：`settled want` 读的是**打印时刻**的自由运行
   光栅行号（看着像收敛到别处）。**监看要在它有意义的那一拍采样，并真的进判据**
   ——「最后一个干净标记的 `want` ∈ `{0,1,749}`」现在是 PASS/FAIL 的一部分。

## 七、这条链**不覆盖**什么

* **TMDS 编码器（VHDL）与 OSERDESE2 原语**：Verilator 不出硬件原语，只验到编码器输入。
* **GT 收发器与厂商加密网表**（SDI 解码）：无 RTL，只能上板。
* **需要真时钟关系的源**：这里 720p60 源要求 `cam_clk = 74.25 MHz` 而输出像素时钟是
  它的一半，这个 1:1 关系测试台的相位表表达不了 → 该制式只有上板能验。
* **上板**：显示器亮不亮、HDMI 接收端认不认这个光栅，本节全部无关。
