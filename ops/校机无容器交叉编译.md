# 校机无容器交叉编译

> **本页回答什么问题**：不用 Docker／podman 容器，只靠校机（Windows 宿主机）本机的工具，能不能编出板上那份 aarch64 的 BYZG `yolov8n` 可执行件——要哪几样东西、每条命令怎么敲、验证到了哪一层。
> **前置阅读**：[[工具链与素材进README]]（厂商的容器路线与素材位置）、[[板卡镜像实测取证]]（出厂 rootfs 全量索引，第六节的依赖核销拿它当分母）。
> **主机口径**：交叉编译与交叉部署一律在校机跑，本机（开发机）不跑编译、不跑交付脚本、不下大资源；板上禁止编译。
> **本页所有数字的来源**：`S:\apps\llm\agentwork\crosswin\` 下 2026-10-12 的四份原始输出 `run-all.out`／`run-verify.out`／`run-final.out`／`run-build2.out`，与校机 `D:\yzd\WCIS\crosswin\logs\build-*.log`。

## 一、结论

1. **跑通了**。校机零容器出 `yolov8n`：**6,408,568 B**，md5 **`2f9290936028cc0b2ddca5376490a03a`**，L1 三道门禁全绿（读数见第五节）。A 级。
2. **可复现**。同一个 md5 由三条互不相同的路径各自产出：① 只改 kit 里被打过补丁的文件、② `rm -rf zlib kit build` 从零重跑整条链、③ 修掉 `build.sh` 的 glob 缺陷后只重编。A 级。
3. **只到 L1**。L2（拿到板上能起进程）与 L3（能出检测框）**没有执行**，本轮也没做。现在这颗二进制的准确说法是：架构、动态依赖集合、符号版本上限三项都对得上出厂镜像——**不等于它能跑**。A 级（"没执行"是事实陈述）。
4. 与 10-05 容器编出来的那份（6,600,360 B）差 **−191,792 B（−2.9 %）**，**原因未归因**——没做符号表／段表比对，只比了体积与 `DT_NEEDED` 集合。C 级。
5. 厂商那批 aarch64 库（`libicraft_*.so` 与 `libcudadefault.so`）**出厂镜像里根本没有**，它们由我们这份 kit 在部署时带上板（依据见第六节）。A 级。

## 三、必须补 zlib：厂商 cmake 里的绝对路径

donor 里 **没有任何一颗 zlib**（`IcraftMdzThirdParty.deb` 的 `Static/lib` 只带 `libopencv_*.a`、`libyaml-cpp.a` 那批），但厂商的 `ModelzooDeps/aarch64/Static/lib/cmake/opencv4/OpenCVModules.cmake` 在 **65、83、109、158 四行**把 zlib 写成宿主绝对路径：

```cmake
65:  INTERFACE_LINK_LIBRARIES "/usr/lib/aarch64-linux-gnu/libz.so"
109: ... $<LINK_ONLY:tegra_hal>;/usr/lib/aarch64-linux-gnu/libz.so;$<LINK_ONLY:ittnotify>;...
158: ... $<LINK_ONLY:libopenjp2>;/usr/lib/aarch64-linux-gnu/libz.so"
```

这个文件是 `install(EXPORT)` 生成的，同文件里其余条目全走 `${_IMPORT_PREFIX}` 相对定位，只有 zlib 这四条漏了 ⇒ 一旦 kit 离开原始目录（我们本来就要离开），链接期就找不着。改法是把四条换成同文件其他条目用的形式：

```cmake
${_IMPORT_PREFIX}/lib/libz.a
```

`_IMPORT_PREFIX` 的算法：从 config 文件自身位置**逐层 `dirname`**，层数＝该文件里 `get_filename_component(_IMPORT_PREFIX … PATH)` 的行数。`OpenCVModules.cmake` 有 4 行 ⇒ 前缀剥到 `Static/` ⇒ `Static/lib/libz.a`，正是 `apply-zlib.sh` 落文件的位置。**别手工改成 `libz.so`**：我们只有静态件，且静态更稳（板上那颗 `libz.so.1.2.11` 由运行时再核）。

`_IMPORT_PREFIX` 的层数这件事也是第五节"闭合检查"的算法本身——脚本按每个 config 文件自己的行数算前缀，再逐条查引用是否存在，所以补丁打没打上、kit 漏没漏文件，都是当场可判的，不靠人眼。A 级。

## 四、跑法（可照抄）

脚本正本在本机 `S:\apps\llm\agentwork\crosswin\`；校机的工作目录是 `D:\yzd\WCIS\crosswin\`。传输用 `payload.tar`（532,480 B，装 `build.sh`／`make-kit.sh`／`get-zlib.sh`／`apply-zlib.sh`／runner＋`cmake\`／`proj\`／`ref\`／`src\`），姿势是 `scp` 到 `C:\Users\YiZhidi\`，脚本自己 `tar -xf` 解到工作目录。

校机 `ssh` 进去默认是 **cmd**，`$` 不展开、`;` 不是分隔符，所以：

```bat
:: 一条命令只做一件事：跑脚本文件，别内联
D:/yzd/MSYS2/usr/bin/bash.exe --login C:/Users/YiZhidi/run-build2.sh
```

`--login` 不能省（省了 PATH 里没有 `/usr/bin`，`bsdtar`、`find` 都找不到）。中文输出是 GBK，直接管道 `iconv` 会中途崩，改成先落本地文件再看（第六节）。

从零到二进制的完整顺序：

```bash
bash get-toolchain.sh          # 一次性：拉＋解 Arm 工具链，自带自检
bash get-zlib.sh               # 拉 focal arm64 zlib，解出并门禁校验 zlib/libz.a
bash make-kit.sh <donor目录> <kit目录>   # 剥 donor -> kit，内含 apply-zlib.sh
bash build.sh                   # configure + ninja + L1 三道门禁
```

`build.sh` 的默认路径就是校机的布局（`$HERE/kit`、`$HERE/src`、`/d/yzd/MSYS2/mingw64`），不用带参数。退出码：0＝建成功且门禁全过，2＝configure／build 失败，3＝门禁红。

已跑过的四个 runner，各自代表一条验证路径：

| runner | 它证明了什么 |
|---|---|
| `run-all.sh` | 第一次：donor 在、工具链在，kit 能建、能连出 aarch64 件 |
| `run-zlib.sh` | 补 zlib 这条路：`get-zlib` → 对现有 kit 打 `apply-zlib` → 重编 |
| `run-verify.sh` | **从零**：`rm -rf zlib kit build` 后整条链重跑，产物 md5 与①②相同 |
| `run-final.sh` + `run-build2.sh` | 备份件挪出 kit 之后重建（`leftovers_in_kit=0`），并复测 md5 不动 |

## 五、L1 门禁读数

`build.sh` 里 `[4]`～`[6]` 三段，全部用工具链自带的 `readelf`，不需要板子。

| 门 | 判据 | 读数 | 结果 |
|---|---|---|---|
| **L1a 架构** | `ELF64` + `AArch64` | `Class: ELF64`、`Type: EXEC`、`Machine: AArch64`、`Entry: 0x434fc0` | PASS |
| **L1b 依赖集合** | 10-05 容器件那 12 项一个都不能少 | `libicraft_hostbackend/buyibackend/zg330backend/xrt/xir/utils.so` + `libdl.so.2` `libpthread.so.0` `libstdc++.so.6` `libm.so.6` `libgcc_s.so.1` `libc.so.6` | PASS（全 12 项在） |
| **L1c 符号版本上限** | 不超过板子给的 | 产物要 `GLIBC 2.29`／`GLIBCXX 3.4.26`／`CXXABI 1.3.9`／`GCC 4.5.0`；板给 `2.31`（libc6 2.31-0ubuntu9.9）／`3.4.28`／`1.3.11`（libstdc++6 10.3.0-1ubuntu1~20.04） | PASS（三项都低于上限） |

L1b 多出来 3 项（`NOTE extra`，不是失败）：`ld-linux-aarch64.so.1`、`librt.so.1`、`libcudadefault.so`。逐项对出厂镜像的核销：

| 多出的项 | 出厂 rootfs 里有没有 | 依据 |
|---|---|---|
| `ld-linux-aarch64.so.1` | 有（`ld-2.31.so`） | [[板卡镜像实测取证]] 第九节那份 234,938 条目的 `00_rootfs_tree.txt.gz` |
| `librt.so.1` | 有（`librt-2.31.so`） | 同上 |
| `libgomp.so.1.0.0`（OpenCV 拖进来的） | 有，253,456 B | 同上 |
| `libz.so.1` | 有，`libz.so.1.2.11` 104,608 B | 同上 |
| `libcudadefault.so` | **索引里 0 命中** | 由 `kit/lib/aarch64-linux-gnu/` 部署时带上 |
| `libicraft_*.so` 9 颗 | **索引里 0 命中** | 同上（这些库出厂系统里没有，是 iCraft 包带的） |

编译期只有一条输出：`PicPre.hpp:204` 的 `note: parameter passing for argument of type 'std::pair<float, float>' … changed to match C++14 in GCC 10.1`。**warning 都算不上**，而且方向是"GCC 10.1 起又改回 C++14 的传法"，与厂商那批用 GCC 10.3（Ubuntu 20.04）编的库是同一 ABI ⇒ 判**无碍**（B 级：按编译器版本推的，没有跑过二进制级比对）。

kit 侧的三道自检（`make-kit.sh`）也是红的绿的分明的：`.so` 清单从 cmake 文件自己的引用里推（不用 glob，glob 会漏 `libcudadefault.so` 这种非 `libicraft_*` 名字）、闭包检查 `8 files / 8 refs / 0 missing`、demo 要的五张头文件逐个 `present`。

## 六、坑与处置

这一节按"现象→根因→处置"写，都是本轮真踩过的。

| 现象 | 根因 | 处置 |
|---|---|---|
| `GET-ZLIB FAILED rc=1`，随后 bsdtar 崩 | `sort -uV` 排的是**整条文件名**，`_`(0x5F) 排在 `.`(0x2E) 后面，于是 `-2ubuntu9`（resolute，`data.tar.zst`）赢了 focal；接着 bsdtar 在 Windows 上建不出 `libz.so` 符号链接 | 正则钉死 focal 的 delta `1\.2\.11\.dfsg-2ubuntu1(\.[0-9]+)?`，**排序前把 `_arm64.deb` 剥掉、选完再拼回**；只解 `usr/lib/aarch64-linux-gnu/libz.a` 这一个成员；解包报错改成容忍（符号链接建不出来不影响我们只要 `.a`） |
| 下错包后 `pkg.deb` 越下越坏 | `-C -` 断点续传接在**上一版的残字节**后面 | 下载前 `rm -f pkg.deb`，体积不对就直接失败 |
| 探 sysroot 报"libc.so.6 等四个 MISSING" | 目录写死成 `libc/lib`，实际在 `libc/lib64` | 用 `find` 而不是拼路径猜（第二节末那条） |
| `BUILD produced no executable`，但文件明明在 | `build.sh` 里 `find … -name yolov8n*` 的 **`*` 没加引号**，bash 拿它去匹配**当前目录**，而我在当前目录放了 `yolov8n.before` ⇒ 参数被替换成那个文件名 | 模式加引号 `--name 'yolov8n*'`。**判据要单独跑 md5 复核**，不能因为"脚本自己说失败"就以为产物坏了——那次产物 md5 是对的 |
| 备份件混进 kit | `apply-zlib.sh` 早先把原文件写成 `OpenCVModules.cmake.pre-zlibfix`，落在 kit 树里 | 备份改到 `zlib/backup/`；`run-final.sh` 里加 `find kit -name '*.pre-zlibfix'` 必须为 0 的门 |
| `set -e` 下脚本悄悄退出 | 赋值语句里放单条会返回非 0 的命令（`grep -l` 无命中即 1） | 无命中的地方一律 `\|\| true`；计数用管道（`grep -c … \| awk`），管道状态取 `awk` |
| 远程中文全乱码／管道提前断 | 校机默认 cmd 输出是 GBK，`iconv -f GBK` 遇到非法序列直接退出，把整条管道带走 | 先 `> x.raw` 落本地文件，再单独转；只看 ASCII 行时 `tr -d '\r'` 就够 |
| CMake 在 `try_compile` 里找不到编译器 | 顶层 `-DCROSSWIN_TC=…` 的缓存项**不会转进** CMake 自建的临时工程 | 工具链文件里写 `$ENV{CROSSWIN_TC}` 兜底，`build.sh` 同时 `export CROSSWIN_TC` |
